# 技术栈

本次采用现有项目内的渐进改造。下表区分已使用的基础与本轮选定的行为，目录、实体和接口契约在 S2 中展开，视觉规格在 S3 中展开。

| 层次 | 采用方案 | 理由 |
|---|---|---|
| 语言与应用 | TypeScript、Next.js App Router、React，沿用当前锁文件 | 保留既有 SSR、多语言、后台和 API 组合，避免为改版引入第二套应用 |
| 多语言 | next-intl，现行 en/ru 发布控制 | 保存六语言草稿与 phase0 通用化，但新语言补齐键和验收前不开放 |
| 视觉与交互 | 现有 CSS/组件基础；S3 输出集中 token、组件和容器规格 | 前台扩大产品表达，后台登录与内部界面一致；方向变更在 token 层表达，替换代价至多改一个 token 文件 |
| 3D | 现有 React Three Fiber、Drei、Three.js 与 GLB/图片回退 | 修正用户实际操作区域和输入冲突，不替换已有模型资产链路 |
| 数据 | 现有 Prisma / PostgreSQL | 会话撤销、聊天、事件去重和聚合需要服务端一致性；不增加第二数据库 |
| 登录 | 延续 Auth.js；增加设备会话、个人信息设置和验证后的无密码模式 | 保留现有账号、角色与撤销能力，同时交付用户要求的持久化和默认验证器码登录 |
| 会话期限 | 未勾选2小时滑动并接通主动刷新；记住设备7天闲置/30天绝对上限 | 时长需求未覆盖，采用可修改初值；服务端必须能拒绝过期及已撤销凭据 |
| 账号恢复 | 独立恢复入口、一次性码原子核销、受限重绑定；授权管理员和服务器所有者兜底 | 去掉日常必填恢复码，同时覆盖丢设备与单管理员，避免永久锁定或匿名接管 |
| 人工聊天 | Next.js/PostgreSQL 内自研最小人工会话，复用现有权限与已验证的通知能力 | 不依赖新的 PHP/MySQL 栈或较重服务，首期交付可接收和回复的联系闭环 |
| 访问统计 | 分析同意后第一方匿名浏览器ID、事件ID、白名单校验和日/产品聚合 | 支撑真实授权访客与3D口径，不采原始IP、跨站指纹或咨询正文 |
| 统计保留与时区 | 原始30天、无个人关联的聚合13个月；站点IANA时区初始UTC | 明确查询范围与“今日”边界；清理后不伪造历史重算能力 |
| 通知与内容 | 延续 SMTP/Gmail、现有询盘，Sanity/R2按真实配置使用 | 新聊天通知不等同于已投递；恢复协议迁移候选保持独立草稿，不直接改生产 |
| 媒体 | 现有网页视频、JPG、GIF及经核验的派生文件 | 静音、可暂停、可见加载、减少动态效果和失败回退；保留原件与品牌来源 |
| 构建与验证 | pnpm10冻结安装、Node原生测试/tsx、Next构建、Playwright、GitHub CI | 依仓库已有检查执行；真实浏览器与接口验证不能由静态渲染或内存桩替代 |
| 交付 | 官方 gh-stack 管理独立恢复分支/草稿PR；沿用 Docker/standalone 部署形态 | 先保存成果供审核，本次不因上传草稿而合并、部署或迁移数据 |

## 被否方案

- **独立 Chatwoot 服务**：已经考察成熟开源方案，但官方部署要求及新服务维护面超过本轮无需扩容的最小路径。现有容量也未经当前实测，因此本轮选择现有栈自研；不是断言 Chatwoot 不可用。参考 https://www.chatwoot.com/deploy 。
- **独立 LiveHelperChat PHP/MySQL 栈**：其安装与升级条件引入第二数据库和运行时；本轮不采用。技术栈校准对该路线判 conflict=yes，人工复核认定无需新增栈的自研路线更合适，保留真实概率而不把模型判断当成资源实测。参考 https://doc.livehelperchat.com/docs/install 。
- **只做访客聊天窗口、运营查数据库**：不能完成用户的人工联系需求；必须有收件、回复和离线恢复。
- **所有账号直接切无密码、完全删除恢复能力**：缺首次绑定、本人开关和单管理员恢复，可能造成账号无法进入或越权重置；采用决策2/3的受验证切换和独立恢复。
- **仅凭访问日志估计全站真实人数**：不能可靠区分浏览器、模型打开与加载结果；采用授权浏览器统计并说明覆盖限制，不宣称跨设备真人识别。
- **所有媒体首屏同时下载并带声轮播**：用户未要求，且会争抢产品操作与加载资源；采用可控制的分区展示。
- **将参考PDF改公司名、用品牌候选当正式logo**：不能满足自己的标识和己方事实要求；采用现用字标和独立重绘。
- **将文档校准服务接入网站运行时**：本轮无产品语义判断需求，校准只参与开发文档流程，不增加AI客服和线上依赖。具体工具与调用证据见03术语表和流程台账。

聊天采用现有应用内的人工会话路线，运维可行性通过容量与真实服务检查验证。

## 选型的执行边界

决策3的账号恢复、决策6的公司对外素材、决策9的数据采集存在选错代价高的提示。它们已经确定可执行边界，不设真人回看图的闸门；实施与审查必须核实受限凭据、事实来源、同意和数据最小化。普通技术及视觉分歧按技能继续裁决；实际花费、不可逆删除和对外承诺仍不能由文档选型代为授权。
