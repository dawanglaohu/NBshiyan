SEGMENT: modules
M1 | 品牌与公共体验：负责现用 PackJoyU 字标、己方可证公司内容、JPG/GIF 发布副本、首页媒体和前台公共页面，并作为全站前后台视觉 token 的唯一归属；不承担后台权限或后台外壳。 | —
M2 | 产品与 3D：负责产品列表、卡片和详情中的产品表达、直接模型操控、输入冲突处理、触屏与键盘查看、图片回退及带产品上下文的询盘入口。 | M1，M4，M5
M3 | 后台访问与账号：负责统一后台登录页和后台公共外壳、个人设置、设备会话、验证器绑定与登录方式切换、会话撤销及独立受限恢复；消费 M1 的视觉 token。 | M1
M4 | 第一方人工咨询：负责访客必要会话、人工消息与离线留言、ADMIN/SALES 收件箱和回复、未读、失败草稿与幂等重试，并保存真实收件和通知结果。 | M1，M3，M5
M5 | 同意与统计账本：负责分析同意、匿名浏览器与事件标识、采集准入和去重、站点统计时区设置、日与产品聚合、原始与聚合保留及可重算边界，产出真实访问和 3D 统计。 | M3
M6 | 业务与运维看板：负责按角色查询并解释统计结果，读取询盘、聊天、接口错误、邮件、存储和备份的真实来源，区分数据时间、零值、无数据、未接入、失败和旧值。 | M1，M3，M4，M5
M7 | 集成验收与交付：负责访客跨模块完整路径、后台权限与恢复路径、统计和可靠性完整链路的真实集成验收及交付证据收口；核对本轮复用的恢复来源，不重做 S1 已完成的取回和来源审计，也不自动合并恢复草稿。 | M1，M2，M3，M4，M5，M6

DATAFLOW:
- M1 → M2：全站视觉 token、现用字标及经核验的品牌发布素材引用；产品图片和模型仍须对应真实产品，不能用首页场景插画冒充。
- M1 → M3：前后台共用的唯一视觉 token 和品牌标识；M3 据此形成后台登录页与公共外壳，不另建第二套全站 token。
- M1 → M4：公共联系入口的内容和视觉规范，以及访客所在语言与页面上下文。
- M3 → M4：服务端确认的 ADMIN/SALES 身份、授权范围、会话有效性及后台公共外壳。
- M3 → M5：站点统计设置操作所需的服务端角色授权结果；管理员身份不进入匿名访问事件。
- M3 → M6：服务端确认的角色授权范围、有效会话和后台公共外壳。
- M2 → M4：访客主动进入询盘或人工联系时携带的产品标识、产品名称、语言与来源页面，不自动发送咨询。
- M5 → M2：当前分析同意状态与可发送的事件规则；拒绝分析不阻断模型查看、操作或询盘。
- M2 → M5：仅获同意后发送的页面和产品访问、3D 发起/成功/失败事件，携带事件标识、匿名浏览器标识、发生时间和产品归因。
- M5 → M4：当前分析同意状态与聊天发起事件规则；必要聊天会话、收件和回复不依赖分析同意。
- M4 → M5：仅获同意后的匿名聊天发起等白名单事件；不传邮箱、消息正文或其他咨询身份信息。
- M4 → M6：可只读汇总的真实询盘与聊天收件、回复和通知结果；聊天保存与回复不等待运维看板成功。
- M5 → M6：按站点时区和查询区间计算的授权访客、PV、产品与 3D 聚合，以及真实数据时间和查询状态；统计采集不反调看板。
- M1 → M7：品牌处理来源、己方事实依据、视频和 GIF 完整播放检查及公开页面验证结果。
- M2 → M7：真实产品与模型路径、桌面/触屏/键盘操控结果、失败回退及产品到咨询的串联证据。
- M3 → M7：真实账号、角色拒绝、设备会话撤销、登录切换及受限恢复到重新绑定的验证结果。
- M4 → M7：真实收件与回复、离线留言、重复重试、失败草稿和通知失败保留咨询的验证结果。
- M5 → M7：同意前后采集差异、事件去重、日界线、产品归因、清理与重算边界的真实验证结果。
- M6 → M7：核心统计展示、辅助来源状态、权限拒绝、查询失败和旧值呈现的真实验证结果；各模块如复用恢复草稿，随证据附 S1 来源审计引用、原 PR/提交与本轮实现提交的对应关系，已保存未合并的草稿不算主线实现。
