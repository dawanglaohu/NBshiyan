## 发现与修复

- B1 [S2] 涉及 M1-T3：字标来源 SHA 在 LF 检出和 CRLF 检出上重读不一致。复现：Windows `core.autocrlf=true` 下 `python docs/brand-media/static/verify-static-media.py` 报 `Hash mismatch: src/app/globals.css`；Linux 上会先撞上按 CRLF 存哈希的文本源。根因：`check_hash` 对文本源用原始字节，清单里 LF/CRLF 混用。修复 `d5f87f4`，文本后缀先归一成 LF，只改当前审计和发布清单，历史快照不动。
- B2 [S3] 涉及 M1-T3：`styleSources.mainColorCascade` 把主色指到 `tokens.css:29` 的 `--pj-on-inverse:#ffffff`。复现：按引用行读文件，该行是白色反色。根因：行号指错，当前字标主色是 `--pj-fg:#000000`。修复 `d5f87f4`，现用审计、发布清单和导出脚本改为 `tokens.css:26`。SVG 未改。
