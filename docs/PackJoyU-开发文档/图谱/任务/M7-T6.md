# M7-T6　终验新鲜本人授权与忘密码隔离

- 所属模块：[[M7]]　集成验收与交付：负责访客跨模块完整路径、后台权限与恢复路径、统计和可靠性完整链路的真实集成验收及交付证据收口；核对本轮复用的恢复来源，不重做 S1 已完成的取回和来源审计，也不自动合并恢复草稿。
- 前置依赖：[[M3-T7]]、[[M3-T9]]、[[M3-T12]]、[[M3-T13]]
- 完成后解锁：[[M7-T5]]

## 输入 / 产出

- **输入**：reauth-dialog、单用途ActionGrant、安全变更与受限恢复入口
- **产出**：fresh-auth-acceptance；新鲜授权/并发核销/无现密码负例报告

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 从真实个人信息操作发POST /api/admin/account/reauth，当前密码+新TOTP才得5min grant
同TOTP步并发最多一成功，同grant并发最多一变更，跨purpose/target/device、过期或撤销后变更均拒且状态未变（[[E-72]]、[[E-73]]、[[E-74]]）。2) 用真实绑定/模式切换入口分别提交错码、过期码、重放与两次并发切换，最终事务重查pending/期限/sv且错误不提交、并发最多一成功，失败后仍有至少一种已验证方式（[[E-08]]）。3) 已启用无密码且忘现密码者可正常email+totp登录处理非敏感业务
仅会话或仅TOTP请求reauth及直接敏感变更均被拒且不签普通grant，界面引导独立受限恢复
受限路径只允许新绑定并有审计，HTTP不能写pendingPasswordHash（[[E-75]]）。

## 必须处理的边界

- [[E-08]]　C-03 验证器绑定与无密码默认开关
    - 触发：绑定码错误、已过期、重复提交或并发切换
    - 期望：把四种触发分别测试，并在最终事务复核待绑定记录、有效期和当前凭证版本；错误/过期/重放不提交，两个并发切换最多一个成功，失败后查询仍存在至少一种已验证登录方式。沿09节规则，不另造登录方式。
- [[E-72]]　敏感设置的新鲜本人验证
    - 触发：同一 TOTP 时间步已被登录、其他敏感操作或并发请求消费
    - 期望：原子消费账号的验证器时间步，后来的请求不能再次发放 ActionGrant；客户端可等待下一验证码重试，不把恢复码重新加入日常登录。
- [[E-73]]　敏感设置的新鲜本人验证
    - 触发：两次请求并发使用同一 ActionGrant，或把改密码授权用于关闭验证器
    - 期望：在敏感变更事务内按动作、设备、账号及凭证版本校验并一次性消费授权，只有一个匹配请求成功，目的不符请求拒绝且不能执行变更。
- [[E-74]]　敏感设置的新鲜本人验证
    - 触发：授权签发后超过 5 分钟、设备撤销、密码/验证器变更或账号权限失效
    - 期望：旧授权立即无效；授权的新鲜验证不得跨设备移用，也不能延长原设备会话期限。
- [[E-75]]　敏感设置的新鲜本人验证
    - 触发：用户忘记现密码但仍能使用启用后的无密码登录
    - 期望：把“D3”指向09/10节已定义受限恢复路径和一次性 permit/restricted cookie；普通无密码登录不改，敏感设置缺当前密码时不得签发普通 ActionGrant，仅凭已登录会话或一枚TOTP的直接请求拒绝并无变更，受限恢复只可新绑定且审计。
