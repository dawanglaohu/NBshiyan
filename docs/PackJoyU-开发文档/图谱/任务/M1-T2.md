## 实施沉淀

<!-- notes:begin -->
- [数据校验（Validation）](https://vibe-hub.org/data-validation)在此只定义可传输字段。账号启用/授权、已发布产品、事件相对服务端时钟的 -48h/+5min、13 个月保留范围及游标所属权限仍须由后续服务验证；客户端解析成功不构成授权。
- Auth.js 的 rememberDevice 按表单专用规则只把字面 `true` 解析为 true；布尔 true 也拒绝。缺值、布尔 false、字面 `false` 为 false。不得以 Boolean/coerce 替换；普通 2h 与记住设备 7d/30d 的实际 JWT/cookie 期限由 M3 适配层接线，本卡不更换既有 Auth.js 协议。
- 首次绑定仅返回 `{otpauthUri}` / `{recoveryCodes}`，受限恢复另有 expiresAt/completed。本人换验证器的兼容响应可携 expiresAt/expiresTruncated；strict DTO 必须保留这些现存字段，不能用受限恢复 DTO 替代旧响应。
- 设备列表按端点特定上限 50（默认 25），聊天列表/消息分别默认 25/50、最大 100。游标是 base64url 的严格 `{createdAt,id}` / `{updatedAt,id}`；格式验证后仍需查询层核所属范围与排序位置。查询整数只接受规范十进制串/整数，不接受科学计数或 truthy 转换。
- 消息上限按 Unicode code points 计数，trim 后 1..4000；UTF-16 length 会误拒绝合法 emoji。正文不接 HTML/不可见控制字符；站内路径剥离 query/hash 并拦截解码后的点段、双斜杠、反斜杠。
- 聊天消息页内 seq 必须连续，非空页 nextAfterSeq 等于最后返回 seq，hasMore 与 nextAfterSeq < lastSeq 一致；页首与请求 afterSeq 的关联仍由持有请求上下文的调用方校验。聊天可选邮箱的 trim 空值视为省略，CR/LF 仍拒绝；账号邮箱保持必填。
- 分析事件始终携 navigationId；模型事件另携 viewId/productSlug，终态才有 durationMs，失败原因仅三种白名单。产品是否发布与 terminal 是否对应 start 由账本服务验证；schema 不制造成功事实。
- 统计来源采用明确枚举与 full/partial/unavailable 覆盖状态。均值必须携 loadDurationSamples，无样本为 null；其他计数不接受小数。保留作业同时提供 candidateCount/deletedCount，默认 dryRun 的候选数不能写成实际删除数。其他作业计数仅保留已声明白名单，新增计数需同步扩展契约。
- IANA 时区由运行时 Intl 校验，支持 CET/GMT/EST5EDT 等合法别名，不以含斜杠作为有效性的替代。自然日范围用日期标签比较；实际 DST 左闭右开 UTC 边界由时区服务计算。
- 公共出口仅依赖 Zod/标准 ES，不导入 Prisma、服务器模块、DOM 或项目路径别名。Auth.js 的新增元数据保持可选，避免把尚未接线的设备字段伪装成既有会话已经提供的数据。
