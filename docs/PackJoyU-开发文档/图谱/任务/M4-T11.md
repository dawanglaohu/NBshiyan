# M4-T11　保存真实人工回复并关闭咨询

- 所属模块：[[M4]]　第一方人工咨询：负责访客必要会话、人工消息与离线留言、ADMIN/SALES 收件箱和回复、未读、失败草稿与幂等重试，并保存真实收件和通知结果。
- 前置依赖：[[M4-T3]]、[[M4-T10]]
- 完成后解锁：[[M4-T9]]、[[M4-T13]]、[[M4-T14]]

## 输入 / 产出

- **输入**：M4-T3运营权限/读取与M4-T10消息追加。
- **产出**：POST /api/admin/chat/conversations/[id]/messages、PATCH /api/admin/chat/conversations/[id]；当前作者和关闭CAS。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 调用方/接线点：真实ADMIN/SALES message handler→当前身份→共享消息追加
author来自session，两人并发回复各保留唯一seq和作者，重复UUID同载荷只一条，客户端自报author不采信（[[E-33]]）。2) 访客POST保存后运营GET实际读取、POST人工回复后访客GET读到相同body/作者，整个过程无AI自动回复
先落库才received（[[E-16]]、[[E-31]]）。3) close以expectedVersion CAS，竞争只有匹配者成功，关闭后访客/人工消息409
撤权后下一poll/send均无正文无写入，threadId/seq/email篡改不得读他人（[[E-32]]、[[E-78]]）。

## 必须处理的边界

- [[E-16]]　在线聊天实现路线
    - 触发：访客首次发消息且运营在线
    - 期望：持久化会话和消息后给出已接收状态，运营收件箱可读取并人工回复，不生成 AI 自动答复。
- [[E-31]]　C-01 人工聊天收件与回复入口
    - 触发：访客提交消息且服务端持久化成功
    - 期望：返回稳定的会话与消息标识并显示“已接收”，运营收件箱能读取；数据库写入失败则保留待重试，不显示已接收或客服已读。
- [[E-32]]　C-01 人工聊天收件与回复入口
    - 触发：未登录、EDITOR、已被撤销权限的账号或访客猜测他人会话标识
    - 期望：直接请求读取/回复接口分别验未登录、EDITOR、撤权账号、他人访客凭据均无内容且无写入；ADMIN/SALES 仅按当前权限返回；不以隐藏按钮作为权限证据。
- [[E-33]]　C-01 人工聊天收件与回复入口
    - 触发：两名有权限人员并发回复或访客重复发送相同客户端消息标识
    - 期望：明确以服务端 seq 排序并展示真实 author；同会话同 clientMessageId 同载荷仅一条消息、一个出箱项和一次未读增加；并发人工回复各自保存，不由后返回响应覆盖先保存回复。
- [[E-78]]　人工聊天同步机制
    - 触发：访客会话到期/撤销，或运营角色从 ADMIN/SALES 变为无聊天权限
    - 期望：下一次轮询和发送均做服务端鉴权并停止返回会话内容；修改 threadId、seq 或邮箱不能读取其他咨询。
