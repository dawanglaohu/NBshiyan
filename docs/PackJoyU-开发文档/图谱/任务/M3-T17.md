# M3-T17　提供本人设备列表及目标撤销API

- 所属模块：[[M3]]　后台访问与账号：负责统一后台登录页和后台公共外壳、个人设置、设备会话、验证器绑定与登录方式切换、会话撤销及独立受限恢复，并负责既有后台页面的共享视觉迁移/回归；不改其询盘/邮件/规格/模型业务，消费 M1 的唯一视觉 token。
- 前置依赖：[[M3-T3]]、[[M3-T1]]
- 完成后解锁：[[M3-T8]]、[[M3-T13]]

## 输入 / 产出

- **输入**：M3-T1设备事实与M3-T3新鲜授权。
- **产出**：GET /api/admin/account/devices、POST /api/admin/account/devices/[id]/revoke、POST /api/admin/account/logout-all。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 调用方/接线点：真实handlers→device-management服务
列表仅本人、cursor持久且不变顺序且DTO无sid凭据
他人device target拒绝
DEVICE_REVOKE目标grant在动作事务一次核销，旧cookie下次GET account返回401（[[E-03]]、[[E-70]]、[[E-73]]）。2) logout-all消费LOGOUT_ALL，User锁下递增sv/撤全部设备/审计并清cookie
并发同grant最多一次成功，跨设备/过期或旧sv不变更
最终状态重复读取一致，不自动重放授权（[[E-03]]、[[E-74]]）。

## 必须处理的边界

- [[E-03]]　会话持久化与记住设备期限
    - 触发：改密、重置验证器、禁用账号或执行“退出所有设备”
    - 期望：服务端撤销该账号旧凭证，旧 JWT 即使尚未到期也被拒绝；普通“退出”至少撤销当前设备会话并清除本地登录状态。
- [[E-70]]　设备会话与Auth.js期限接合
    - 触发：cookie/JWT 仍有效，但设备已撤销、账号禁用、凭证版本变化或服务端校验不可用
    - 期望：受保护请求不得仅凭 cookie 放行；在请求范围内去重查询不能演变成跨请求忽略撤销的缓存。
- [[E-73]]　敏感设置的新鲜本人验证
    - 触发：两次请求并发使用同一 ActionGrant，或把改密码授权用于关闭验证器
    - 期望：在敏感变更事务内按动作、设备、账号及凭证版本校验并一次性消费授权，只有一个匹配请求成功，目的不符请求拒绝且不能执行变更。
- [[E-74]]　敏感设置的新鲜本人验证
    - 触发：授权签发后超过 5 分钟、设备撤销、密码/验证器变更或账号权限失效
    - 期望：旧授权立即无效；授权的新鲜验证不得跨设备移用，也不能延长原设备会话期限。
