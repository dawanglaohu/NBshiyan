# M3-T3　签发一次性新鲜本人授权

- 所属模块：[[M3]]　后台访问与账号：负责统一后台登录页和后台公共外壳、个人设置、设备会话、验证器绑定与登录方式切换、会话撤销及独立受限恢复，并负责既有后台页面的共享视觉迁移/回归；不改其询盘/邮件/规格/模型业务，消费 M1 的唯一视觉 token。
- 前置依赖：[[M3-T2]]、[[M3-T1]]
- 完成后解锁：[[M3-T4]]、[[M3-T16]]、[[M3-T17]]、[[M3-T20]]

## 输入 / 产出

- **输入**：M3-T2当前secret/sv/step消费、M3-T1有效设备；09/10 purpose/target/5min规则。
- **产出**：AdminActionGrant及POST /api/admin/account/reauth，组合服务直接消费当前身份。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 调用方/接线点：真实POST reauth→当前设备守卫→现密码和未用TOTP→256bit单次token响应/hash入库
同时登录/另一敏感请求已消费该step时不再发grant（[[E-72]]）。2) 用测试消费者在同一数据库事务核purpose/target/user/sid/sv/expiresAt/usedAt，重复或跨用途/跨设备/5min等号/设备撤销均不消费成功
真实reauth读取当前权限，ADMIN才可为他人RECOVERY_AUTHORIZE（[[E-73]]、[[E-74]]）。3) 对仍可无密码登录但忘现密码的真实账号，仅session或TOTP请求reauth返回401且grant数不变，随后普通totp登录仍可用
受限恢复不签普通grant（[[E-75]]）。

## 必须处理的边界

- [[E-72]]　敏感设置的新鲜本人验证
    - 触发：同一 TOTP 时间步已被登录、其他敏感操作或并发请求消费
    - 期望：原子消费账号的验证器时间步，后来的请求不能再次发放 ActionGrant；客户端可等待下一验证码重试，不把恢复码重新加入日常登录。
- [[E-73]]　敏感设置的新鲜本人验证
    - 触发：两次请求并发使用同一 ActionGrant，或把改密码授权用于关闭验证器
    - 期望：在敏感变更事务内按动作、设备、账号及凭证版本校验并一次性消费授权，只有一个匹配请求成功，目的不符请求拒绝且不能执行变更。
- [[E-74]]　敏感设置的新鲜本人验证
    - 触发：授权签发后超过 5 分钟、设备撤销、密码/验证器变更或账号权限失效
    - 期望：旧授权立即无效；授权的新鲜验证不得跨设备移用，也不能延长原设备会话期限。
- [[E-75]]　敏感设置的新鲜本人验证
    - 触发：用户忘记现密码但仍能使用启用后的无密码登录
    - 期望：把“D3”指向09/10节已定义受限恢复路径和一次性 permit/restricted cookie；普通无密码登录不改，敏感设置缺当前密码时不得签发普通 ActionGrant，仅凭已登录会话或一枚TOTP的直接请求拒绝并无变更，受限恢复只可新绑定且审计。

## 实施沉淀

<!-- notes:begin -->
时间步消费使用共享 consumeTotpStep 的 Prisma 连接，必须在授权事务加 User 行锁之前完成，避免两条连接互相等待。授权事务按 User → Device 加锁，重查 sessionVersion、totpSecret、账号和设备有效性后写授权与审计；重查失败不发授权，已消费的时间步不退回。本人用途的 targetId 规范化为 null，恢复授权绑定另一账号，设备撤销授权绑定本人的目标设备。

消费方可传入敏感变更事务，在同一事务核用途、目标、账号、当前设备、凭证版本、到期和 usedAt。到期等号拒绝，UTC 时间参数先转换为无时区钟面。签发和消费都不写设备 lastActivityAt 或期限；签发成功不设置会话 cookie。

reauth 必须有现密码与未用 TOTP。只带会话、只带 TOTP 或携带 recoveryCode 都不签普通授权，也不消费时间步；普通 passwordless 登录独立保留。账号/IP 限流桶与登录隔离，错误响应和审计不记录明文 token、密码或验证码。

数据库测试仅认 M3T3_TEST_DATABASE_URL，不回退到开发/生产 DATABASE_URL。PG17 CI 在 m3t3 schema 串行执行两个目标文件，并要求每个文件 pass≥1、fail/skip/todo/cancelled=0，计数字段缺失也失败；M3T3_REQUIRE_DATABASE=true 缺地址直接报错。无数据库的 bootstrap 回归只证明真实测试导入顺序，缺库负向检查也不能替代真实 PostgreSQL 验收。当前真实 PG CI 逐文件执行结果待取得，不据此标记已落地。

数据影响：schema 增加 ActionPurpose 枚举与 AdminActionGrant 表、索引和外键，不改既有密码/验证器等字段定义，不更新设备活动或期限；签发会核销 User.totpLastStep、新增授权与审计，消费会更新 usedAt。本轮未执行生产迁移，生产表结构现状未核验；部署与迁移需另行授权。回滚先停用签发/消费入口，等待已发授权失效，再按批准的数据库变更流程移除新增对象，不能在仍有消费者时删表。
