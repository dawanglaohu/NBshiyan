## 实施沉淀

<!-- notes:begin -->
采纳的是 `R4-T16305211:impl-scope` 的 option B（恢复开关），不是改边界。判定依据是 `judgments.jsonl` 里 `impl-scope`（2026-10-26T05:08:15，jev-1.14.0，pick B 0.82 high，`adopt.action=take`）；更早的 `R4-T16305211:impl`（04:55:15，pick B 0.53 medium，`adopt.action=red_line`）按 `needs_owner=unsure` 判为授权红线，未被当作授权，也不因后一条 take 而作废，两条都原样留在仓库日志里。因此 E-20 源行与 M4-T15 产出句本轮一字未改，只补界面与文案。

开关只做本页的 UI 状态，不进同意存储。`HumanContactNotice` 里没有 `setConsent`、没有读 `Consent` 上下文、不写 `pj-consent`，所以打开开关不会伪装成已同意，也不会加载 Tawk。代价是刷新后回到关闭——这是有意为之：共享的同意存储模块不在本任务有效路径内，强行持久化会越界，也影响其他已落地任务。

询盘与邮箱入口放在开关条件之外，开关只改自身文案与状态句。这样「关闭聊天」不会被误实现成「关闭联系方式」，E-20 要求的「保留现有联系入口」是靠结构而不是靠文案保证的。

填充色只跟 `aria-checked`，不跟 `:hover`。`tokens.css` 的 `.pj-button:hover` 会改底色，这里用 `#contact-chat-switch` 的 id 权重压过去，悬停只加下划线；元素自带 `id` 保证优先级，不靠 `!important`，`.contact-chat-switch` 的类名改动不会让样式静默失效。

状态句用 `aria-live="polite"` 而不是 `role="alert"`，因为开关切换是可预期操作，不需要打断读屏。状态句在 `@media (hover:hover)` 之外的各宽度都 `flex-basis:100%` 独占一行，避免 768 与 1280 之间切换开关时整行折行跳动。

俄文的两类不可见字符必须写成 JSON 转义：`\u2060`（字连接符）贴在 `e-mail`、`по-прежнему` 的连字符两侧，`\u00A0`（不换行空格）在 `Свяжитесь с нами` 和 `по e-mail` 处。写成字面量会被编辑器或格式化工具改写，测试按原始字节校验，不能图省事改成普通连字符。

`--landed` 的门槛不是 `progress` 字段。`build_docs.py:4747` 先用 `stale_reasons()` 拦产物过期，`:4760` 再用 `readiness()[i].ready` 拦未登记的契约复核，最后 `:4764` 过 issue 围栏。本任务最初 `ready=false` 的原因是 `_run/task-reviews.json` 里没有本任务的登记（不是缺静态契约——`handoff_contract.py:189-192` 明确拒绝对同名 ID 重复登记）。批次闸门只影响「下一批能否派发」，不挡 `--landed` 本身。
