# M6-T5　接入HTTP和邮件可靠性来源

- 所属模块：[[M6]]　业务与运维看板：负责按角色查询并解释统计结果，读取询盘、聊天、接口错误、邮件、存储和备份的真实来源，区分数据时间、零值、无数据、未接入、失败和旧值。
- 前置依赖：[[M6-T6]]、[[M4-T4]]
- 完成后解锁：[[M6-T7]]

## 输入 / 产出

- **输入**：stats-core、M3真实ApiDailyCounter、MailMessage与ChatNotification状态
- **产出**：stats-reliability；明确覆盖的HTTP与通知计数适配器

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 对已接线API产生真实2xx/5xx响应后GET /api/admin/stats的http来源，分母为同范围真实requestCount且错误为5xx
覆盖标签仅本轮instrumented routes，无分母为null、未接入为not_connected，禁止声称全站错误率（[[E-64]]）。2) 通过真实通知作业产生queued/sending/sent/failed/unknown结果，mail来源按真实尝试/SMTP接受计数，不把排队或咨询received算投递
某来源查询失败保留其原成功时间/旧值或显示无旧值失败，其他来源继续成功（[[E-51]]、[[E-52]]、[[E-53]]、[[E-64]]、[[E-67]]）。

## 必须处理的边界

- [[E-51]]　C-06 看板数据时间与异常状态
    - 触发：查询失败且已有上次成功快照
    - 期望：保留旧值并显著标注旧值时间、当前失败及重试入口；不能刷新时间后让旧值看似刚更新。
- [[E-52]]　C-06 看板数据时间与异常状态
    - 触发：查询失败且没有成功快照
    - 期望：显示错误与重试，不生成默认 0 或演示数字；错误信息不向业务角色暴露凭据、堆栈或连接串。
- [[E-53]]　C-06 看板数据时间与异常状态
    - 触发：面板内不同来源的更新速度或失败状态不同
    - 期望：每个指标保留自己的数据时间与状态，页面总刷新成功不覆盖局部失败。
- [[E-64]]　运维指标扩展及角色权限
    - 触发：接口或邮件已接真实结果来源
    - 期望：展示脱敏且口径明确的错误率与通知失败计数，邮件失败按真实发送尝试记录，不把排队、已调用发送函数或普通询盘收件等同于成功投递。
- [[E-67]]　运维指标扩展及角色权限
    - 触发：任一附加来源中断或无数据
    - 期望：该卡独立显示错误、旧值、未知或未接入；其他真实指标仍可查询，避免单个辅助来源拖垮整张看板。

## 实施沉淀

<!-- notes:begin -->
- `ApiDailyCounter` 仅由已接入 `createApiCounter` 的后台与聊天路由写入，公开页、`/api/rum` 与旧公开询盘入口不在统计分母内。因此 `api_requests`、`api_errors` 与 `StatsDTO.apiErrorRate` 固定标 `coverage: 'partial'` 与 `scope: 'instrumented_routes'`，Zod 契约显式拒绝 `coverage: 'full'` 以防声称全站错误率；`ApiDailyCounter` 无 `productSlug` 列，带产品筛选时直接返回 `no_data` 而非混入不区分产品的计数。[[E-64]]
- `MailMessage` 同时承载入站回信（`INBOUND` / `RECEIVED`）与出站队列（`OUTBOUND`），统计 `mail` 必须限定 `direction = 'OUTBOUND'`，并将 `status = 'FAILED' AND errorCode = 'unknown_delivery' AND attempts > 0` 单列为 `unknown`，与 `ChatNotification.status = 'UNKNOWN'` 对齐。主指标 `value` 仅统计经 SMTP 接受的 `SENT`（`attempts > 0`），咨询接口的 [幂等（Idempotency）](https://vibe-hub.org/idempotency) 收件回执（`received`）或尚未尝试的 `QUEUED`/`SENDING` 仅进入 `notificationCounts` 明细，不计入成功投递；发信配置缺失且无真实尝试记录时，即便定时作业空跑写过 `JobState.lastSucceededAt`，来源仍报 `not_connected`。[[E-64]]
- 遵循服务端不设进程级全局可变计数缓存的约束，四个可靠性来源各自在独立 `SET TRANSACTION READ ONLY`（2s 等待、5s 超时）事务内读取，经二次 [权限控制（Authorization）](https://vibe-hub.org/authorization) 限制 `api_*`/`mail` 仅 `ADMIN`、`chat_notifications` 限 `ADMIN`/`SALES` 且零 PII 出库。单源异常仅将该卡置为 `query_failed` 而不拖垮其余指标；传入同查询键 `previousSnapshot` 时保留旧值与原始 `lastSucceededAt`（不刷新成功时间），无同键快照时置 `value: null`，同时对超过 5 分钟未更新或最近一次失败的持久 `JobState` 水位标 `stale`。[[E-51]] [[E-52]] [[E-53]] [[E-67]]
- `src/lib/server/jobs/registry.ts` 经 `uploads.ts` 间接静态导入 `db.ts`，Prisma 6 在构造单例时快照 `process.env.DATABASE_URL`；集成测试顶层须用 `import type` 并在 `before()` 写入专库 Schema 地址后再动态导入 `db.ts` 与作业注册表，避免落入默认库。`e2e/stats-reliability-api.spec.ts` 使用独立可信测试 IP（`198.18.10.22`/`23`）避开 CI 主段共享限流桶。
