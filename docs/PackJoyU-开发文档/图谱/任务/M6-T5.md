# M6-T5　接入HTTP和邮件可靠性来源

- 所属模块：[[M6]]　业务与运维看板：负责按角色查询并解释统计结果，读取询盘、聊天、接口错误、邮件、存储和备份的真实来源，区分数据时间、零值、无数据、未接入、失败和旧值。
- 前置依赖：[[M6-T6]]、[[M4-T4]]
- 完成后解锁：[[M6-T7]]

## 输入 / 产出

- **输入**：stats-core、M3真实ApiDailyCounter、MailMessage与ChatNotification状态
- **产出**：stats-reliability；明确覆盖的HTTP与通知计数适配器

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 对已接线API产生真实2xx/5xx响应后GET /api/admin/stats的http来源，分母为同范围真实requestCount且错误为5xx
覆盖标签仅本轮instrumented routes，无分母为null、未接入为not_connected，禁止声称全站错误率（[[E-64]]）。2) 通过真实通知作业产生queued/sending/sent/failed/unknown结果，mail来源按真实尝试/SMTP接受计数，不把排队或咨询received算投递
某来源查询失败保留其原成功时间/旧值或显示无旧值失败，其他来源继续成功（[[E-51]]、[[E-52]]、[[E-53]]、[[E-64]]、[[E-67]]）。

## 必须处理的边界

- [[E-51]]　C-06 看板数据时间与异常状态
    - 触发：查询失败且已有上次成功快照
    - 期望：保留旧值并显著标注旧值时间、当前失败及重试入口；不能刷新时间后让旧值看似刚更新。
- [[E-52]]　C-06 看板数据时间与异常状态
    - 触发：查询失败且没有成功快照
    - 期望：显示错误与重试，不生成默认 0 或演示数字；错误信息不向业务角色暴露凭据、堆栈或连接串。
- [[E-53]]　C-06 看板数据时间与异常状态
    - 触发：面板内不同来源的更新速度或失败状态不同
    - 期望：每个指标保留自己的数据时间与状态，页面总刷新成功不覆盖局部失败。
- [[E-64]]　运维指标扩展及角色权限
    - 触发：接口或邮件已接真实结果来源
    - 期望：展示脱敏且口径明确的错误率与通知失败计数，邮件失败按真实发送尝试记录，不把排队、已调用发送函数或普通询盘收件等同于成功投递。
- [[E-67]]　运维指标扩展及角色权限
    - 触发：任一附加来源中断或无数据
    - 期望：该卡独立显示错误、旧值、未知或未接入；其他真实指标仍可查询，避免单个辅助来源拖垮整张看板。
