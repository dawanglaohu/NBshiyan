# M3-T4　签发管理员目标恢复permit

- 所属模块：[[M3]]　后台访问与账号：负责统一后台登录页和后台公共外壳、个人设置、设备会话、验证器绑定与登录方式切换、会话撤销及独立受限恢复；消费 M1 的视觉 token。
- 前置依赖：[[M3-T3]]、[[M3-T1]]
- 完成后解锁：[[M3-T9]]、[[M3-T18]]、[[M3-T19]]

## 输入 / 产出

- **输入**：M3-T3目标新鲜授权与当前权限；09/10 permit15min和审计协议。
- **产出**：AdminRecoveryPermit；POST /api/admin/account/recovery-authorizations及POST /api/admin/users/[id]/reset-2fa兼容别名。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 调用方/接线点：真实ADMIN handler→recovery-authorizations
当前密码+新TOTP取得绑定他人的RECOVERY_AUTHORIZE grant后签15min permit，target不可自己
旧无body直接reset、仅session、访客邮件请求、SALES/EDITOR均拒绝且目标因素不变（[[E-13]]）。2) permit随机256bit、仅存hash/一次响应，授权核销/target/source/reason审计同事务，重复同grant不再签发
日志无permit明文，响应丢失不自动签第二份
普通passwordless会话不能借此省略现密码（[[E-73]]、[[E-75]]）。

## 必须处理的边界

- [[E-13]]　C-04 验证器丢失与单管理员恢复
    - 触发：另一管理员代为授权恢复
    - 期望：授权方必须重新验证，不能仅凭已打开后台页面或访客邮件请求重置其他账号。
- [[E-73]]　敏感设置的新鲜本人验证
    - 触发：两次请求并发使用同一 ActionGrant，或把改密码授权用于关闭验证器
    - 期望：在敏感变更事务内按动作、设备、账号及凭证版本校验并一次性消费授权，只有一个匹配请求成功，目的不符请求拒绝且不能执行变更。
- [[E-75]]　敏感设置的新鲜本人验证
    - 触发：用户忘记现密码但仍能使用启用后的无密码登录
    - 期望：把“D3”指向09/10节已定义受限恢复路径和一次性 permit/restricted cookie；普通无密码登录不改，敏感设置缺当前密码时不得签发普通 ActionGrant，仅凭已登录会话或一枚TOTP的直接请求拒绝并无变更，受限恢复只可新绑定且审计。
