# M2-T2　修正模型直接拖动与滚轮焦点

- 所属模块：[[M2]]　产品与 3D：负责产品列表、卡片和详情中的产品表达、直接模型操控、输入冲突处理、触屏与键盘查看、图片回退及带产品上下文的询盘入口。
- 前置依赖：[[M2-T1]]
- 完成后解锁：[[M2-T3]]

## 输入 / 产出

- **输入**：现有真实GLB和OrbitControls、D20
- **产出**：可取消的精确指针/焦点控制

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 从产品卡模型viewport直接pointer-down捕获当前模型，hover停自转且不几何缩放
普通wheel始终页面滚动
Ctrl/Cmd+wheel仅在真实DOM焦点归属本模型视口/命名工具条且指针命中同一模型视口/工具条时缩放该相机，zoom控件点击仍可缩放
标题/说明/规格/链接与跨模型命中不缩放任一模型并保留浏览器行为，不以整张卡片或缓存焦点代替判定，不先强制激活（[[E-97]]、[[E-98]]、[[E-99]]）。2) pointercancel/blur/Escape/卸载均释放，重新操作正确目标且不残留锁页
用户暂停优先于隐藏/显示恢复
测试保留修改前失败与修改后通过（[[E-100]]）。

## 必须处理的边界

- [[E-100]]　失焦与取消
    - 触发：pointercancel、窗口失焦、Escape、卡片卸载或切换页面
    - 期望：释放pointer capture、监听和交互状态；无遗留滚轮拦截或持续旋转，下一次进入可正常开始
- [[E-97]]　模型拖动所有权
    - 触发：PC在可见模型视口内pointer-down并拖动，随后指针跨到其他卡片
    - 期望：仅起始模型获得pointer capture并旋转；不触发卡片导航，不切换另一个模型，几何卡片不做hover scale
- [[E-98]]　页面滚动与缩放
    - 触发：指针在模型视口、工具条、正文或另一模型上使用普通滚轮、触控板或 Ctrl/Cmd+wheel
    - 期望：普通滚轮和触控板始终正常滚页；Ctrl/Cmd+wheel仅在真实焦点归属某模型视口/命名工具条且指针命中同一模型视口/工具条时改变该相机，明确缩放按钮仍可点击。焦点与指针分属不同模型，或指针落在标题/说明/规格/链接等非控制区时，所有模型相机不变且保留浏览器行为；退出后释放所有滚轮拦截，不凭缓存焦点再次接管。
- [[E-99]]　自动旋转与用户意图
    - 触发：悬停、已开始手动操控、用户显式暂停、离开视区或恢复前台
    - 期望：悬停/手控时暂停自动旋转；用户暂停不被重新可见覆盖；减少动态效果默认静态且可主动操作

## 实施沉淀

<!-- notes:begin -->
采纳 `design` 裁决 A：`model=jev-1.14.0`，`pick=A`，`confidence=0.32`、`band=low`，`adopt=take(A)`，`register=commerce`，`stated=yes`，`token_only=no`；低置信按既定规则执行，风险保留、未重跑。

**准入拆成两个独立轴**：焦点归属（真实 DOM 焦点在本模型视口或命名工具条内）与指针命中（语义 `closest` 到本模型视口或工具条且在该 wrapper 内）。任一不成立即 `scroll-page`，调用方直接 `return`，既不 `preventDefault` 也不 `requestZoom`。源码事实上该分支与本任务自身的拦截互斥；「普通滚轮照常滚页」另由 e2e 的实际 `scrollY` 增加与相机不变观测支撑，不单靠本函数返回值。

**监听域从整张卡片收窄到焦点 wrapper**：`article` 另含标题、说明、规格与购买入口，挂在其上会让正文修饰滚轮也缩放相机，正是复审指出的越界。改挂 `viewport.parentElement` 后正文即使冒泡也进不了准入域。

**退出必须同步撤销，不能等渲染**：reducer 新状态要等 React 提交、旧监听 cleanup 还要再等一次 effect，中间存在 DOM 焦点仍留视口的窗口。故加 `wheelPermit` ref，在 Escape（`:120`）、窗口失焦（`:127`）、pointercancel（`:194`）、焦点离开（`:251`）四条路径上与 `dispatch` 同刻清空；卸载时 cleanup 也清（`:137`），但组件已不存在、许可无消费者，该处安全主要靠监听被摘除。单测 `tests/m2-t2-model-pointer.test.ts:130`–`:135` 断言前四条；卸载不在语法断言内。

**踩坑：`focus()` 不保证派发事件**。`onDown` 先 `focus()` 再靠 `onFocus` 签发许可不对：焦点若已在该视口（取消后常见），浏览器不再派发 `focus`，许可永不恢复。CI 首轮因此红在场景 C（相机停在 `0.9094`）；缺陷随后修复并复跑通过，最终 head CI 为 170 条 / 161 通过 / 9 跳过 / 0 失败，两条 E-98 具名通过。

**e2e 负例不能靠条件分支**：正文用例原先带两层 `if`，正文缺失会静默跳过整段。现在先硬断言正文存在、可见、非空文本，再用 `elementFromPoint` 确认命中 `p.desc`，才做 wheel 与相机不变断言；负例还要求处理后若干帧内持续不变，避免读到异步未应用的旧值。

**场景 D 先决条件**：C 重入后直接点 Zoom 只能证明「重入后可用」。D 先 Escape，断言焦点与归属已释放，再观察这次修饰滚轮后相机距离保持不变，随后记录基线验证 Zoom 按钮。该格只观测相机；源码准入失败分支在 `preventDefault` 之前 return，但用例不读取 `event.defaultPrevented`，也不验证浏览器默认动作（如页缩放）是否被其他处理器取消或实际执行。
