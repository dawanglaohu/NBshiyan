## 输入 / 产出

- **输入**：siteDayUtcBounds 只寻找墙上 00:00:00。day-boundaries.ts:133 找不到时抛 DayBoundaryError('invalid_date')，:144 用次日午夜当右开端，所以前一天一并失败。settings.ts:176 到 :180 把任何 DayBoundaryError 映成时区字段非法，设置不写入。本机探针上 America/Santiago 的 2026-09-05 与 2026-09-06、America/Havana 的 2026-03-07 与 2026-03-08 抛 invalid_date。America/New_York 的 2026-03-08 为 2026-03-08T05:00:00.000Z 至 2026-03-09T04:00:00.000Z，2026-11-01 为 2026-11-01T04:00:00.000Z 至 2026-11-02T05:00:00.000Z。tests/analytics-day-boundaries.test.ts 覆盖纽约，不覆盖这两处被跳过的午夜。Australia/Lord_Howe 的 23.5/24.5 小时日午夜仍在，不作为本条缺陷。
- **产出**：跳过的本地午夜改用该本地日最早存在的瞬间做左闭端，并用同一瞬间做前一天的右开端。合法 IANA 不因这种日期被设置更新拒绝。在 tests/analytics-day-boundaries.test.ts 增加回归
- **有效路径**：`src/lib/analytics/day-boundaries.ts`、`src/lib/server/analytics/settings.ts`、`tests/analytics-day-boundaries.test.ts`
