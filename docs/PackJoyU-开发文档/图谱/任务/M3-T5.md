## 实施沉淀

<!-- notes:begin -->
### 怎么实现

- **受限会话不重造**：enroll/confirm 只认 T19 已签发的 `pj_recovery` cookie（`Path=/api/auth-admin/recovery`），按 SHA-256 tokenHash 查 `AdminRecoverySession`；不读 Auth.js 会话，也换不出后台权限。所有判定在事务内 `SELECT … FOR UPDATE` 后重做，锁前结果不穿过锁等待。
- **enroll 的状态机**：首写 `encrypt(secret)`＋`pendingUntil=min(now+10min, session.expiresAt)`；同一有效 session/sv 内重入时解密同一 pending，返回原 `otpauthUri`/原期限，不旋转、不续时。session 或 pending 到期先在同一事务提交 `revokedAt`（持久 REVOKED），事务返回后由 service 抛 `recovery_expired`——若在事务内直接 throw，撤销会被回滚。
- **confirm 的一次性发布**：错码只做只读 `checkDelta`（不调用 `consumeTotpStep`，避免它写 `User.totpLastStep` 与 pending 脱节）；失败计数“+1 与第 5 次作废”是一条 UPDATE，事务提交后 service 再抛 `bad_credentials`（副作用不被回滚）。成功先 `completeRecoverySession` 领取 completedAt，再用一条 User CAS 提交 `totpSecret=pending`、`totpLastStep=step`、10 个新恢复码 hash、`sessionVersion+1`（仅 `passwordResetSource='SERVER_OWNER'` 时用 `COALESCE(pendingPasswordHash, passwordHash)`），同事务撤 `< committedSv` 的设备（reason `recovery_confirm`）、撤其他未完成受限会话、写 `recovery.completed` 审计；恢复码只在 200 响应返回一次。
- **HTTP 边界**：同源 → 8KiB 限体 → strict `{}` / `{totp}`（额外 password/newPassword/passwordHash 一律 400，不触 DB）→ IP 桶 → 受限 cookie → service；错误映射沿用 A 方案：`recovery_expired` 只给真实到期，其余（错码 1–4、第 5 次、revoked、completed）统一 `bad_credentials`；失败不清 cookie，成功才清。限流桶独立命名空间（`recovery-enroll:*` / `recovery-confirm:*`，账号 5 / IP 20 / 10min）。
- **未越界**：不改 schema/DTO/契约/CI；不用 `consumeTotpStep` 写 pending；HTTP 永不接 password 字段；`passwordlessEnabled` 原样保留。

### 踩坑

- **raw SQL 的 DateTime 必须显式 UTC**：`AnalyticsRecoverySession` 的 `DateTime` 是 PostgreSQL `timestamp(3)`。Prisma Client 写读一致，但 `$queryRaw` 直接绑 JS Date 会被驱动按 `timestamptz` 发送、再按 DB 会话时区落成 timestamp——本地实测 `pendingUntil` 比 `expiresAt` 早 8 小时，导致 R1/R2 红。新 raw 写/比较统一用 `($n::timestamptz AT TIME ZONE 'UTC')`（既有 `consumePermit` 同款），修后两条用例转绿。
- **拒绝分支的副作用**：过期撤销、错码计数/作废都不能靠“write 后 throw”——同一事务的 throw 会一起回滚。实现改为事务返回 tagged result（expired/rejected），提交后再抛 HTTP 错误。
- **测试目标校验**：两个新测试在 `db push` 前自检 `M3T3_TEST_DATABASE_URL`（loopback、显式 `schema=m3t3`、非空库、禁回退 `DATABASE_URL`），H1 用纯函数覆盖负例；清理只删本测试创建的 User（级联设备/恢复会话/permit）与其精确命中的 AuditLog。
- **限流主体**：测试请求带 `EDGE_AUTH_SECRET`＋`x-edge-auth`＋逐例 `cf-connecting-ip`，否则全部落 `untrusted` 共享桶，会把 429 误读成业务拒绝。
