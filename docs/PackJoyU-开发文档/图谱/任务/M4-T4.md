# M4-T4　消费持久聊天通知并注册每分钟作业

- 所属模块：[[M4]]　第一方人工咨询：负责访客必要会话、人工消息与离线留言、ADMIN/SALES 收件箱和回复、未读、失败草稿与幂等重试，并保存真实收件和通知结果。
- 前置依赖：[[M4-T1]]、[[M5-T1]]、[[M5-T8]]
- 完成后解锁：[[M4-T13]]、[[M4-T14]]、[[M6-T2]]、[[M6-T5]]、[[M7-T7]]

## 输入 / 产出

- **输入**：原子聊天出箱、M5固定作业基础与现有SMTP安全适配。
- **产出**：chat-notifications固定job、独立SMTP内容适配/稳定Message-ID、真实每分钟cron；不包含旧mail-queue包装。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 调用方/接线点：每分钟真实cron POST /api/admin/cron/operations(jobKey=chat-notifications)→registry→持久通知服务
保存后重启仍消费、无Bearer触发拒绝
messageId唯一出箱不因重试增项，通知只收件事实/受保护链接（[[E-90]]、[[E-94]]）。2) leaseOwner/leaseVersion原子认领并清空requestStartedAt，领取不计次
发送前以同一有效租约CAS写requestStartedAt并递增attempts，该CAS为0行不发送
SMTP事务外20s。清扫与结果写回用同一注入时钟并在取锁后判定：过期且本次标记为空→QUEUED、次数不增且立即可领，非空→UNKNOWN
写回须核status=SENDING、leaseOwner/leaseVersion及lockedUntil>当前时钟
过期＝lockedUntil<=当前时钟，等于即视为已释放，清扫只处理过期行，时钟在取锁后采样
写入方等锁期间跨过期点的写回为0行，旧worker亦不能覆盖新租约
worker确知未调用SMTP按已知失败处理、不记UNKNOWN。未达上限时，隔离SMTP接收后中断→UNKNOWN→重启后复用同stable Message-ID有界重试
首次发送后最多重试3次，最多4次已标记开始的发送尝试，明确允许SMTP重复（[[E-91]]、[[E-92]]）。3) 失败或未知结果写入时availableAt=该次写入时钟+1m/5m/30m（attempts=1/2/3），隔离测试含延迟清扫，下一档从清扫写入起算
认领与UNKNOWN提升均须attempts<4且availableAt到期
连续4次暂拒时第4次确知失败在同一结果CAS直写FAILED、不经QUEUED且lastErrorCode为脱敏码，另测第4次SMTP接收后写回前中断→UNKNOWN且停止自动重试，两案均无第5次自动尝试，全程最多4次已开始尝试
任何时刻不存在attempts>=4的QUEUED，人为植入该行时不认领、不发送、不自动迁移，按不变量违例检出。SMTP缺配置时仅attempts=0且未标记的QUEUED置DISABLED，不为同一messageId补建通知
已有UNKNOWN与attempts>0的QUEUED在缺配置期间不发送、不提升，状态与availableAt不变，恢复后按到期与上限继续
DISABLED在恢复后保持原状态。不可达/暂拒等真实状态脱敏持久保存，重启按出箱恢复
body/email/token不进通知/日志，失败不撤聊天received，HTTP触发未知不自动再触发（[[E-35]]、[[E-41]]、[[E-93]]）。

## 必须处理的边界

- [[E-35]]　C-01 人工聊天收件与回复入口
    - 触发：邮件提醒失败或未接通
    - 期望：将“真实通知状态”落到已定义 queued/sending/sent/failed 或其现有 DTO 映射，保存消息后的通知失败只改变该通知状态，不改变消息 received 或 inbox 可处理状态；未接通不得显示已发送。
- [[E-41]]　C-02 离线留言与发送失败恢复
    - 触发：留言已保存但客服回信或通知发送失败
    - 期望：保留已接收结果及收件箱待处理状态，单独呈现真实发送失败，不假装已联系到访客。
- [[E-90]]　聊天通知持久队列
    - 触发：保存消息后进程立即中断，或客户端因超时重发同一消息
    - 期望：在同一数据库事务内保存消息及 messageId 唯一的出箱记录；已提交消息可在重启后继续通知，消息幂等命中不能新增第二条通知。
- [[E-91]]　聊天通知持久队列
    - 触发：多个 cron worker 并发领取，或领取者崩溃直到租约到期
    - 期望：原子领取并携带租约/代次提交状态；过期后按本次requestStartedAt分类，可重试工作须attempts<4且availableAt到期方可重领。清扫与旧worker写回在取得行锁后按同一注入时钟判定，租约过期即不能回写，也不能覆盖新租约的处理结果；通知失败不得撤回已经成功保存的聊天消息。
- [[E-92]]　聊天通知持久队列
    - 触发：SMTP 已接收但发送进程在写回成功状态前中断
    - 期望：对尚未到上限的通知，用隔离 SMTP 受控接收后中断 worker，再重启验证可按至少一次重试并复用 stable Message-ID，且重试不早于未知结果写入后的对应退避档；达到上限仍未知时保留UNKNOWN并停止自动重试。允许 SMTP 实际重复，但本地状态不标精确一次或客服已读，聊天 received 不变；按09节 unknown-delivery/租约规则呈现真实状态。
- [[E-93]]　聊天通知持久队列
    - 触发：SMTP 不可达、配置缺失或暂时拒绝
    - 期望：把有界重试引用到09/10节持久任务/次数上限和退避规则，注入SMTP不可达/暂拒后重启验证可重试工作从持久出箱恢复；缺配置时仅从未开始尝试的QUEUED置DISABLED，已有UNKNOWN与已尝试的QUEUED暂停并保持原状态，配置恢复后按到期与上限处理；DISABLED为终态，恢复后新出箱可处理、旧DISABLED行不自动补发；日志和计数只含脱敏错误码及数量，不含主动邮箱/body；不得用 Next after() 的完成代替持久记录。
- [[E-94]]　聊天通知持久队列
    - 触发：出箱/通知接口被无聊天权限角色调用，或 SMTP 适配器仅能发送既有询盘格式
    - 期望：分别验无权限调用拒绝、chat-notifications 使用独立受限适配器且不扩展旧 mail UI；deploy/cron.nbshiyan 确有每分钟注册，重启后实际消费已提交出箱，不能只有手工调用或未来空注册。M4随交付注册，M7仅最终验收。

## 实施沉淀

<!-- notes:begin -->
- 通知租约为 40 秒，SMTP 整次截止为 20 秒。领取、标记及内容读取、发送和写回分别预留 3、3、20、5 秒，另留 3 秒完成作业摘要及 1 秒调度余量。整轮剩余时间低于 35 秒时停止领取。数据库阶段以连接等待、事务、语句和锁预算共同限时。
- 通知行锁与作业级租约事务分开。取得通知锁后采业务时钟，SQL 参数用 ISO 字符串转 UTC `timestamp`。等于租约截止时已过期。写回核对状态、owner、代次、有效期和发送标记。空标记的过期行立即回队且不计次，已有标记的进入 `UNKNOWN`。第 1–3 次可重试结果从写入时刻起等 1、5、30 分钟，封顶行保留 `availableAt`，`SENT` 清除旧错误码。
- `CHAT_NOTIFICATION_TO` 可选。生产 Node 启动时对缺失值报一次警告，非法值使生产运行期启动退出 1，诊断不含输入值。缺配置时只禁用从未开始尝试的队列行，已尝试队列和 `UNKNOWN` 暂停，恢复后按到期与上限继续。`DISABLED` 不自动补发。
- 邮件只含收件事实和受保护会话链接，保持出箱的稳定 Message-ID。查询成功且确定内容无法发送时，在有效租约下记 `CHAT_LOCAL_INVALID`，数据库读取异常归为 `UNKNOWN`。这些状态不撤回聊天 `received`。
- SMTP 截止先封定 `UNKNOWN`，再主动销毁本次连接。证书分类使用受控错误码，包括底层 `originalCode`。DATA 后断连缺明确拒收证据时保持 `UNKNOWN`。第 4 次明确失败直写 `FAILED`，第 4 次投递未知保持 `UNKNOWN`，两种情形都停止自动重试。
