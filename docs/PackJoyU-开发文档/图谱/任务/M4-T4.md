# M4-T4　消费持久聊天通知并注册每分钟作业

- 所属模块：[[M4]]　第一方人工咨询：负责访客必要会话、人工消息与离线留言、ADMIN/SALES 收件箱和回复、未读、失败草稿与幂等重试，并保存真实收件和通知结果。
- 前置依赖：[[M4-T1]]、[[M5-T1]]、[[M5-T8]]
- 完成后解锁：[[M4-T13]]、[[M4-T14]]、[[M6-T2]]、[[M6-T5]]、[[M7-T7]]

## 输入 / 产出

- **输入**：原子聊天出箱、M5固定作业基础与现有SMTP安全适配。
- **产出**：chat-notifications固定job、独立SMTP内容适配/稳定Message-ID、真实每分钟cron；不包含旧mail-queue包装。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 调用方/接线点：每分钟真实cron POST /api/admin/cron/operations(jobKey=chat-notifications)→registry→持久通知服务
保存后重启仍消费、无Bearer触发拒绝
messageId唯一出箱不因重试增项，通知只收件事实/受保护链接（[[E-90]]、[[E-94]]）。2) leaseOwner/version原子认领/CAS提交
旧worker不能覆盖新租约
SMTP事务外20s，隔离SMTP接收后中断→UNKNOWN→同stable Message-ID至少一次有界重试，最多3次并1m/5m/30m退避
明确允许SMTP重复（[[E-91]]、[[E-92]]）。3) SMTP缺配置DISABLED，不可达/暂拒/达到上限真实状态脱敏持久保存，重启按出箱恢复
body/email/token不进通知/日志，失败不撤聊天received，HTTP触发未知不自动再触发（[[E-35]]、[[E-41]]、[[E-93]]）。

## 必须处理的边界

- [[E-35]]　C-01 人工聊天收件与回复入口
    - 触发：邮件提醒失败或未接通
    - 期望：将“真实通知状态”落到已定义 queued/sending/sent/failed 或其现有 DTO 映射，保存消息后的通知失败只改变该通知状态，不改变消息 received 或 inbox 可处理状态；未接通不得显示已发送。
- [[E-41]]　C-02 离线留言与发送失败恢复
    - 触发：留言已保存但客服回信或通知发送失败
    - 期望：保留已接收结果及收件箱待处理状态，单独呈现真实发送失败，不假装已联系到访客。
- [[E-90]]　聊天通知持久队列
    - 触发：保存消息后进程立即中断，或客户端因超时重发同一消息
    - 期望：在同一数据库事务内保存消息及 messageId 唯一的出箱记录；已提交消息可在重启后继续通知，消息幂等命中不能新增第二条通知。
- [[E-91]]　聊天通知持久队列
    - 触发：多个 cron worker 并发领取，或领取者崩溃直到租约到期
    - 期望：原子领取并携带租约/代次提交状态；过期工作可重新领取，旧 worker 不能覆盖新租约的处理结果，通知失败不得撤回已经成功保存的聊天消息。
- [[E-92]]　聊天通知持久队列
    - 触发：SMTP 已接收但发送进程在写回成功状态前中断
    - 期望：用隔离 SMTP 受控接收后中断 worker，再重启验证可按至少一次重试并复用 stable Message-ID；允许 SMTP 实际重复，但本地状态不标精确一次或客服已读，聊天 received 不变；按09节 unknown-delivery/租约规则呈现真实状态。
- [[E-93]]　聊天通知持久队列
    - 触发：SMTP 不可达、配置缺失或暂时拒绝
    - 期望：把有界重试引用到09/10节持久任务/次数上限和退避规则，注入 SMTP不可达/缺配置/暂拒后重启验证从持久出箱恢复；日志和计数只含脱敏错误码及数量，不含主动邮箱/body；不得用 Next after() 的完成代替持久记录。
- [[E-94]]　聊天通知持久队列
    - 触发：出箱/通知接口被无聊天权限角色调用，或 SMTP 适配器仅能发送既有询盘格式
    - 期望：分别验无权限调用拒绝、chat-notifications 使用独立受限适配器且不扩展旧 mail UI；deploy/cron.nbshiyan 确有每分钟注册，重启后实际消费已提交出箱，不能只有手工调用或未来空注册。M4随交付注册，M7仅最终验收。
