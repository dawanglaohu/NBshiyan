# M4-T2　读取访客消息页并单调推进读位置

- 所属模块：[[M4]]　第一方人工咨询：负责访客必要会话、人工消息与离线留言、ADMIN/SALES 收件箱和回复、未读、失败草稿与幂等重试，并保存真实收件和通知结果。
- 前置依赖：[[M4-T1]]、[[M4-T8]]
- 完成后解锁：[[M4-T3]]、[[M4-T10]]

## 输入 / 产出

- **输入**：M4-T1持久seq消息与M4-T8必要cookie；09/10分页和read MAX。
- **产出**：GET /api/chat/conversations/[id]与POST /api/chat/conversations/[id]/read，访客范围/稳定分页。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 调用方/接线点：真实GET/read handlers→cookie范围repo
仅本人，afterSeq升序max100，页间插入后补齐ID恰一次，read MAX不越lastSeq、不回退，轮询仅receipt不标用户read
猜ID/seq/email无权（[[E-19]]、[[E-34]]、[[E-77]]、[[E-79]]）。2) 先以已完成POST conversations真实存首消息，再记录retainUntil/lastActivityAt
反复GET/POST read前后90d截止不变
复用M4-T8期限前置，过期cookie请求401且保留中的消息记录与正文不变（[[E-85]]）。

## 必须处理的边界

- [[E-19]]　在线聊天实现路线
    - 触发：访客猜测其他会话标识或非授权后台账号访问收件箱
    - 期望：拒绝读取和回复；访客只能使用自己的不可猜会话凭据访问本人会话。
- [[E-34]]　C-01 人工聊天收件与回复入口
    - 触发：刷新收件箱或翻页时又收到新消息
    - 期望：补入已定义 seq 游标与已读 MAX 规则：在分页间插入消息，补齐范围内消息 ID 恰一次；已读只推进到用户实际确认的 seq，新到且 seq 更大的消息仍未读。
- [[E-77]]　人工聊天同步机制
    - 触发：多个标签页、重试、响应乱序或跨分页期间又插入新消息
    - 期望：以服务端稳定 seq 和消息标识合并去重，游标只推进到已完整接收的范围；后返回的旧响应不能倒退游标、覆盖新回复或把漏页消息跳过。
- [[E-79]]　人工聊天同步机制
    - 触发：网络中断后恢复或运营收件箱尚有很多未读
    - 期望：把“有界页”引用到既定分页上限并验每次请求不越界、seq 连续补齐；轮询只更新已确认收件游标，不推进用户已读位置，不创建客服在线或已读承诺。
- [[E-85]]　聊天凭据及数据保留期限
    - 触发：cookie 闲置达到 7 天、签发达到 30 天绝对上限或被撤销
    - 期望：服务端拒绝该凭据访问旧会话，浏览器可建立新咨询；仅填写相同邮箱不能找回旧会话，cookie 与其前端副本均不存 PII。
