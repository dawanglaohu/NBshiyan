# M7-T4　终验询盘聊天闭环与容量降级

- 所属模块：[[M7]]　集成验收与交付：负责访客跨模块完整路径、后台权限与恢复路径、统计和可靠性完整链路的真实集成验收及交付证据收口；核对本轮复用的恢复来源，不重做 S1 已完成的取回和来源审计，也不自动合并恢复草稿。
- 前置依赖：[[M7-T1]]、[[M4-T6]]、[[M4-T7]]、[[M4-T14]]、[[M4-T12]]、[[M4-T13]]
- 完成后解锁：[[M7-T8]]

## 输入 / 产出

- **输入**：product-contact、访客/运营聊天和现有联系渠道、独立可用性开关
- **产出**：visitor-acceptance；带产品上下文的询盘/聊天收发及容量边界报告

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 从产品可见联系入口提交真实POST /api/inquiries及POST /api/chat/conversations，核productSlug/持久且不变消息ID
ADMIN/SALES从收件箱回复，访客seq同步收到
网络失败保留当前标签草稿，同UUID重试仅一消息
收件与通知失败独立，拒分析也可咨询（[[E-16]]、[[E-18]]、[[E-31]]、[[E-37]]、[[E-40]]）。2) 在隔离目标环境实测聊天开启前后内存/并发/延迟并记录限制
不足时实际关闭独立聊天可用性开关并保留可见原联系/询盘入口，前端显示不可用而非虚假在线
不使用旧约2.7GB快照当当前容量，不自动购买扩容（[[E-20]]）。

## 必须处理的边界

- [[E-16]]　在线聊天实现路线
    - 触发：访客首次发消息且运营在线
    - 期望：持久化会话和消息后给出已接收状态，运营收件箱可读取并人工回复，不生成 AI 自动答复。
- [[E-18]]　在线聊天实现路线
    - 触发：同一消息因重试重复提交
    - 期望：按客户端消息标识去重，收件箱只出现一条，不重复触发通知。
- [[E-20]]　在线聊天实现路线
    - 触发：上线前资源实测不足
    - 期望：保持独立开关可关闭聊天并保留现有联系入口，记录容量证据和限制，不声称快照剩余约 2.7 GB 内存等于当前可用容量，也不自动购买扩容。
- [[E-31]]　C-01 人工聊天收件与回复入口
    - 触发：访客提交消息且服务端持久化成功
    - 期望：返回稳定的会话与消息标识并显示“已接收”，运营收件箱能读取；数据库写入失败则保留待重试，不显示已接收或客服已读。
- [[E-37]]　C-02 离线留言与发送失败恢复
    - 触发：提交超时或响应丢失、实际保存状态未知
    - 期望：显示待确认或可重试，以原客户端消息标识重试并返回原收件结果，收件箱与通知不产生重复项。
- [[E-40]]　C-02 离线留言与发送失败恢复
    - 触发：访客拒绝分析但主动打开第一方人工聊天
    - 期望：允许完成必要咨询，不创建分析标识或加载第三方聊天脚本，聊天必要会话与分析同意分开处理。
