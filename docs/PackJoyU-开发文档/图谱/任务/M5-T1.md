## 实施沉淀

<!-- notes:begin -->
领取和完成的胜负必须落在同一条条件语句里。先读出 lockedUntil 再写，两个连接会同时认为租约空闲。领取用 `lockedUntil IS NULL OR lockedUntil <= 时钟`，续租和完成用 `lockedUntil > 时钟`。满 90 秒的同一时刻，新代次可以领取，旧 owner 不能续租或完成。

lastSucceededAt 只在完成语句的 CASE 中、状态为 SUCCEEDED 时写成当前时钟。失败和部分完成走 ELSE。代次、owner、租约或时区 revision 不匹配时，这条 UPDATE 影响 0 行，成功时间、summary 和租约都不变。新代次领取也不清 lastSucceededAt，新一轮中途停止后，安全读取仍保留上一次成功时间。

时钟由调用方注入，默认是服务端 `new Date()`，作为 UTC 文本参数进入条件语句，不从 summary 读取。测试拨动这个时钟跨过 90 秒。该列是 timestamp without time zone；把 JavaScript Date 直接绑定给驱动时，驱动会按会话时区解释，比较和读回都会偏移。读回用 SQL 的 to_char 格式化已存的 UTC 分量。

summary 写库前用严格 schema 解析。计数只用契约 JobCountsSchema。时间只允许 dataThrough、sourceThrough、aggregatedAt、measuredAt。版本只允许 timezoneRevision、policyVersion。多余字段、脚本、命令和原始异常文本整次拒绝，且不释放租约。读出时再解析一次；库里已有的不合白名单 JSON 或错误码按空值返回。

完成在同一事务里锁住 SiteSetting 的 analytics.settings。没有这行时 revision 是 1。行存在但没有正整数 timezoneRevision 时，领取和完成都拒绝。调用方带回领取时看到的 revision；当前值不同则不写。revision 比较同时留在 UPDATE 的 WHERE 里。

没有执行 summary、注册任意 key 或运行脚本的入口。key 只接受契约中的六个作业名。这个原语不注册生产组合和 cron，M5-T8 负责接入。

deploy.sh 保持原样。schema_sync 已经对整份 prisma/schema.prisma 做备份、diff、plan-check 和 db push，push 命令不含 --accept-data-loss。单独的 SQL 文件不会被这条路径执行。
