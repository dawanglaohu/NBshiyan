# M4-T1　原子保存咨询首消息及唯一通知出箱

- 所属模块：[[M4]]　第一方人工咨询：负责访客必要会话、人工消息与离线留言、ADMIN/SALES 收件箱和回复、未读、失败草稿与幂等重试，并保存真实收件和通知结果。
- 前置依赖：[[M4-T8]]、[[M5-T1]]、[[M5-T8]]
- 完成后解锁：[[M4-T2]]、[[M4-T4]]、[[M4-T10]]

## 输入 / 产出

- **输入**：M4-T8真实必要cookie、M5作业基础、09/10消息/会话/出箱约束。
- **产出**：ChatConversation/Message/ReadCursor/Notification schema；POST /api/chat/conversations及持久首消息服务。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 调用方/接线点：真实POST conversations→cookie范围服务→会话+首消息+seq+messageId唯一出箱同事务，成功才返持久不变id/seq/receivedAt
数据库失败无部分记录，同UUID同payload返回原结果、异payload409、并发仅一消息一通知（[[E-18]]、[[E-31]]、[[E-90]]）。2) 16KiB限体后strict schema，正文1..4000code points纯文本，email省略/空值可发送，trim后超254、CRLF/显示名/非法格式字段错误
身份取cookie，不能关联他人session，拒分析仍接收且不建分析身份（[[E-39]]、[[E-40]]）。

## 必须处理的边界

- [[E-18]]　在线聊天实现路线
    - 触发：同一消息因重试重复提交
    - 期望：按客户端消息标识去重，收件箱只出现一条，不重复触发通知。
- [[E-31]]　C-01 人工聊天收件与回复入口
    - 触发：访客提交消息且服务端持久化成功
    - 期望：返回稳定的会话与消息标识并显示“已接收”，运营收件箱能读取；数据库写入失败则保留待重试，不显示已接收或客服已读。
- [[E-39]]　C-02 离线留言与发送失败恢复
    - 触发：访客主动提供空邮箱、非法格式或超长联系方式
    - 期望：镜像10节已定字段：email 可省略；填写时 trim 后≤254、单个合法邮箱、不接收显示名/CRLF；空值按不填处理，非法或过长返回字段错误并保留当前标签页原消息，不升级为已验证身份或投递保证。
- [[E-40]]　C-02 离线留言与发送失败恢复
    - 触发：访客拒绝分析但主动打开第一方人工聊天
    - 期望：允许完成必要咨询，不创建分析标识或加载第三方聊天脚本，聊天必要会话与分析同意分开处理。
- [[E-90]]　聊天通知持久队列
    - 触发：保存消息后进程立即中断，或客户端因超时重发同一消息
    - 期望：在同一数据库事务内保存消息及 messageId 唯一的出箱记录；已提交消息可在重启后继续通知，消息幂等命中不能新增第二条通知。
