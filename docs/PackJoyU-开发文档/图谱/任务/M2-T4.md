## 实施沉淀

<!-- notes:begin -->
- 重复终态按[幂等（Idempotency）](https://vibe-hub.org/idempotency)处理：同一次观察再次到达时不产生第二条 success 或 failure。eventId 必须由调用方传入；本模块另造 id 会让同一次观察的重放变成新事件。
- durationMs 等于终态与 start 的注入整数时钟差，不是 occurredAt 相减。差值小于 0 或大于 600000 时种类已经定案，但不发出这条终态，也不把差值夹到边界。非整数时钟不可读，不锁定尝试，后面的合法终态仍可决定。
- 终态信号没有产品字段。productSlug、navigationId、locale 只从打开该 viewId 的 start 抄出。path 要过共享 SitePathSchema，query 和 hash 会被去掉；这不改变产品或导航。
- surface 省略或为 glb 才是真实加载。poster 与 fold-box（FoldBox）无论放在 display 上还是 success 上，都不写入账本。若先缓冲成 pending，同 viewId 后到的 GLB start 会把海报成功发出去。省略 surface 会被当成真实 GLB。
- cancel 不写 failure，也不收回已经发出的 start，只拒绝该 viewId 之后的终态。retry 的 viewId 必须不同于 previousViewId。新 start 被 schema 拒绝、surface 不是 glb、或该 viewId 已占用时，整次 retry 保持旧尝试开着；先取消再发现新 start 无效，会丢掉仍在加载的那次尝试。
- 终态先于 start 到达时只保留第一种，start 通过后按 start、terminal 发出。没有对应 start 的终态不单独发出。对已缓冲终态的 viewId 调用 cancel，会丢掉该终态并占住这个 id；对完全未知的 viewId，cancel 是空操作。
- 失败原因只有 LOAD_ERROR、TIMEOUT、WEBGL_UNAVAILABLE。timeout 信号固定写成 TIMEOUT。未知原因不锁定尝试。context lost 由 M2-T7 在调用前映射成这三项之一。本模块不读取同意状态，也不代替 M2-T7 发请求。
<!-- notes:end -->
