# M4-T10　幂等追加访客消息并更新咨询保留期限

- 所属模块：[[M4]]　第一方人工咨询：负责访客必要会话、人工消息与离线留言、ADMIN/SALES 收件箱和回复、未读、失败草稿与幂等重试，并保存真实收件和通知结果。
- 前置依赖：[[M4-T2]]、[[M4-T1]]
- 完成后解锁：[[M4-T5]]、[[M4-T11]]

## 输入 / 产出

- **输入**：M4持久conversation/seq/出箱及只读/已读API。
- **产出**：POST /api/chat/conversations/[id]/messages；可复用消息追加服务。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 调用方/接线点：真实POST messages→cookie范围/OPEN校验→锁行seq+消息+出箱+90d期限同事务
同clientMessageId同payload返回原id/seq且通知一条，异payload409、closed/anonymized拒绝，写失败无变更（[[E-18]]、[[E-33]]、[[E-90]]）。2) 成功存储后丢弃HTTP响应，用原UUID/payload重试返回相同receipt
只有首次提交推进90d，读/通知不推进
过期/撤销或换别人的id/email不能读写（[[E-37]]、[[E-78]]、[[E-86]]）。

## 必须处理的边界

- [[E-18]]　在线聊天实现路线
    - 触发：同一消息因重试重复提交
    - 期望：按客户端消息标识去重，收件箱只出现一条，不重复触发通知。
- [[E-33]]　C-01 人工聊天收件与回复入口
    - 触发：两名有权限人员并发回复或访客重复发送相同客户端消息标识
    - 期望：明确以服务端 seq 排序并展示真实 author；同会话同 clientMessageId 同载荷仅一条消息、一个出箱项和一次未读增加；并发人工回复各自保存，不由后返回响应覆盖先保存回复。
- [[E-37]]　C-02 离线留言与发送失败恢复
    - 触发：提交超时或响应丢失、实际保存状态未知
    - 期望：显示待确认或可重试，以原客户端消息标识重试并返回原收件结果，收件箱与通知不产生重复项。
- [[E-78]]　人工聊天同步机制
    - 触发：访客会话到期/撤销，或运营角色从 ADMIN/SALES 变为无聊天权限
    - 期望：下一次轮询和发送均做服务端鉴权并停止返回会话内容；修改 threadId、seq 或邮箱不能读取其他咨询。
- [[E-86]]　聊天凭据及数据保留期限
    - 触发：隐藏标签页仍有轮询，或仅刷新访问但没有成功收发咨询消息
    - 期望：这些行为不推迟消息/邮箱的 90 天保留截止；咨询活动以成功保存的访客消息或人工回复为准，不把通知重试、投递回执或读状态更新当作新咨询。
- [[E-90]]　聊天通知持久队列
    - 触发：保存消息后进程立即中断，或客户端因超时重发同一消息
    - 期望：在同一数据库事务内保存消息及 messageId 唯一的出箱记录；已提交消息可在重启后继续通知，消息幂等命中不能新增第二条通知。
