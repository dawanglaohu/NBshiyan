# M4-T14　在真实双端会话接通人工回复与关闭

- 所属模块：[[M4]]　第一方人工咨询：负责访客必要会话、人工消息与离线留言、ADMIN/SALES 收件箱和回复、未读、失败草稿与幂等重试，并保存真实收件和通知结果。
- 前置依赖：[[M4-T6]]、[[M4-T11]]、[[M4-T4]]
- 完成后解锁：[[M2-T8]]、[[M7-T4]]

## 输入 / 产出

- **输入**：M4-T6真实收件页、M4-T11人工写API、M4-T9访客同步、通知job。
- **产出**：OperatorReplyComposer/关闭控件、访客到运营到访客的真实可操作闭环。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 入口：访客contact窗口Send→received，运营后台Human conversations→实际会话行→Send reply（operator-chat-send）
数据源POST /api/admin/chat/conversations/[id]/messages及双方GET
点发后真实保存作者body，访客轮询显示同条人工消息，期间无AI生成回复
DB保存失败没有received（[[E-16]]、[[E-31]]）。2) 两名真实运营并发回复各保留seq/author，点击Close conversation（operator-chat-close）PATCH expectedVersion，冲突读最新不自动改写、关闭后两端发信409
撤权下一send403且无新行
通知失败只改变通知态（[[E-33]]、[[E-35]]、[[E-41]]、[[E-78]]）。 按11节唯一minimalist-flat，在实际服务1920×1080、1440×900、390×844记录GIF与computed style：2px黑边、0圆角、无阴影、强调色#b45700
后台逐页以work/form/card、density7/gutter16/gap16/pad16运行D1–D6和overflow探针。label与键盘焦点可达，触屏控件点击框至少44px。

## 必须处理的边界

- [[E-16]]　在线聊天实现路线
    - 触发：访客首次发消息且运营在线
    - 期望：持久化会话和消息后给出已接收状态，运营收件箱可读取并人工回复，不生成 AI 自动答复。
- [[E-31]]　C-01 人工聊天收件与回复入口
    - 触发：访客提交消息且服务端持久化成功
    - 期望：返回稳定的会话与消息标识并显示“已接收”，运营收件箱能读取；数据库写入失败则保留待重试，不显示已接收或客服已读。
- [[E-33]]　C-01 人工聊天收件与回复入口
    - 触发：两名有权限人员并发回复或访客重复发送相同客户端消息标识
    - 期望：明确以服务端 seq 排序并展示真实 author；同会话同 clientMessageId 同载荷仅一条消息、一个出箱项和一次未读增加；并发人工回复各自保存，不由后返回响应覆盖先保存回复。
- [[E-35]]　C-01 人工聊天收件与回复入口
    - 触发：邮件提醒失败或未接通
    - 期望：将“真实通知状态”落到已定义 queued/sending/sent/failed 或其现有 DTO 映射，保存消息后的通知失败只改变该通知状态，不改变消息 received 或 inbox 可处理状态；未接通不得显示已发送。
- [[E-41]]　C-02 离线留言与发送失败恢复
    - 触发：留言已保存但客服回信或通知发送失败
    - 期望：保留已接收结果及收件箱待处理状态，单独呈现真实发送失败，不假装已联系到访客。
- [[E-78]]　人工聊天同步机制
    - 触发：访客会话到期/撤销，或运营角色从 ADMIN/SALES 变为无聊天权限
    - 期望：下一次轮询和发送均做服务端鉴权并停止返回会话内容；修改 threadId、seq 或邮箱不能读取其他咨询。
