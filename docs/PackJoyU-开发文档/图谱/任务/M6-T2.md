# M6-T2　接入询盘与聊天只读业务计数

- 所属模块：[[M6]]　业务与运维看板：负责按角色查询并解释统计结果，读取询盘、聊天、接口错误、邮件、存储和备份的真实来源，区分数据时间、零值、无数据、未接入、失败和旧值。
- 前置依赖：[[M6-T6]]、[[M4-T4]]
- 完成后解锁：[[M6-T7]]

## 输入 / 产出

- **输入**：stats-core、真实Inquiry/ChatConversation/ChatMessage与既有SALES scope
- **产出**：stats-business；统计入口business来源适配器

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 通过真实POST /api/inquiries及POST /api/chat/conversations保存合成询盘/消息，再GET /api/admin/stats请求business来源核持久且不变业务ID计数
同消息UUID重试及被拒垃圾不增加计数，结果不含email/body（[[E-62]]）。2) ADMIN/SALES按既有询盘scope只读查询
统计查询故障不能回滚或阻断咨询保存，业务计数不要求M4导入M6
未登录及EDITOR直接请求业务来源拒绝（[[E-62]]、[[E-66]]）。

## 必须处理的边界

- [[E-62]]　运维指标扩展及角色权限
    - 触发：询盘或聊天被成功持久化、重复重试或垃圾提交被拒绝
    - 期望：明确业务计数读取已成功持久化的 inquiry/conversation/message 稳定业务标识；同标识重试与被拒垃圾不加计数；M6只读来源，结果 DTO 不含 email、body 等个人字段，不要求业务写入等待看板。
- [[E-66]]　运维指标扩展及角色权限
    - 触发：SALES、EDITOR 或未登录用户直接访问运维接口或导出地址
    - 期望：按09/10节来源矩阵直接测：ADMIN全来源、SALES受既有 scope 的业务聚合、EDITOR公开流量/产品/3D；直接请求系统敏感来源403，混合来源响应在查询前裁剪且不含被隐藏计数。
