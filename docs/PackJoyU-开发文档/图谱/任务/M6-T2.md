# M6-T2　接入询盘与聊天只读业务计数

- 所属模块：[[M6]]　业务与运维看板：负责按角色查询并解释统计结果，读取询盘、聊天、接口错误、邮件、存储和备份的真实来源，区分数据时间、零值、无数据、未接入、失败和旧值。
- 前置依赖：[[M6-T6]]、[[M4-T4]]
- 完成后解锁：[[M6-T7]]

## 输入 / 产出

- **输入**：stats-core、真实Inquiry/ChatConversation/ChatMessage与既有SALES scope
- **产出**：stats-business；统计入口business来源适配器

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 通过真实POST /api/inquiries及POST /api/chat/conversations保存合成询盘/消息，再GET /api/admin/stats请求business来源核持久且不变业务ID计数
同消息UUID重试及被拒垃圾不增加计数，结果不含email/body（[[E-62]]）。2) ADMIN/SALES按既有询盘scope只读查询
统计查询故障不能回滚或阻断咨询保存，业务计数不要求M4导入M6
未登录及EDITOR直接请求业务来源拒绝（[[E-62]]、[[E-66]]）。

## 必须处理的边界

- [[E-62]]　运维指标扩展及角色权限
    - 触发：询盘或聊天被成功持久化、重复重试或垃圾提交被拒绝
    - 期望：明确业务计数读取已成功持久化的 inquiry/conversation/message 稳定业务标识；同标识重试与被拒垃圾不加计数；M6只读来源，结果 DTO 不含 email、body 等个人字段，不要求业务写入等待看板。
- [[E-66]]　运维指标扩展及角色权限
    - 触发：SALES、EDITOR 或未登录用户直接访问运维接口或导出地址
    - 期望：按09/10节来源矩阵直接测：ADMIN全来源、SALES受既有 scope 的业务聚合、EDITOR公开流量/产品/3D；直接请求系统敏感来源403，混合来源响应在查询前裁剪且不含被隐藏计数。

## 实施沉淀

<!-- notes:begin -->
- 业务计数仅覆盖 `inquiries`、`chat_conversations`、`chat_messages` 三张业务表的已持久化主键，`chat_notifications` 属投递可靠性留归 [[M6-T5]]。询盘产品过滤须用 `items: { some: { productSlug } }` 生成 `EXISTS` 子查询，避免同一询盘含多条明细时因连接翻倍。[[E-62]]
- 经 [身份认证（Authentication）](https://vibe-hub.org/authentication) 与 [权限控制（Authorization）](https://vibe-hub.org/authorization) 后，`handleGetStats` 显式透传当前请求 `userId` 而不挂进程级用户状态；`inquiries` 复用既有 `inquiryScope` 使 `SALES` 仅计本人受派询盘，聊天则沿共享人工收件箱语义对 `ADMIN`/`SALES` 同口径计数。`SALES` 调用缺少 `userId` 时直接降级为 `query_failed`，不得回退为无过滤全站计数。[[E-66]]
- 读取固定在 `SET TRANSACTION READ ONLY` 事务（2s 等待、5s 超时）内执行，异常仅令该来源返回 `query_failed`，不依赖分析同意密钥或聚合作业状态，也不阻塞或回滚咨询写入；尚未到来的未来日期窗口（`startUtc > now`）返回 `no_data`，不伪报 `zero`/`full`。[[E-62]]
- CI 主段共享单应用进程内存限流桶，`e2e/stats-business-api.spec.ts` 须为询盘与聊天请求上下文分配独立可信边缘测试 IP（`198.18.10.20`/`21`），不可落入共享 `untrusted` 桶。
