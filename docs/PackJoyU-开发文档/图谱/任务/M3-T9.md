# M3-T9　在账号行复用验证对话框授权恢复

- 所属模块：[[M3]]　后台访问与账号：负责统一后台登录页和后台公共外壳、个人设置、设备会话、验证器绑定与登录方式切换、会话撤销及独立受限恢复，并负责既有后台页面的共享视觉迁移/回归；不改其询盘/邮件/规格/模型业务，消费 M1 的唯一视觉 token。
- 前置依赖：[[M3-T12]]、[[M3-T4]]
- 完成后解锁：[[M3-T25]]、[[M7-T5]]、[[M7-T6]]

## 输入 / 产出

- **输入**：既有UsersAdmin、M3-T12 ReauthDialog、M3-T4目标授权API。
- **产出**：/admin/users目标行授权按钮与单次permit结果区；移除原直接重置调用。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 入口：后台Account permissions（admin-users-link）→/admin/users→真实他人行Authorize recovery（user-authorize-recovery-{id}）
数据源既有用户列表、POST /api/admin/account/reauth及POST /api/admin/account/recovery-authorizations
复用现成对话框点击后实际依次发送target grant和permit请求，target因素不变、token一次显示且审计actor/source/target齐（[[E-13]]）。2) 自己行无授权控制，直请求self/EDITOR/SALES/旧无body reset均拒绝
取消不发请求，未知结果不重复签，关闭结果区清秘密而用户增删角色流程契约不改（[[E-73]]）。 按11节唯一minimalist-flat，在实际服务1920×1080、1440×900、390×844记录GIF与computed style：2px黑边、0圆角、无阴影、强调色#b45700
后台逐页以work/form/card、density7/gutter16/gap16/pad16运行D1–D6和overflow探针。label与键盘焦点可达，触屏控件点击框至少44px。

## 必须处理的边界

- [[E-13]]　C-04 验证器丢失与单管理员恢复
    - 触发：另一管理员代为授权恢复
    - 期望：授权方必须重新验证，不能仅凭已打开后台页面或访客邮件请求重置其他账号。
- [[E-73]]　敏感设置的新鲜本人验证
    - 触发：两次请求并发使用同一 ActionGrant，或把改密码授权用于关闭验证器
    - 期望：在敏感变更事务内按动作、设备、账号及凭证版本校验并一次性消费授权，只有一个匹配请求成功，目的不符请求拒绝且不能执行变更。
