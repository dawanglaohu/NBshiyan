# M4-T6　接通运营收件箱和只读会话页

- 所属模块：[[M4]]　第一方人工咨询：负责访客必要会话、人工消息与离线留言、ADMIN/SALES 收件箱和回复、未读、失败草稿与幂等重试，并保存真实收件和通知结果。
- 前置依赖：[[M4-T3]]、[[M3-T7]]、[[M4-T9]]
- 完成后解锁：[[M2-T8]]、[[M4-T14]]、[[M7-T4]]

## 输入 / 产出

- **输入**：M4运营读取API、M3后台壳、已完成seq轮询组件。
- **产出**：/admin/chat、/admin/chat/[id]读容器、实际未读导航/分页/状态；人工发送控制由M4-T14添加。

## 必须处理的边界

- [[E-31]]　C-01 人工聊天收件与回复入口
    - 触发：访客提交消息且服务端持久化成功
    - 期望：返回稳定的会话与消息标识并显示“已接收”，运营收件箱能读取；数据库写入失败则保留待重试，不显示已接收或客服已读。
- [[E-32]]　C-01 人工聊天收件与回复入口
    - 触发：未登录、EDITOR、已被撤销权限的账号或访客猜测他人会话标识
    - 期望：直接请求读取/回复接口分别验未登录、EDITOR、撤权账号、他人访客凭据均无内容且无写入；ADMIN/SALES 仅按当前权限返回；不以隐藏按钮作为权限证据。
- [[E-34]]　C-01 人工聊天收件与回复入口
    - 触发：刷新收件箱或翻页时又收到新消息
    - 期望：补入已定义 seq 游标与已读 MAX 规则：在分页间插入消息，补齐范围内消息 ID 恰一次；已读只推进到用户实际确认的 seq，新到且 seq 更大的消息仍未读。
- [[E-35]]　C-01 人工聊天收件与回复入口
    - 触发：邮件提醒失败或未接通
    - 期望：将“真实通知状态”落到已定义 queued/sending/sent/failed 或其现有 DTO 映射，保存消息后的通知失败只改变该通知状态，不改变消息 received 或 inbox 可处理状态；未接通不得显示已发送。
- [[E-41]]　C-02 离线留言与发送失败恢复
    - 触发：留言已保存但客服回信或通知发送失败
    - 期望：保留已接收结果及收件箱待处理状态，单独呈现真实发送失败，不假装已联系到访客。
- [[E-76]]　人工聊天同步机制
    - 触发：聊天/收件箱可见且请求成功
    - 期望：以 3 秒为正常间隔；标签页隐藏时暂停，恢复可见立即从已确认 seq 补齐；慢网或连续失败采用有界退避，间隔最多 30 秒，任一轮不能叠加无限在途请求。
- [[E-77]]　人工聊天同步机制
    - 触发：多个标签页、重试、响应乱序或跨分页期间又插入新消息
    - 期望：以服务端稳定 seq 和消息标识合并去重，游标只推进到已完整接收的范围；后返回的旧响应不能倒退游标、覆盖新回复或把漏页消息跳过。
- [[E-78]]　人工聊天同步机制
    - 触发：访客会话到期/撤销，或运营角色从 ADMIN/SALES 变为无聊天权限
    - 期望：下一次轮询和发送均做服务端鉴权并停止返回会话内容；修改 threadId、seq 或邮箱不能读取其他咨询。
- [[E-79]]　人工聊天同步机制
    - 触发：网络中断后恢复或运营收件箱尚有很多未读
    - 期望：把“有界页”引用到既定分页上限并验每次请求不越界、seq 连续补齐；轮询只更新已确认收件游标，不推进用户已读位置，不创建客服在线或已读承诺。
