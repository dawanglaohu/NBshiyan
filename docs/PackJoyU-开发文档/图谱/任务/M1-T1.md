## 实施沉淀

<!-- notes:begin -->
**token 值与消费规则分两处。** 值只写在 `src/styles/tokens.css` 的 `:root`；既有选择器在 `src/app/globals.css` 末尾消费这些值。后置规则按层叠覆盖原值；`tests/catbar-card-spacing.test.ts` 固定了原正文行高，`tests/home-entry-grid-308.test.ts` 固定了入口布局与图片规则。整合原规则时须同步对应测试并保留 computed style 验证。

**正文行高靠层叠覆盖，不是唯一声明。** `src/app/globals.css` 上方仍有 `body{line-height:1.55}`（16px × 1.55 = 24.8px），文件末尾那条 `line-height:var(--pj-body-line)` 是 24px 的唯一生效声明。删掉末尾这条，computed style 会静默回到 24.8px，冒烟的 `body line-height` 断言随即变红。

**焦点颜色没有独立变量。** 11 节只给了 `--pj-focus-width`/`--pj-focus-offset`，颜色由组件表规定为强调色，因此 `:focus-visible` 直接写 `var(--pj-accent)`，不再造 `--pj-focus`。11 节若日后新增焦点颜色变量，改这一处即可。

**深色区按钮必须带 `:not(.ghost)`。** `.theme-premium .btn:not(.ghost)` 这类既有规则特异性高于 `.theme-premium .btn`，只写后者压不住，按钮在礼盒/酒盒 band 里会保持旧配色。

**深色区的焦点环必须反白。** 按第11节组件表，`.theme-premium` 与 `.cta-band` 的按钮统一使用 `globals.css:352` 的 `--pj-bg` 白色 outline，宽度与 offset 均为2px；浅色区仍用强调色。`e2e/brand-smoke.spec.ts:185` 通过真实键盘聚焦核对三个深色按钮及浅色对照，防止全局焦点规则覆盖深色例外。

**RUM 载荷由同次服务日志核验。** 本轮环境未从 Playwright 的 `postData()` / `postDataBuffer()` 取得 sendBeacon 的 Blob body，因此浏览器侧核真实 `POST /api/rum` 与204，再读取同次 standalone stdout 的新增白名单日志；另用真实 HTTP 验证带 `email` 字段400、路径带query时400及合法载荷204空体。`tests/rum.test.ts` 固定解析白名单；这些证据不依赖替换应用请求。

**App Router 的客户端跳转不产生 document 响应。** 点 header 产品链接后 `waitForResponse` 等 `resourceType === 'document'` 会 30 秒超时；改为等 URL，再用 `request.get('/en/products')` 单独取该路由的服务端 HTML 来证明产品卡是 SSR 直出的。

**产品卡计数用 `<article[^>]*class="card`。** 12 张卡里有宽窄两种 class 组合，写死 `class="card"` 只能数到 10 张。

**`/api/models` 的 200 不按环境跳过。** 该端点走 `listPublishedModels()` 查库，服务进程连的是 `DATABASE_URL` 指向的测试库，e2e 跑之前库必须就位。跳过会让「200」这条验收在 CI 之外无人核过，所以库缺失时直接红；本机自备一份 PostgreSQL 跑同一条用例，CI 用 postgres service。

**全部 e2e 用例共用一个 standalone 服务，不是 `next start`。** 浏览器冒烟必须验真实构建产物，所以 `playwright.config.ts` 的 app webServer 改成 `node .next/standalone/server.js`，并在 config 加载时把 `.next/static` 与 `public` 复制进 `.next/standalone/`——standalone 产物本身不含这两样，不复制的话样式与媒体全 404，computed style 断言会以看不懂的方式失败。不要为了「本地跑得快」改回 `next start`，那验的不是同一份东西。

**webServer 的 stdout 默认被丢弃。** Playwright 只在 `stdout: 'pipe'` 或调试模式下才把 webServer 的输出转给 reporter，而 CI 用的 github reporter 即使拿到也不打印。所以 standalone 的 stdout 用 shell 重定向落盘到 `.next/standalone-server.log`，spec 与 CI 都读这份文件核 RUM 脱敏白名单。改回「看控制台输出」会拿不到任何 RUM 行。

**RUM 冒烟使用真实页面生命周期。** `WebVitals` 在每次 `useReportWebVitals` 回调时发送允许的指标。冒烟在可见同意后执行真实浏览器导航，让待结算指标按真实页面生命周期触发上报；App Router 站内跳转不卸载文档。测试不以人工派发 `pagehide` / `visibilitychange` 代替浏览器行为。

**standalone 的 e2e 必须显式给 `APP_ORIGIN`。** `assertSameOrigin` 的生产判断只认 `APP_ENV` / `VERCEL_ENV`，不由 `NODE_ENV` 决定；生产环境只允许配置的 `APP_ORIGIN`，非生产还允许请求自身 origin。此测试配置下 `req.url` 的监听地址为 `http://0.0.0.0:3100`，与浏览器 `http://localhost:3100` 不同，因此须显式设置 `APP_ORIGIN`。缺失时后台写请求返回403 `forbidden_origin`；应修正测试配置并保留原守卫。

**GIF 录制证据。** 六帧来自同次真实 standalone（127.0.0.1:3210）：首页、主按钮焦点、产品页、产品卡、同意条及深色区焦点。截图视口为1280×800，Pillow编码后的GIF为1100×688；每帧时长按实际帧数生成。同意条先经可见控件操作，再读取 `pj-consent` 核对结果，不写入浏览器状态。
