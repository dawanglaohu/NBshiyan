## 实施沉淀

<!-- notes:begin -->
**token 值与消费规则分两处。** 值只写在 `src/styles/tokens.css` 的 `:root`；把值接到既有选择器上的规则在 `src/app/globals.css` 末尾。原因是层叠：`.btn`、`.entry a`、`.hero`、`body` 的原规则被 `tests/catbar-card-spacing.test.ts` 与 `tests/home-entry-grid-308.test.ts` 逐字锁定，改原规则会直接红；末尾同特异性、后出现的规则改值，原规则不动。要把两处合并成一处，先改对应测试。

**正文行高靠层叠覆盖，不是唯一声明。** `src/app/globals.css` 上方仍有 `body{line-height:1.55}`（16px × 1.55 = 24.8px），文件末尾那条 `line-height:var(--pj-body-line)` 是 24px 的唯一生效声明。删掉末尾这条，computed style 会静默回到 24.8px，冒烟的 `body line-height` 断言随即变红。

**焦点颜色没有独立变量。** 11 节只给了 `--pj-focus-width`/`--pj-focus-offset`，颜色由组件表规定为强调色，因此 `:focus-visible` 直接写 `var(--pj-accent)`，不再造 `--pj-focus`。11 节若日后新增焦点颜色变量，改这一处即可。

**深色区按钮必须带 `:not(.ghost)`。** `.theme-premium .btn:not(.ghost)` 这类既有规则特异性高于 `.theme-premium .btn`，只写后者压不住，按钮在礼盒/酒盒 band 里会保持旧配色。

**深色区的焦点环必须反白。** 深色区按钮是白底黑字，强调色 `#b45700` 落在 `#121214`/`--premium-bg` 上看不见；旧的 `--focus-ring:var(--gold)`（金色）也只覆盖 `.theme-premium`，`.cta-band` 靠另一条规则单独指白，两处会漂。现在两处统一走 `globals.css:352` 的 `--pj-bg` 白色 outline，offset 与浅色区一致。改浅色区的焦点色时别顺手把这条也改回强调色——`e2e/brand-smoke.spec.ts:185` 会红。

**`navigator.sendBeacon` 的请求体在 Playwright 侧读不到。** `request().postData()` 与 `postDataBuffer()` 对 Blob body 都返回 null，这是浏览器实现限制。所以浏览器侧只断言真实发生 `POST /api/rum` 且 204；载荷脱敏用真实 HTTP 打端点验证（带 `email` 字段 400、白名单 204 空体），字段白名单另由 `tests/rum.test.ts` 固定。想靠拦截浏览器请求断言载荷会一直拿到 null，不要往那个方向改。

**App Router 的客户端跳转不产生 document 响应。** 点 header 产品链接后 `waitForResponse` 等 `resourceType === 'document'` 会 30 秒超时；改为等 URL，再用 `request.get('/en/products')` 单独取该路由的服务端 HTML 来证明产品卡是 SSR 直出的。

**产品卡计数用 `<article[^>]*class="card`。** 12 张卡里有宽窄两种 class 组合，写死 `class="card"` 只能数到 10 张。

**`/api/models` 的 200 不按环境跳过。** 该端点走 `listPublishedModels()` 查库，服务进程连的是 `DATABASE_URL` 指向的测试库，e2e 跑之前库必须就位。跳过会让「200」这条验收在 CI 之外无人核过，所以库缺失时直接红；本机自备一份 PostgreSQL 跑同一条用例，CI 用 postgres service。

**全部 e2e 用例共用一个 standalone 服务，不是 `next start`。** 浏览器冒烟必须验真实构建产物，所以 `playwright.config.ts` 的 app webServer 改成 `node .next/standalone/server.js`，并在 config 加载时把 `.next/static` 与 `public` 复制进 `.next/standalone/`——standalone 产物本身不含这两样，不复制的话样式与媒体全 404，computed style 断言会以看不懂的方式失败。不要为了「本地跑得快」改回 `next start`，那验的不是同一份东西。

**webServer 的 stdout 默认被丢弃。** Playwright 只在 `stdout: 'pipe'` 或调试模式下才把 webServer 的输出转给 reporter，而 CI 用的 github reporter 即使拿到也不打印。所以 standalone 的 stdout 用 shell 重定向落盘到 `.next/standalone-server.log`，spec 与 CI 都读这份文件核 RUM 脱敏白名单。改回「看控制台输出」会拿不到任何 RUM 行。

**RUM 上报要真实导航触发。** web-vitals 把指标攒到文档卸载才发；App Router 的站内跳转不卸载文档，所以在页面里 `dispatchEvent('pagehide')` 只是自欺。冒烟改为同意后 `page.goto('/en/products')` 走一次真实浏览器导航，让 `pagehide`/`visibilitychange` 自然发生。

**standalone 的 e2e 必须显式给 `APP_ORIGIN`。** `.next/standalone/server.js` 把 `NODE_ENV` 钉成 production，于是 `src/lib/server/admin-guard.ts:25` 的 `assertSameOrigin` 走生产分支：只认 `APP_ORIGIN`，不再自动放行请求自身 origin（standalone 下 `req.url` 是监听地址 `http://0.0.0.0:3100`）。CI 的 e2e env 漏了这一项时，admin-about-images / admin-enroll / admin-org-settings 会整片 403 `forbidden_origin`，页面文案是「请求无效，请刷新页面重试」，看起来像前端 bug。本地复现同一现象时先查这个变量，别去改守卫。

**GIF 用 Pillow 编码。** 本机没有 ffmpeg，skill 自带编码脚本跑不了；帧仍来自真实 standalone（127.0.0.1:3210），用 Pillow 合成 1280×800 的 6 帧（首页 / 主按钮焦点 / 产品页 / 产品卡 / 同意条 / 深色区焦点）。同意条的等待条件是 `localStorage` 里 `pj-consent` 落地，不是固定延时。每帧时长按帧数生成，写死 5 个会在增删帧时抛 `IndexError: list index out of range`。
