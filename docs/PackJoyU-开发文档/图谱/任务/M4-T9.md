## 必须处理的边界

- [[E-18]]　在线聊天实现路线
    - 触发：同一消息因重试重复提交
    - 期望：按客户端消息标识去重，收件箱只出现一条，不重复触发通知。
- [[E-37]]　C-02 离线留言与发送失败恢复
    - 触发：提交超时或响应丢失、实际保存状态未知
    - 期望：显示待确认或可重试，以原客户端消息标识重试并返回原收件结果，收件箱与通知不产生重复项。
- [[E-38]]　C-02 离线留言与发送失败恢复
    - 触发：网络中断且尚未保存
    - 期望：消息与可选邮箱只留在当前标签页内存，可重试并提供现有联系邮箱入口；刷新、关闭或崩溃后不承诺恢复草稿，也不写入 localStorage 或日志。
- [[E-76]]　人工聊天同步机制
    - 触发：聊天/收件箱可见且请求成功
    - 期望：以 3 秒为正常间隔；标签页隐藏时暂停，恢复可见立即从已确认 seq 补齐；慢网或连续失败采用有界退避，间隔最多 30 秒，任一轮不能叠加无限在途请求。
- [[E-77]]　人工聊天同步机制
    - 触发：多个标签页、重试、响应乱序或跨分页期间又插入新消息
    - 期望：以服务端稳定 seq 和消息标识合并去重，游标只推进到已完整接收的范围；后返回的旧响应不能倒退游标、覆盖新回复或把漏页消息跳过。
- [[E-78]]　人工聊天同步机制
    - 触发：访客会话到期/撤销，或运营角色从 ADMIN/SALES 变为无聊天权限
    - 期望：下一次轮询和发送均做服务端鉴权并停止返回会话内容；修改 threadId、seq 或邮箱不能读取其他咨询。
- [[E-85]]　聊天凭据及数据保留期限
    - 触发：cookie 闲置达到 7 天、签发达到 30 天绝对上限或被撤销
    - 期望：服务端拒绝该凭据访问旧会话，浏览器可建立新咨询；仅填写相同邮箱不能找回旧会话，cookie 与其前端副本均不存 PII。

## 实施沉淀

<!-- notes:begin -->
- 轮询与分页合并：抽离无 React 依赖的 `createChatPoller`（支持 `audience: 'visitor' | 'admin'`）管理 3s 正常轮询、`visibilityState` 隐藏停轮询与恢复可见立即补页、`AbortController` 与 generation 单在途队列。分页响应经 `mergeChatMessages` 按 `id` 与稳定 `seq` 双重去重，连续游标在第一个缺号前停止，过期或小游标响应不倒退游标。
- 可见已读与历史阅读保位：在 `.pj-chat-body` 滚动或消息更新后，经 `requestAnimationFrame` 调用 `selectMaxVisibleContiguousSeq` 仅计算视口底部之上的连续完整可见序号，避免用户在顶部读历史时把底部未看消息标为已读；上翻时新消息到达不改 `scrollTop` 与输入框焦点，仅显示 `#chat-new-messages`。
- 草稿和重试载荷均保存在组件内存中。待确认时，编辑器只读，重试复用原正文、邮箱与客户端标识。当前组件在处理失败时读取浏览器在线状态。此时离线且没有 HTTP 状态码的首次失败会回到可编辑草稿，即便服务端已保存消息。
- 访客凭据失效、运营权限撤销、咨询关闭或匿名化后，客户端停止旧会话的定时器并取消在途请求，保留当前草稿。用户可主动开始新咨询。`/admin/chat` 的收件箱页面及其密度验收归 [[M4-T6]]。
