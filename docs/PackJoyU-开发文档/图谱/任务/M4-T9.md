## 必须处理的边界

- [[E-18]]　在线聊天实现路线
    - 触发：同一消息因重试重复提交
    - 期望：按客户端消息标识去重，收件箱只出现一条，不重复触发通知。
- [[E-37]]　C-02 离线留言与发送失败恢复
    - 触发：提交超时或响应丢失、实际保存状态未知
    - 期望：显示待确认或可重试，以原客户端消息标识重试并返回原收件结果，收件箱与通知不产生重复项。
- [[E-38]]　C-02 离线留言与发送失败恢复
    - 触发：网络中断且尚未保存
    - 期望：消息与可选邮箱只留在当前标签页内存，可重试并提供现有联系邮箱入口；刷新、关闭或崩溃后不承诺恢复草稿，也不写入 localStorage 或日志。
- [[E-76]]　人工聊天同步机制
    - 触发：聊天/收件箱可见且请求成功
    - 期望：以 3 秒为正常间隔；标签页隐藏时暂停，恢复可见立即从已确认 seq 补齐；慢网或连续失败采用有界退避，间隔最多 30 秒，任一轮不能叠加无限在途请求。
- [[E-77]]　人工聊天同步机制
    - 触发：多个标签页、重试、响应乱序或跨分页期间又插入新消息
    - 期望：以服务端稳定 seq 和消息标识合并去重，游标只推进到已完整接收的范围；后返回的旧响应不能倒退游标、覆盖新回复或把漏页消息跳过。
- [[E-78]]　人工聊天同步机制
    - 触发：访客会话到期/撤销，或运营角色从 ADMIN/SALES 变为无聊天权限
    - 期望：下一次轮询和发送均做服务端鉴权并停止返回会话内容；修改 threadId、seq 或邮箱不能读取其他咨询。
- [[E-85]]　聊天凭据及数据保留期限
    - 触发：cookie 闲置达到 7 天、签发达到 30 天绝对上限或被撤销
    - 期望：服务端拒绝该凭据访问旧会话，浏览器可建立新咨询；仅填写相同邮箱不能找回旧会话，cookie 与其前端副本均不存 PII。

## 实施沉淀

<!-- notes:begin -->
- 轮询与分页合并：抽离无 React 依赖的 `createChatPoller`（支持 `audience: 'visitor' | 'admin'`）管理 3s 正常轮询、`visibilityState` 隐藏停表并立即中止在途请求（`fetchChatConversationUpdates` 在每页拉取前后校验 `signal.aborted` 阻止多页续拉）、恢复可见立即从已确认连续 `seq` 补页，以及 `AbortController` 与 generation 单在途队列。分页响应经 `mergeChatMessages` 按 `id` 与稳定 `seq` 双重去重，连续游标在第一个缺号前停止，过期或小游标响应不倒退游标。
- 可见已读、失败补报与历史阅读保位：在 `.pj-chat-body` 滚动或消息更新后，经 `requestAnimationFrame` 调用 `selectMaxVisibleContiguousSeq` 与 `resolveReadAckTargetSeq` 仅计算视口底部之上的连续完整可见序号；若 `POST /read` 因断网耗尽重试失败，`pendingReadTargetRef` 保留该已读目标并在后续成功轮询（即使无新消息）或恢复可见时自动补报；上翻时新消息到达不改 `scrollTop` 与输入框焦点，仅显示 `#chat-new-messages`。
- 草稿与幂等重试状态机：草稿和重试载荷均保存在组件内存中，不写入 Web Storage 或 cookie。仅发送前已处于离线且未发起过网络请求（`attempts === 0`）的草稿才保持可编辑并展示既有邮箱入口；一旦在线发起请求，无论遭遇响应截断还是在途断网导致无 HTTP 状态码，均冻结原 `clientMessageId`/正文/邮箱进入待确认只读态，待点击重试复用原载荷返回原回执。
- 失权停止与门禁补丁：访客凭据失效、运营权限撤销、咨询关闭或匿名化后，客户端停止旧会话定时器、中止在途请求并保留当前草稿供主动开启新咨询；`/admin/chat` 页面与密度验收归 [[M4-T6]]。通过范围补丁 `m4-t9-ci-support`、`m4-t9-a3-regression` 与 `m4-t9-analytics-e2e-race` 纳入 `.github/workflows/ci.yml`、`tests/stats-route.test.ts` 的 A3 分区同步门禁及 `e2e/chat-start-analytics.spec.ts` 的分析事件落库轮询同步。
