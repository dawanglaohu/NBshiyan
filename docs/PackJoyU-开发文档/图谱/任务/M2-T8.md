# M2-T8　贯通产品咨询与人工收件回复

- 所属模块：[[M2]]　产品与 3D：负责产品列表、卡片和详情中的产品表达、直接模型操控、输入冲突处理、触屏与键盘查看、图片回退及带产品上下文的询盘入口。
- 前置依赖：[[M2-T5]]、[[M2-T7]]、[[M4-T5]]、[[M4-T6]]、[[M4-T9]]、[[M4-T14]]
- 完成后解锁：[[M7-T1]]

## 输入 / 产出

- **输入**：product-inquiry、chat-visitor-ui、chat-operator-ui与model-events
- **产出**：product-contact；带产品上下文的访客/运营人工咨询链

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 产品卡chat-product打开窗口，POST /api/chat/conversations保存同一productSlug/持久且不变消息编号后才显示已接收
运营真实收件箱可读该消息并人工回复，访客收到同一回复
网络中无AI答复接口或自动生成答复（[[E-16]]、[[E-31]]）。2) 拒绝分析仍可咨询且不建分析ID/第三方聊天脚本
提交超时/响应丢失后同clientMessageId重试返回原收件结果，收件箱/通知各一项
当前标签草稿保留，en/ru/390路径有真实GIF（[[E-37]]、[[E-40]]）。

## 必须处理的边界

- [[E-16]]　在线聊天实现路线
    - 触发：访客首次发消息且运营在线
    - 期望：持久化会话和消息后给出已接收状态，运营收件箱可读取并人工回复，不生成 AI 自动答复。
- [[E-31]]　C-01 人工聊天收件与回复入口
    - 触发：访客提交消息且服务端持久化成功
    - 期望：返回稳定的会话与消息标识并显示“已接收”，运营收件箱能读取；数据库写入失败则保留待重试，不显示已接收或客服已读。
- [[E-37]]　C-02 离线留言与发送失败恢复
    - 触发：提交超时或响应丢失、实际保存状态未知
    - 期望：显示待确认或可重试，以原客户端消息标识重试并返回原收件结果，收件箱与通知不产生重复项。
- [[E-40]]　C-02 离线留言与发送失败恢复
    - 触发：访客拒绝分析但主动打开第一方人工聊天
    - 期望：允许完成必要咨询，不创建分析标识或加载第三方聊天脚本，聊天必要会话与分析同意分开处理。
