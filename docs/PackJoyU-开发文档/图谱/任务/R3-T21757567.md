## 实施沉淀

<!-- notes:begin -->
SANITY_IMPORT_PYTHON 一旦出现就只启动这一个可执行文件，空字符串也算已设置。探测失败后再改试 python 或 py，错误配置会变成通过。这个值是路径或命令名，不是 shell 命令行。`py -3` 只在变量未设置时作为 Windows 候选。

Windows 上名为 python3 的命令可以是 WindowsApps 别名，退出码 9009，标准输出和标准错误都为空。别名只由这次探测的退出码确认：正好是 9009 才运行真实别名断言。退出 0 是可用解释器，按该命令执行。命令缺失时没有退出码，启动失败带 spawn 错误，说明里保留 stderr，不写成 exit 9009。其他非 9009 的退出码也不按别名断言。这三种结果都不失败该用例。9009 必须在内容断言之前失败。只判断 status 非 0 的占位、食品声称或内链拒绝，会把这个别名当成脚本拒绝成功。

POSIX 的 wait 状态只有 8 位，所以 Linux 上看不到退出码 9009。这条规则对照 Windows 上 spawnSync 上报的 9009，不能改成把 49 当成别名失败。

子进程固定 PYTHONUTF8=1。区域编码不是 UTF-8 时，build.py 和 linkmap.py 的默认文本写会按本地代码页重写已提交的 UTF-8 文件，字节比较失败。不要把这两个脚本的 write_text 改成固定 LF。已提交 blob 是 LF，autocrlf 检出是 CRLF，文本模式写出的换行与当前检出一致；固定 LF 会使 Windows 上的逐字节比较失败。

内链用例去掉 `import: false` 时必须允许这一行以 CR 结尾。只匹配 LF 时，CRLF 检出仍留着该标志，linkmap 不生成链接，恢复后的链接数是 0 而不是 3。

同一次选定的解释器可以反复启动。通过结果不能缓存，否则占位和食品声称不再真正执行。

运行时 Next 与配套 env/SWC 使用同一 15.5.28 补丁版本。现有声明 `~15.5.27` 已允许该版本，锁文件更新不需要扩大声明范围；冻结安装继续检查二者一致性。依赖安全修复须保持审计与构建检查有效。

导入脚本使用 Python 3.8 的赋值表达式语法。自动候选探测必须拒绝更早版本后继续后续候选，避免 PATH 前面的 Python 3.7 遮住可用的 `py -3`。显式 `SANITY_IMPORT_PYTHON` 仍只使用指定解释器，失败不回退。
