# M3-T11　接通独立恢复及受限重绑向导

- 所属模块：[[M3]]　后台访问与账号：负责统一后台登录页和后台公共外壳、个人设置、设备会话、验证器绑定与登录方式切换、会话撤销及独立受限恢复，并负责既有后台页面的共享视觉迁移/回归；不改其询盘/邮件/规格/模型业务，消费 M1 的唯一视觉 token。
- 前置依赖：[[M3-T6]]、[[M3-T5]]、[[M3-T18]]、[[M3-T20]]
- 完成后解锁：[[M3-T12]]、[[M7-T2]]、[[M7-T5]]

## 输入 / 产出

- **输入**：真实start/enroll/confirm、OS-ownerCLI和SELF_REAUTH；M3-T6登录表单。
- **产出**：/admin-recovery安全root layout、RecoveryWizard、recovery客户端、登录恢复入口。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 入口：/admin-login的Cannot use your authenticator（login-recovery）→/admin-recovery
数据源POST /api/auth-admin/recovery/start/enroll/confirm
用隔离恢复码或OS permit实发start，持restricted cookie继续原pending，不能GET admin
中断重入URI/期限不变，过期提示新授权且旧有效因素未提前删（[[E-10]]、[[E-11]]、[[E-14]]）。2) 点recovery-confirm真实新TOTP仅一次提交并展示新恢复码，下一时间步回login真实登录
旧设备/旧因素拒绝，响应未知不自动confirm/取回旧码
无材料说明OS-owner而网页不签权限
body无密码/hash字段、秘密仅内存清理（[[E-12]]、[[E-15]]）。 按11节唯一minimalist-flat，在实际服务1920×1080、1440×900、390×844记录GIF与computed style：2px黑边、0圆角、无阴影、强调色#b45700
后台逐页以work/form/card、density7/gutter16/gap16/pad16运行D1–D6和overflow探针。label与键盘焦点可达，触屏控件点击框至少44px。
3) 逐步页面/网络断言复用前置恢复API测试：点击login-recovery后URL.pathname=/admin-recovery
日常登录表单无recoveryCode必填项。点击recovery-start时仅POST /api/auth-admin/recovery/start，body含email/credentialKind/credential，响应200且restricted=true/expiresAt存在，页面显示受限到期值
随后POST /api/auth-admin/recovery/enroll body={}为200，页面显示返回URI。保存restricted cookie后仅带它GET /api/admin/account=401且正文无后台数据。刷新/返回后由Continue setup再次enroll，URI和expiresAt与上次相等
期限等号401/error=recovery_expired时，页面隐藏待绑定URI和确认输入，显示重新取得恢复授权入口。点击recovery-confirm仅POST /api/auth-admin/recovery/confirm body={totp}一次，200/completed=true时只在当次结果面板列recoveryCodes
返回login或pagehide后码不再出现在DOM、localStorage、sessionStorage。服务已提交但confirm响应被切断时，显示结果待确认文案，观察15秒无第二次confirm且无重新取码请求，Return to sign in按钮去/admin-login。选择无恢复材料仅显示联系服务器所有者说明，网络无permit签发请求
页面与confirm请求均无password/newPassword/passwordHash字段。

## 必须处理的边界

- [[E-10]]　C-04 验证器丢失与单管理员恢复
    - 触发：正常登录
    - 期望：不显示为必填恢复码，单独“无法使用验证器”进入恢复流程；仅填写账号或邮箱不能获得重置权限。
- [[E-11]]　C-04 验证器丢失与单管理员恢复
    - 触发：使用账号与有效一次性恢复码
    - 期望：原子核销恢复码并签发受限、短时重绑定凭据，只能绑定新验证器，正确验证新码前不能获得完整后台权限；同一恢复码并发使用仅一次成功。
- [[E-12]]　C-04 验证器丢失与单管理员恢复
    - 触发：验证器与全部恢复码同时丢失且没有第二管理员
    - 期望：仅允许具有服务器操作系统管理权限的所有者执行本地恢复命令，为明确目标账号生成一次性凭据，记录操作者、时间和目标，不把凭据明文写入审计日志。
- [[E-14]]　C-04 验证器丢失与单管理员恢复
    - 触发：恢复中断或重置凭据过期
    - 期望：明确 restricted 凭据访问受保护后台必须拒绝；中断或过期不提交待绑定新因素，原有效绑定保持；持有效 restricted cookie 可重入同一 enroll，失效则按10节已定义恢复码/授权路径重启，不能换取完整后台会话。
- [[E-15]]　C-04 验证器丢失与单管理员恢复
    - 触发：新验证器完成校验并提交恢复
    - 期望：撤销旧会话、旧绑定与旧恢复凭据，生成新的恢复码并明确展示一次，后续旧设备不能继续访问。
