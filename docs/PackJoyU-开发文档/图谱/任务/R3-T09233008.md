## 实施沉淀

<!-- notes:begin -->
生产路径和权限规则仍在 `prod-env-check.ts` 与 `src/lib/server/storage.ts`：POSIX 绝对且规范的 `UPLOAD_DIR`、`public/` 与 `.next/` 前缀、文件 0600、目录 0700、不跟随符号链接、`O_EXCL` 不覆盖。这三份测试不能删掉那六条安全用例，也不能把 0600 改成当前平台报出的 mode。

缺能力时用 `node:test` 的 skip，原因写明该分支未执行。断言前 `return` 会把用例记成通过，安全分支却没有跑。不要用 `process.platform === 'win32'` 代替探测。要看这次进程里 `path.resolve('/app')` 是否仍是 `/app`、`path.join` 是否得到 `/app/public`、临时目录是否 `path.posix.isAbsolute`、`symlinkSync(目标, 链接)` 不加 Windows type 是否成功、新建文件 `mode & 0o777` 是否为 `0o600`。探测和用例必须用同一种创建方式，否则探测通过而用例仍是 EPERM。

Windows 上 `path.resolve('/app')` 会带盘符，生产检查用的 `public/`、`.next/` 前缀对不上 `/app/public/uploads`。临时目录也不是 POSIX 绝对路径，真实目录、chmod 和 realpath 夹具走不到。词法拒绝、注入的不可写、ENOENT realpath 和 EEXIST 覆盖仍要每次都跑。Linux 上这些中性断言和原用例重复，两处都必须是 pass。

`chmod 0o500` 在 uid 0 下不能证明目录不可写。只读子测试此时 skip。Ubuntu 作业把「只读目录拒绝」缺失或 skip 当成失败。注入的「拒绝不可写目录」不依赖 chmod，各平台都要执行。

TAP 把标题里的 `#` 写成 `\#`。比对 `#323 local 驱动…` 之前必须还原，否则这条通过的用例会被当成缺失。父用例 ok 不能代替被 skip 的子测试。名单里每个名字的每一次出现都要是 pass；出现任何 `not ok` 作业失败。上传测试记录失败不得把作业改成成功，记录正文已经打在作业日志里。

在 Windows 的 `node_modules` 上用 WSL 跑 `storage-local.test.ts`，用例结束后会因 Prisma 引擎不匹配产生文件级失败。那是引擎目录不对，不是符号链接用例失败。Ubuntu 作业自己 `pnpm install`，会生成当前平台的引擎。不要为了本机混跑去改 `binaryTargets`。
