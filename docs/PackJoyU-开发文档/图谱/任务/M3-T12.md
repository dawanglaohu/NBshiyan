# M3-T12　接通个人安全页与共享新鲜验证对话框

- 所属模块：[[M3]]　后台访问与账号：负责统一后台登录页和后台公共外壳、个人设置、设备会话、验证器绑定与登录方式切换、会话撤销及独立受限恢复，并负责既有后台页面的共享视觉迁移/回归；不改其询盘/邮件/规格/模型业务，消费 M1 的唯一视觉 token。
- 前置依赖：[[M3-T7]]、[[M3-T16]]、[[M3-T20]]、[[M3-T11]]
- 完成后解锁：[[M3-T8]]、[[M3-T9]]、[[M3-T13]]、[[M7-T6]]

## 输入 / 产出

- **输入**：M3后端敏感写、M3-T7壳、M3-T11受限页；client-api-foundation。
- **产出**：/admin/account、AccountContainer/ReauthDialog及各域account客户端；个人模式/密码/重绑控制。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 入口：后台Personal information（admin-account-link）→/admin/account
数据源GET /api/admin/account
login-mode-toggle先POST reauth(LOGIN_MODE)再PATCH login-mode，随后下一码真实totp登录不填密码
拒绝移除所有方式且409后显示旧值（[[E-06]]、[[E-07]]、[[E-09]]）。2) change-password以PASSWORD grant POST password
change-authenticator以TOTP_RESET grant POST 2fa/reset→Continue setup可见控件进入/admin-recovery
每次点击断言真实purpose/target/body与持久结果
同一步码已用提示等待下一码，grant5min/用途不符不提交（[[E-72]]、[[E-73]]、[[E-74]]）。3) 忘现密码但仍totp登录可工作，敏感按钮不给session-only/TOTP-only替代
恢复只走独立受限页，普通验证密码/TOTP结束清空，grant仅内存且未知响应不重放（[[E-75]]）。 按11节唯一minimalist-flat，在实际服务1920×1080、1440×900、390×844记录GIF与computed style：2px黑边、0圆角、无阴影、强调色#b45700
后台逐页以work/form/card、density7/gutter16/gap16/pad16运行D1–D6和overflow探针。label与键盘焦点可达，触屏控件点击框至少44px。
4) 本卡只新增页面请求与显示断言，复用T3/T16/T20已经通过的事务用例：进入/admin/account时GET /api/admin/account为200，开关checked与passwordlessEnabled相等。点login-mode-toggle后ReauthDialog有现密码/6位totp字段，提交POST /api/admin/account/reauth body的purpose=LOGIN_MODE
200返回token/purpose/expiresAt后才PATCH /api/admin/account/login-mode body={passwordlessEnabled,actionGrant:token}，200返回的新Boolean与提交值相同、changedAt为时间，旧会话下一GET account=401并显示/admin-login
409时开关恢复GET到的旧值并显示错误，不能显示保存成功。change-password发purpose=PASSWORD，POST /api/admin/account/password body含newPassword/actionGrant，200响应ok=true且reauthRequired=true后回登录
change-authenticator发purpose=TOTP_RESET，POST /api/admin/account/2fa/reset带actionGrant，200响应reenrollRequired=true及enrollLink后显示Continue setup，点击其pathname=/admin-recovery。reauth失败401不返回token，当前dialog显示错误且无后续敏感写
重复时间步提示等待下一验证码。grant过期或错用途时目标写为401/error=action_grant_invalid，设置GET前后相同、弹窗要求重新本人验证。忘现密码时只提交session或totp的reauth为401且无token，仍可用原totp模式登录
页面不会代发缺password的reauth或把恢复码加回日常表单。关闭dialog/pagehide后密码、totp、grant不在输入值或浏览器持久存储
未知写响应后15秒无自动重复POST/PATCH，只允许GET当前设置核实。

## 必须处理的边界

- [[E-06]]　C-03 验证器绑定与无密码默认开关
    - 触发：已绑定账号本人通过新鲜验证启用开关
    - 期望：日常登录仅要求邮箱或账号与验证器码，恢复码作为独立恢复入口，密码不再是此模式的必填项。
- [[E-07]]　C-03 验证器绑定与无密码默认开关
    - 触发：关闭无密码开关或解绑验证器会使账号失去所有可用登录方式
    - 期望：拒绝该次变更，先完成可用密码或替代方式的设置与验证，再原子提交切换。
- [[E-09]]　C-03 验证器绑定与无密码默认开关
    - 触发：界面沿用用户称呼“2FA”
    - 期望：说明当前无密码模式是“账号 + 验证器码”；账号标识不是独立因素，不宣称其具备两个独立因素的安全等级。
- [[E-72]]　敏感设置的新鲜本人验证
    - 触发：同一 TOTP 时间步已被登录、其他敏感操作或并发请求消费
    - 期望：原子消费账号的验证器时间步，后来的请求不能再次发放 ActionGrant；客户端可等待下一验证码重试，不把恢复码重新加入日常登录。
- [[E-73]]　敏感设置的新鲜本人验证
    - 触发：两次请求并发使用同一 ActionGrant，或把改密码授权用于关闭验证器
    - 期望：在敏感变更事务内按动作、设备、账号及凭证版本校验并一次性消费授权，只有一个匹配请求成功，目的不符请求拒绝且不能执行变更。
- [[E-74]]　敏感设置的新鲜本人验证
    - 触发：授权签发后超过 5 分钟、设备撤销、密码/验证器变更或账号权限失效
    - 期望：旧授权立即无效；授权的新鲜验证不得跨设备移用，也不能延长原设备会话期限。
- [[E-75]]　敏感设置的新鲜本人验证
    - 触发：用户忘记现密码但仍能使用启用后的无密码登录
    - 期望：把“D3”指向09/10节已定义受限恢复路径和一次性 permit/restricted cookie；普通无密码登录不改，敏感设置缺当前密码时不得签发普通 ActionGrant，仅凭已登录会话或一枚TOTP的直接请求拒绝并无变更，受限恢复只可新绑定且审计。
