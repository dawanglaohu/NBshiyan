- 所属模块：[[M2]]　产品与 3D：负责产品列表、卡片和详情中的产品表达、直接模型操控、输入冲突处理、触屏与键盘查看、图片回退及带产品上下文的询盘入口。

- **输入**：model-event-rules、model-fallback、analytics-ingest与analytics-consent-ui
- **产出**：model-events；页面/产品访问与真实GLB start/terminal生产者接线

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 真浏览器产品卡发起GLB后POST /api/analytics/events分别保存产品访问、model_view_start及成功/失败
仅进入产品路由且没有真实GLB加载尝试时无start
可视区自动加载或主动操作确实发起GLB时均产生start，不要求额外激活点击
未同意/拒绝分析时模型仍可用且无分析请求（[[E-42]]、[[E-46]]）。2) 分别注入GLB下载失败/WebGL不支持/context lost/poster或FoldBox，仅对应产品静态回退、重试及询盘可用
poster/演示无GLB success
同viewId最多一种终态，新实际重试按规则新viewId（[[E-103]]）。3) 成功/失败/超时两次尝试与切卡取消逐项核关联及真实durationMs，分母仅同意后真实start、timeout为failure、平均耗时带samples且无样本null，不补拒绝样本（[[E-63]]）。

## 必须处理的边界

- [[E-103]]　真实模型失败与统计
    - 触发：GLB下载失败、WebGL不支持、context lost或只能展示海报/FoldBox演示
    - 期望：分别注入GLB下载失败、不支持WebGL、context lost、仅poster/FoldBox，检查对应产品静态回退、重试和询盘；同viewId最多一个终态，poster/程序演示均不发GLB success。真实模型重试若新建尝试按既定viewId规则处理。
- [[E-42]]　C-05 分析采集、去重与保留期
    - 触发：用户尚未允许或拒绝分析
    - 期望：不生成或保存分析标识、不发分析事件，网站与 3D 功能仍可用；看板明确只覆盖授权浏览器，不将缺失授权样本补成全站人数。
- [[E-46]]　C-05 分析采集、去重与保留期
    - 触发：仅进入产品路由、可视区或主动操作实际发起GLB加载，或加载失败
    - 期望：产品页访问与真实模型加载发起分别记录：仅路由访问但尚无加载尝试不发start，可视区自动加载或主动操作确实发起GLB就按viewId发start，不要求额外激活点击；成功/失败按实际终态并绑定服务端认可产品标识，失败和poster/FoldBox不算GLB成功。
- [[E-63]]　运维指标扩展及角色权限
    - 触发：3D 加载有成功、失败、超时或没有样本
    - 期望：引用09节既定口径：分母为获同意后真实 model_view_start；同 viewId 最多一个 success/failure 终态，超时记 failure；终态 durationMs 的有效样本算平均耗时并带 samples，无样本为 null，零成功且有样本才为0%，拒绝分析样本不补分母。

## 实施沉淀

<!-- notes:begin -->
- 复用而不是再造：事件构造全部走 M2-T4 的 `reduceModelEventSignals`，排队只调 M5-T7 已导出的 `enqueueAnalyticsEvents`（同一去重、microtask flush、403 停采），因此没有第二套 queue/flush/同意门控。
- start 与 success 的落点不同，是被 React Suspense 逼出来的：`useGLTF` 在渲染期挂起，`Gltf` 里的 effect 直到解析完才跑，不能用来报 start；start 放在 `ProductModel` 的载入 effect（`cachedModelUrl` 之前、真实 GLB 分支），success 放在 `Gltf` 挂载后的 effect。外层 Suspense 会让整棵子树重挂，所以 attempt 级去重放在生产者（按 slug+attempt），不能只靠组件 ref，否则一次真实加载会开出两个 viewId。
- 终态不从 `GalleryScene` 的 `onModelResult` 接入：那个回调在 FoldBox 和 poster 就绪时也会报 ready，直接当 GLB success 会违反 E-103。终态只由 `Gltf` 挂载成功或真实失败回调产生。
- product_view 只在首次真实 start 时补一条（Set 按 navigation+product 去重）：同导航重试若再发一条，payloadHash 会因 occurredAt 不同而触发 409，且产品视角只应记一次。
- 超时阈值取 30s：E-63 只要求“超时记 failure”，代码里原先没有模型级超时；选择在 `ProductGallery` 用现有失败条和重试呈现，生产者发 TIMEOUT 终态。超时后迟到成功的回调不会再写终态（view 已 decided），也不会把失败改成成功。
- 取消的边界：切到无 unfold 的刀模 FoldBox、页面卸载时只 cancel 开放尝试；不在 `ProductModel` 卸载时 cancel，因为 Suspense 重挂会误杀真实加载。WebGL 不可用时 `GalleryScene` 根本不挂载，场景级失败回调没有 open view，自然没有 start/terminal。
- 同页授权后不能补发 page_view（M5-T7 已定），但页面生产者必须静默建立当前页 navigation 上下文；否则模型生产者拿不到 navigationId，同意后同页的真实加载要等下一次导航才记（F1）。上下文用新 navigationId、当前 path/locale，不发 page_view/product_view。
- 同意前已见到的 attempt 要按**页面访问代次**记住：同一次访问内 Suspense/场景重挂的同一 attempt 继续抑制，同文档离开返回（attempt 归零）按新代次正常计入；代次由 `noteNavigation` 递增，只在内存里做生命周期标记，不发送、不持久化、不作分析身份；不能用集合超 500 整体清空来解除抑制（R1 跨访问残留的修法）。
- 进入新访问时清掉旧 `open`/`lastViewId`：旧访问的迟到回调不会 settle 新访问的尝试；离开时 `ProductGallery` 卸载仍 cancel 未决尝试，不补终态。
- context lost 是场景级失败，`WEBGL_UNAVAILABLE` 已能表达：场景失败时立即结算未决尝试并清计时器；只等 30s 的 TIMEOUT 会晚 30s 才落库，还会把可见失败原因改成 TIMEOUT（E-103）。
- 同页接受/拒绝的回归不能假设鼠标移动一定新开一次加载：横幅/对话框点击与焦点回位滚动都可能已经触发过 3D 懒加载；要滚到同意前未加载的卡片，或用重试把 attempt 加一，才能证明“同意后的新真实尝试”。
- 30s 超时阈值与目录卡片 product_view 语义已由 Jev 裁决（`M2-T7:R1:timeout`、`M2-T7:R1:catalog-product-view-v2`，model `jev-1.14.0`）：30s 保留；目录卡片在首次真实 start 记一条 product_view（每 navigation+product 一条）。
- 本机限制（非产品代码）：Windows `next build` 的 standalone 复制会在符号链接处 EPERM，本地 e2e 用仓库外临时 config + `next start -p 3230`（同一 `.next` 生产构建）跑同一 spec；CI 仍用仓库 playwright 配置。`next start` 另需根 `node_modules/@swc/helpers`、`tslib` junction（SWC DLL 回退），均为本机安装层，不入仓库。
