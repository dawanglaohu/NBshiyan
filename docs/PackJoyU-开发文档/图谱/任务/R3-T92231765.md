## 实施沉淀

<!-- notes:begin -->
`core.autocrlf=true` 把库里的 LF blob 检出成 CRLF。源码断言里的 `\n` 针、用 `$` 去掉的行注释，以及 Bash `source`，都会因此失败。比较语句、守卫和样式时先把 `\r\n` 和单独的 `\r` 收成 `\n`。断言正文保持不变。

不要给整个仓库写 `* text eol=lf`。内容导入按当前检出的换行做逐字节比较；全局 LF 会让 Windows 上 Python 文本模式写出的 CRLF 对不上。`.gitattributes` 只把 `*.sh` 固定为 LF。这个属性管新检出。工作区里已经是 CRLF 的脚本，要重新 checkout 才会变成 LF。测试仍把脚本收成 LF，不能假设属性已经生效。

Bash 读到 CRLF 脚本会以 `$'\r'` 语法错误退出。`loc_bad` 不能把这个非零退出当成 Location 安全，否则 `//evil.com/` 会被放行。

WSL 的 bash 不把 `C:\...` 当文件路径，`plan_problems` 会把这种路径看成空计划。夹具放在仓库内的相对路径，分隔符用 `/`，调用结束就删掉。Git Bash 也能读这种路径。

`plan_problems` 自己会把 CR 换成空格，所以同一份 SQL 的 LF 与 CRLF 结论相同。空文件必须报 empty/unreadable，DROP 必须报出来。不要为了让字符串相等去改 SQL 文件，也不要删 review-only 注释。

`admin-enroll-p1` 的恢复码 `.txt` 规定就是 CRLF。归一化只包住源码读取，不要包住 `recoveryTxt` 的返回值。
