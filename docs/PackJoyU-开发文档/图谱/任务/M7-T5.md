# M7-T5　终验受限恢复与单管理员兜底

- 所属模块：[[M7]]　集成验收与交付：负责访客跨模块完整路径、后台权限与恢复路径、统计和可靠性完整链路的真实集成验收及交付证据收口；核对本轮复用的恢复来源，不重做 S1 已完成的取回和来源审计，也不自动合并恢复草稿。
- 前置依赖：[[M7-T6]]、[[M3-T9]]、[[M3-T11]]、[[M3-T18]]、[[M3-T20]]
- 完成后解锁：[[M7-T8]]

## 输入 / 产出

- **输入**：已交付恢复向导/OS-owner CLI、一次性码和受限cookie协议
- **产出**：admin-acceptance；恢复并发、不可越权及本地兜底证据

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 从独立恢复入口POST /api/auth-admin/recovery/start→enroll→confirm
同码、不同码并发核销不复活已用码，restricted cookie不能访问后台
中断/过期保留旧有效因素，重入返回同URI/期限，新确认才替换因素且必须普通登录（[[E-10]]、[[E-11]]、[[E-14]]）。2) 无第二管理员且恢复码丢失时，隔离服务器OS-owner实际TTY CLI明确target/reason生成permit，隐藏密码预授权只在新TOTP最终确认提交且审计
旧首次绑定reset脚本guard不放宽，匿名浏览器不能签permit/改密码
最终confirm撤销旧会话/旧绑定/旧恢复材料、新恢复码仅展示一次，旧设备下一请求被拒（[[E-15]]）。

## 必须处理的边界

- [[E-10]]　C-04 验证器丢失与单管理员恢复
    - 触发：正常登录
    - 期望：不显示为必填恢复码，单独“无法使用验证器”进入恢复流程；仅填写账号或邮箱不能获得重置权限。
- [[E-11]]　C-04 验证器丢失与单管理员恢复
    - 触发：使用账号与有效一次性恢复码
    - 期望：原子核销恢复码并签发受限、短时重绑定凭据，只能绑定新验证器，正确验证新码前不能获得完整后台权限；同一恢复码并发使用仅一次成功。
- [[E-14]]　C-04 验证器丢失与单管理员恢复
    - 触发：恢复中断或重置凭据过期
    - 期望：明确 restricted 凭据访问受保护后台必须拒绝；中断或过期不提交待绑定新因素，原有效绑定保持；持有效 restricted cookie 可重入同一 enroll，失效则按10节已定义恢复码/授权路径重启，不能换取完整后台会话。
- [[E-15]]　C-04 验证器丢失与单管理员恢复
    - 触发：新验证器完成校验并提交恢复
    - 期望：撤销旧会话、旧绑定与旧恢复凭据，生成新的恢复码并明确展示一次，后续旧设备不能继续访问。
