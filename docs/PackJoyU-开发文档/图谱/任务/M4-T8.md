## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 调用方/接线点：真实POST /api/chat/session→visitor-session
主动联系才创建随机256bit token/hash库记录，Secure/HttpOnly/SameSite=Lax/Path=/api/chat、无Domain/PII
缺/拒分析不阻止，GET普通网页不签聊天cookie（[[E-40]]）。2) 7d闲置/首次30d绝对、等号/撤销即拒，先验有效再touch
有效cookie可复用，无cookie结果未知不自动循环创建，相同email不恢复旧session
精确Origin和10次/10min cookie、20次/10min IP-HMAC限流生效（[[E-85]]）。

## 实施沉淀

<!-- notes:begin -->
Path 必须保持 `/api/chat`。改成 `/` 才能用 `__Host-`，但那样这张 cookie 会跟着所有请求走。

等号拒绝。更新语句用 `>`。服务先看行，条件更新后再看返回行。少了第二次判断，并发下已经到期的行仍可能被写成新的 lastActivityAt。

失效凭据该请求只清除。同一次请求里接着插入，会把拒绝旧会话做成静默换新会话，调用方分不清自己还在不在原来的咨询上。下一次没有这张 cookie 的 POST 才新建。一次请求只插入一行。响应如果没到浏览器，库里会留下一行空会话。邮箱不是找回它的键。

限流键只接受恰好一张、43 字符的 token，再做 HMAC。多张或畸形既不进 cookie 桶，也不当成未登录去签发。cookie 桶已经拒绝时不要再扣 IP 桶，否则同一出口的新咨询会被坏 cookie 提前打满。

回写的 Max-Age 到不了 absoluteExpiresAt 之后。闲置续期不能把绝对期限往后推。

这张 cookie 与 pj_analytics 无关。缺分析 cookie，或带着分析 cookie，都不改变这次签发。页面 GET 不进这个路由。

不要把聊天令牌密钥加进生产必填名单。原值的库内形式是 SHA-256，限流键继续用现有的 rateLimitKeyHash。新增必填秘密会改变生产启动检查的缺项条数。

非生产省略 Secure 看的是请求 URL 的主机，不是调用方写的 Origin。预览域名仍然带 Secure。

限流前缀是 `chat:session:cookie:` 和 `chat:session:ip:`。不要复用分析同意或后台的前缀。
