# M3-T2　校验登录方式并原子核销当前验证器时间步

- 所属模块：[[M3]]　后台访问与账号：负责统一后台登录页和后台公共外壳、个人设置、设备会话、验证器绑定与登录方式切换、会话撤销及独立受限恢复；消费 M1 的视觉 token。
- 前置依赖：[[M3-T1]]、[[M1-T2]]
- 完成后解锁：[[M3-T3]]、[[M3-T5]]、[[M3-T6]]、[[M3-T7]]、[[M3-T10]]、[[M3-T16]]

## 输入 / 产出

- **输入**：M3-T1 的真实设备登录与当前权限链；现有 enroll/token/confirm 与 TOTP 工具；M1-T2 单一 LoginMode schema。
- **产出**：Credentials 的 password/totp 模式与恢复码拒绝；消费M3-T1已增加且默认false的User.passwordlessEnabled，不重复建字段；当前 secret/sv/step 的 TOTP CAS；POST /api/auth-admin/enroll、POST /api/auth-admin/enroll/confirm 的当前令牌/期限 CAS。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 调用方/接线点：真实 Auth.js Credentials→authorizeLogin
已启用账号的 totp 模式只校验账号+验证码，password 模式校验当前密码+验证码
未知mode、未开启totp、非空recoveryCode和未知账号都同一通用失败且无设备行（[[E-06]]、[[E-96]]）。2) 当前secret/sv/step原子核销，登录/并发请求同一步最多成功一次
重置交错时旧secret的码不能生效
保留6位前导零及既有限流（[[E-72]]、[[E-08]]）。3) 未绑定账号须既有一次性token完成首次绑定
真实 enroll/confirm 在最终事务复核 tokenhash/expiry/sv/pendingSecret，错误/过期/并发确认不提交，且未确认前 passwordlessEnabled 保持false（[[E-05]]、[[E-08]]）。

## 必须处理的边界

- [[E-05]]　C-03 验证器绑定与无密码默认开关
    - 触发：账号尚未绑定验证器
    - 期望：继续使用现有可用登录方式并进入绑定流程；只有正确验证新验证器后才能启用无密码默认登录，不批量强开。
- [[E-06]]　C-03 验证器绑定与无密码默认开关
    - 触发：已绑定账号本人通过新鲜验证启用开关
    - 期望：日常登录仅要求邮箱或账号与验证器码，恢复码作为独立恢复入口，密码不再是此模式的必填项。
- [[E-08]]　C-03 验证器绑定与无密码默认开关
    - 触发：绑定码错误、已过期、重复提交或并发切换
    - 期望：把四种触发分别测试，并在最终事务复核待绑定记录、有效期和当前凭证版本；错误/过期/重放不提交，两个并发切换最多一个成功，失败后查询仍存在至少一种已验证登录方式。沿09节规则，不另造登录方式。
- [[E-72]]　敏感设置的新鲜本人验证
    - 触发：同一 TOTP 时间步已被登录、其他敏感操作或并发请求消费
    - 期望：原子消费账号的验证器时间步，后来的请求不能再次发放 ActionGrant；客户端可等待下一验证码重试，不把恢复码重新加入日常登录。
- [[E-96]]　登录方式枚举与账号隐私
    - 触发：mode未知、totp模式未获账号本人启用或普通Credentials携非空recoveryCode
    - 期望：列明每种非法 mode、未由本人开启的totp、普通Credentials带非空recoveryCode都沿同一通用Auth.js失败结果，不签后台会话且响应不区分账号存在；合法password/totp只校验相应方式，并按既定限流/错误协议测试，保留有效用户登录。
