1) 调用方/接线点：真实 Auth.js Credentials→authorizeLogin

## 必须处理的边界

- [[E-05]]　C-03 验证器绑定与无密码默认开关
    - 触发：账号尚未绑定验证器
    - 期望：继续使用现有可用登录方式并进入绑定流程；只有正确验证新验证器后才能启用无密码默认登录，不批量强开。
- [[E-06]]　C-03 验证器绑定与无密码默认开关
    - 触发：已绑定账号本人通过新鲜验证启用开关
    - 期望：日常登录仅要求邮箱或账号与验证器码，恢复码作为独立恢复入口，密码不再是此模式的必填项。
- [[E-08]]　C-03 验证器绑定与无密码默认开关
    - 触发：绑定码错误、已过期、重复提交或并发切换
    - 期望：把四种触发分别测试，并在最终事务复核待绑定记录、有效期和当前凭证版本；错误/过期/重放不提交，两个并发切换最多一个成功，失败后查询仍存在至少一种已验证登录方式。沿09节规则，不另造登录方式。
- [[E-72]]　敏感设置的新鲜本人验证
    - 触发：同一 TOTP 时间步已被登录、其他敏感操作或并发请求消费
    - 期望：原子消费账号的验证器时间步，后来的请求不能再次发放 ActionGrant；客户端可等待下一验证码重试，不把恢复码重新加入日常登录。
- [[E-96]]　登录方式枚举与账号隐私
    - 触发：mode未知、totp模式未获账号本人启用或普通Credentials携非空recoveryCode
    - 期望：列明每种非法 mode、未由本人开启的totp、普通Credentials带非空recoveryCode都沿同一通用Auth.js失败结果，不签后台会话且响应不区分账号存在；合法password/totp只校验相应方式，并按既定限流/错误协议测试，保留有效用户登录。

## 实施沉淀

<!-- notes:begin -->
`User.passwordlessEnabled` 已经存在，默认 false。签发待确认密钥和确认绑定都不写这一列。在确认时把它设为 true，会在本人还没单独启用之前，把日常登录改成只验验证码。  时间步的 `updateMany` 必须同时等于这次验过的密文、`totpEnabled` 和 `sessionVersion`。只按账号 id 和上一次时间步更新时，重置若在校验之后换了密钥或递增了会话版本，内存里的旧码仍可能把新的 `totpLastStep` 写上去。  条件更新保持单条 `updateMany`，where 使用 `OR`，不用 `AND`，也不开事务。现有绑定测试的内存匹配认识 `OR`、相等和 `gt`，不认识 `AND`，多数替身也没有 `$transaction`。改成那两种写法，这些测试会在没有数据库时失败。  Auth.js 会把 `csrfToken`、`callbackUrl` 和空密码字符串一起交给 `authorize`。登录契约是 strict 的，密码至少 1 个字符。解析前要删掉这些传输字段，并把空字符串密码当成没有密码。否则 totp 模式无法省略密码，已有的密码登录也会被契约拒绝。  未知 mode 和非空 `recoveryCode` 在契约层就是 `CredentialsSignin`，与 `authorizeLogin` 返回 null 的跳转相同：`/api/auth/signin`，`error=CredentialsSignin`，`code=credentials`。账号没有打开 `passwordlessEnabled` 时，totp 模式调用 `fail(null)`，不增加 `failedLogins`，也不核销时间步。`checkSecondFactor` 仍接受恢复码，供重新验证使用；`authorizeLogin` 不把恢复码传进去。  `auth.login_success` 只保留一行，`target` 是 `user.id`。隐私测试按源码里这一行的数量计数，再写一行成功审计会让它失败。  确认路由里的令牌 where 字面量要留在 `src/app/api/auth-admin/enroll/confirm/route.ts`。`tests/admin-enroll-token-347.test.ts` 用这段原文锁定条件更新。`commitEnrollConfirmation` 在这个对象上再要求当前 `sessionVersion` 和 `totpPendingUntil`。删掉字面量，源码断言会失败，路由上的令牌条件也会消失。  日常登录的真实 Auth.js 覆盖在 `tests/admin-login-mode.db.test.ts`，通过生产 handler 提交 Credentials。没有新增 e2e 后台登录。main 上单 IP 登录总数保持 23/26。  `checkDelta` 和 `Math.floor(now / 30_000)` 使用同一次 `Date.now()`。otplib 的默认 epoch 是调用时现取的，所以这里用 `authenticator.clone({ epoch: now })`，不改共享实例上的 window。  两个数据库测试在没有专用地址时会在 describe 上跳过，TAP 汇总是 tests 0、skipped 0，原来的 `# skipped 0` 门禁看不见。PG17 步骤设 `M3T2_REQUIRE_DATABASE=true`，缺地址时文件直接抛错，再用每个文件的 `test:summary` 要求 pass > 0。单元测试 job 不设这个变量。
