## 实施沉淀

<!-- notes:begin -->
- **入口不复制产品数据**：卡片入口只带 `product=<slug>`；联系页从 `Products.names` / `Products.specs` 读同一份文案，避免 query 里传可变名称或规格造成漂移。入口文案复用 `Nav.quote`，页面外面向用户仍是既有“询盘/报价”语义。
- **优先级按入口来源而非本地状态**：`from=quote` 保持原 CART 清单流程；其余带 `product` 的入口只在该 slug 属于静态目录且翻译键存在时预选，并在首个 effect 标记 `entryPrefilled`，阻止陈旧 localStorage 清单覆盖。非法 `product` 保持默认，不静默换成别的产品。
- **服务器认可**：只收紧 `WIZARD`/`CART` 中无 `designId` 的条目；`designId` 条目仍先过既有 `liveDesignIds`，FORM/SAMPLE/CUSTOMIZER、请求体、错误码与限流均未改。目录读取失败不放行，避免目录故障时把未知 slug 当合法。静态 slug 集合在模块级构建，只有出现非静态条目时才查库。
- **测试与计数**：新增四条浏览器/接口用例覆盖 EN、RU 390、EN 390 与目录/designId/旧清单边界，真实起生产构建与专用 PG，提交后直接查 `Inquiry` 行；`.actions` 从两子元素变三，故同步更新既有 product-cards 计数与 A3 总数 220+2+1=223。
- **已知验证边界**：Windows 本地 `next build` 的 standalone 拷贝因 symlink EPERM 中止，本地 e2e 改用同一 `.next` 的 `next start`；CI 仍按 standalone 执行。全量 223 例只做过 `--list`，未在本地跑完整 A3。
