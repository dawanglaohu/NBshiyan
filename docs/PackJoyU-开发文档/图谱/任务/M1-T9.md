# M1-T9　制作公司区块独立图稿与可编辑源工程

- 所属模块：[[M1]]　品牌与公共体验：负责现用 PackJoyU 字标、己方可证公司内容、JPG/GIF 发布副本、首页媒体和前台公共页面，并作为全站前后台视觉 token 的唯一归属；不承担后台权限或后台外壳。
- 前置依赖：[[M1-T1]]、[[M1-T3]]
- 完成后解锁：[[M1-T5]]

## 输入 / 产出

- **输入**：参考PDF组织/产品主题、己方可证事实、现用PackJoyU字标与用户已授权GPT Dot远程软件制作 M1-T3已交付并核哈希的brand-logo-master；不得另画一套字标。
- **产出**：company-visual-assets；网站公司区块选定1–2幅独立重绘图稿、可编辑软件源工程、Web图/enru alt与尺寸、哈希及真实制作清单

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 实际交付1–2幅网站公司区块独立重绘图稿，每幅均有“参考PDF页码/主题→己方可证事实或不含企业硬事实的产品示意”对照。只借鉴组织和产品主题，原PDF/JPG/GIF/视频与现用logo原文件SHA-256保持不变
YUHAO认证/产能/规模及无己方依据的真实厂房、设备、证照不出现在图中，不要求重画25页整本（[[E-27]]、[[E-111]]）。2) 每幅必须同时存在docs/brand-content/source/内的可编辑软件源工程及public/brand/company/内的Web图。用对应软件实际打开每个工程，能选择并编辑至少一个独立图形或文字对象，保留对象/图层面板与一次可撤回编辑的记录，关闭时不覆盖已登记源件
只有平面截图不算可编辑工程。实际解码每幅Web图并测得正整数宽高。docs/brand-content/company-visuals.json每幅都含source.path/source.sha256、web.path/web.sha256/width/height、alt.en/alt.ru、参考主题/事实依据
逐文件计算的SHA-256须与manifest逐字相同，解码宽高须逐值相同，en/ru alt均为非空且对应实际画面（[[E-111]]）。3) manifest登记现用PackJoyU logo master文件路径与SHA-256，读取该实际文件计算值须逐字匹配
图稿使用同一master而非候选新标，制作记录列明引用/导入该master的对象。原logo不修改，成品与源工程均无旧品牌或候选标
不等待用户回看候选图（[[E-28]]、[[E-111]]）。4) 必须提供可核对的实际GPT Dot调用/软件操作记录：对应调用或会话标识、软件名称版本、打开工程与导出Web文件的记录，记录中的文件逐件对应manifest路径和SHA-256
最后重新打开源工程、解码Web图并复算全部哈希，全部通过才交company-visual-assets。Dot不可达、软件步骤未执行或任一图稿/源工程/Web图/必要记录缺失时，本任务保持未完成，不能仅交尚未执行状态、计划或截图就提交为已完成或落地（[[E-29]]、[[E-111]]）。5) 本卡完整交付的边界是已核验的素材集合与manifest，不输出页面完成声明
[[E-111]]的首页/about实际消费及浏览器证据由M1-T5集成验收，T9不得伪造页面证据。源工程和工具私有记录不进入public或生产镜像（[[E-111]]）。
