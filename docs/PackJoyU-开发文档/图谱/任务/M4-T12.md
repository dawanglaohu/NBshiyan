## 实施沉淀

<!-- notes:begin -->
### 怎么实现

- **注册而非重写**：既有 `mail-queue` 变成固定作业。`createMailQueueJob` 用同一 JobState 租约；旧 route 在 gate/Bearer 后调 `executeJobRequest`，GET/POST 共享租约与摘要；`deploy/cron.nbshiyan` 只加每分钟 POST，409 视为租约占用正常跳过。
- **预算与收尾**：budget deadline = HTTP 55s − 250ms = 54.75s；剩余 ≤1s 停止领取；终态写剩余 >750ms 走普通预算，否则走绝对窗口 `[54.75s, 56.75s)`，每轮 `closeUsed` 只允许一次（D 回退与终态写先到先用）；SMTP 晚于窗口返回则 `mail.close_skipped`，不写不计数。
- **attempt 与 CAS**：reserve 在同一事务里 increment 后读回 attempts/lockedUntil；终态是一条 `updateMany({id,status:'SENDING',attempts,redactedAt:null}, data)`，count=1 即已写；成功结果遇 stale 只追加一条 `FAILED+unknown_delivery+同attempt` 的条件 SQL 升级 SENT。失败 0 行不计数、不发配置告警、不延长保留期。
- **D 回退**：reserve 后、SMTP 前预算耗尽 → 同一收尾事务回 QUEUED + 原 deferredUntil，attempts/retryCount 保留、capDay/lockedUntil 清空；命中后立即 `break`，否则下一行会二次触发回退。
- **告警**：`sendAdminAlert` 返回 `'sent'|'skipped'|'failed'`，在同一 deadline 的入口、限流后、`sendMail` 前三处检查；队列在调用前再按 `deadlineAt − 500ms` 自查。`sendMail` true→sent、`mail_disabled`→skipped、抛错（含 `SMTP_CONFIG_*`）→failed，旧三参调用兼容。
- **交互路径**：直发/重试不传 budget/close；终态 0 行时按一次重读返回当前状态，已匿名化返回 409 `anonymized`，不套队列预算。

### B1 收尾分类（本轮返工）

- 仅按本次操作的结构化错误分类：`P2034` 或 `P2010`＋`meta.code ∈ {40001,40P01,57014,55P03}` → `close_rolled_back`；`P2028`、连接类、`PrismaClientUnknownRequestError`、未识别错误 → `close_unconfirmed`。
- 不再用 `!callbackDone` 或 `txStarted=false` 推断“已回滚/未发起事务”：已调用 `$transaction` 后、回调开始前也可能超时/断连；只有调用前的本地校验失败（如收尾窗不足）才是 `close_skipped`。日志 `stage=callback` 只表示尚未完成提交，不证明回调已开始。
- 无库回归 B1-1..B1-19 覆盖 terminal/D 回退 × callback/commit × 已知/未知 × 本地 skip/`$transaction` 前拒绝。

### P2-A 错误传播（本轮续接）

- `processMailQueue` 的 stale/due/recipient/dropped 四阶段非预算错误一律上抛并停止后续操作；预算分支保持原返回/break，不改成 503。
- `queue-job` 对非预算失败只尝试一次预算内失败登记：persisted/unpersisted 都传播原错误，由 `executeJobRequest` 映射 500 `job_failed`；budget 才走 timeout。失败登记未确认不宣称已写 FAILED、不重试。
- 失败摘要仍是 `EMPTY_COUNTS`，**不代表本轮没做过工作**；部分已确认终态可能未进入失败摘要。已提交早行/已发 SMTP 不撤回、不重发、不补计数；“下一分钟”指下一次正常调度按持久状态接管，不是自动重放本轮操作。
- 无库回归 P2-1..P2-8 覆盖四阶段停止、预算分支、失败登记成功/未确认、`createMailQueueJob→executeJobRequest→handler` 500、早行 SENT 保留。

### 踩坑

- **Prisma 的 `undefined` 会静默省略条件**：`attempts: undefined` 等于没有这个守卫。终态写必须显式整数校验，缺 token 直接 fail closed；内存夹具对 undefined 的方向与 Prisma 相反，不能拿它证明安全。
- **旧 route 单测靠内存 Prisma**：接线后 route 会真的 claim/complete，内存夹具必须补最小 JobState/租约 SQL 语义，否则旧用例变 500。
- **测试环境 SMTP 配置**：`MAIL_FROM` 的域不能等于/后缀 REPLY_DOMAIN，否则 `smtpConfig` 返回 `bad_from`，队列直接零计数。
- **收尾窗只一次**：D 回退与终态写共用同一个 `closeUsed`；回退后不 `break` 就会在同一轮用掉第二次收尾机会。
