# M4-T12　注册既有邮件队列真实POST调度

- 所属模块：[[M4]]　第一方人工咨询：负责访客必要会话、人工消息与离线留言、ADMIN/SALES 收件箱和回复、未读、失败草稿与幂等重试，并保存真实收件和通知结果。
- 前置依赖：[[M5-T1]]、[[M5-T8]]
- 完成后解锁：[[M7-T4]]

## 输入 / 产出

- **输入**：现有mail-queue handler/worker、mail gate、M5 JobState；不修改旧邮件状态协议。
- **产出**：既有POST /api/admin/cron/mail-queue每分钟cron与同源固定JobState摘要。

## 验收标准

> 逐条都要满足，这是验收时的唯一依据。

1) 调用方/接线点：deploy/cron.nbshiyan每分钟POST旧mail-queue→既有mail gate/Bearer→worker，重启后受控SMTP实际消费已提交邮件
原stale/sent/failed/deferred/dropped字段不改，不以GET预取触发（[[E-94]]）。2) GET/POST兼容入口共享租约/JobState摘要，HTTP超时不自动重放或换方法探测，SMTP结果未知保留旧unknown_delivery协议
无权限/未启用不发信，失败不冒SENT（[[E-35]]、[[E-41]]）。

## 必须处理的边界

- [[E-35]]　C-01 人工聊天收件与回复入口
    - 触发：邮件提醒失败或未接通
    - 期望：将“真实通知状态”落到已定义 queued/sending/sent/failed 或其现有 DTO 映射，保存消息后的通知失败只改变该通知状态，不改变消息 received 或 inbox 可处理状态；未接通不得显示已发送。
- [[E-41]]　C-02 离线留言与发送失败恢复
    - 触发：留言已保存但客服回信或通知发送失败
    - 期望：保留已接收结果及收件箱待处理状态，单独呈现真实发送失败，不假装已联系到访客。
- [[E-94]]　聊天通知持久队列
    - 触发：出箱/通知接口被无聊天权限角色调用，或 SMTP 适配器仅能发送既有询盘格式
    - 期望：分别验无权限调用拒绝、chat-notifications 使用独立受限适配器且不扩展旧 mail UI；deploy/cron.nbshiyan 确有每分钟注册，重启后实际消费已提交出箱，不能只有手工调用或未来空注册。M4随交付注册，M7仅最终验收。
