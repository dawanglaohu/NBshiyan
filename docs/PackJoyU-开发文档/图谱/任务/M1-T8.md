## 实施沉淀

<!-- notes:begin -->
业务模块从 `requestApi` 取请求，从 `adaptApiError` 取错误文案。不要在组件里另写 fetch，也不要改 Auth.js 的 CSRF、signIn 和 signOut。

15 秒是每一次尝试的截止（Timeout，https://vibe-hub.org/timeout），不是 1/2/4 秒退避的总预算。同一次挂起只取消当前套接字。用一个计时器罩住全部重试时，第三次发送会在退避途中被取消。

普通安全 GET 不在客户端里循环。第 10 节允许它沿既有读取方式重试，而现有后台读取是调用方自己再发一次。网络失败、408、429 和 5xx 把 `retryable` 设为 true。`GET /api/admin/cron/mail-queue` 会触发发信，`retryable` 必须保持 false。

自动重放只给三类 POST：聊天消息（含创建会话时的第一条）、聊天 read、分析事件。最多 3 次重试，一共 4 次发送，字节始终是循环外的那一份字符串。在循环里重新 `JSON.stringify`，或另造 `clientMessageId`、`eventId`，服务端会看成另一份载荷。

`boundedRetry: true` 只给 `POST /api/analytics/consent` 和 `POST /api/auth-admin/recovery/enroll` 增加一次零延迟重放。reauth、recovery 的 start 与 confirm、activity、cron 和 chat session 忽略这个标志。这些路径遇到 503 时，动作要从 retry 改成 stop，否则调用方会重发尚未确认的授权。

自动等待取退避和 `Retry-After` 的较大值。超过 30 秒就带着 `retryAfterMs` 返回，不在这次调用里睡满。`Retry-After: 0` 仍等待计划中的那一档。用户取消不显示服务故障，退避中途也不再发送。离开页面只结束等待，不表示已经提交的写入被撤销。

收到响应头后，正文断连或超时不能丢弃状态和 `Retry-After`。401/403/404/409 不重放；429 以及可重试的 408/503 均保留已收到的等待限制。调用方取消优先静默结束。

错误体不要整份交给 strict 的 `AppErrorDTOSchema` 或 `LegacyGuardErrorSchema`。旁边的 `message` 或 `stack` 会让整份失败，合法的 `error` 和 `requestId` 一起丢掉。数据校验（Validation，https://vibe-hub.org/data-validation）先丢掉未知键。`fieldErrors` 只留契约字段里 1 到 200 字、不含控制符的句子。没有合法 UUID `requestId` 的已知码仍按旧 `{error}` 读取。

`UuidSchema` 定义在 `common.ts`。`errors.ts` 使用它，但不导出。从 `errors.ts` 按名字引入时运行值是 undefined，而且只有响应真带 `requestId` 时才会爆。

路径在匹配策略和实际发送前做一次解码，查询字符串保持原文，非法字符和点段拒绝。编码别名沿同一路径执行 Auth.js 排除、cron 禁重试、限体和重试白名单。

`/api/auth` 及其子路径在 fetch 之前拒绝。`/api/auth-admin` 不是这一族。`CredentialsSignin` 含大写，不是旧守卫 token，不能写入 `code` 或句子。

请求体在发送前按路径限制：分析 32KiB，聊天 16KiB，其余 8KiB。超限时 `attempts` 为 0，不重试原体。响应超过 4MiB 时，已经读到的字节也不进入失败对象。聊天一页可以远大于请求上限，不能把响应上限改成 16KiB。客户端自己拒绝的体积没有服务端 `requestId`，信封是 `unavailable`。

2xx 只返回有名 DTO 的解析结果，不拆开 `{ok,data}`。解析失败或正文不是 JSON 时用固定句子。Zod 的 issue 文本和 `Error.message` 都会带上输入，不能放进用户可见结果。
后台 HTTP 401 没有可识别错误码时，动作与固定本地化文案都按会话结束处理；HTML、空体和断体不能丢掉重新登录入口。已识别的 bad_credentials、recovery_expired 与 action_grant_invalid 保留各自处理，访客不触发后台登录。
收到的后台 HTTP 401 即使响应体声明超限或流式读取超限，也保留登录恢复动作与固定会话文案；请求发出前的体积拒绝没有 HTTP 状态，仍返回 stop 和零次尝试。
真实响应头到达与正文解释之间，调用方取消仍优先。正文读取正常返回后再次核对调用方signal，再解释超限/DTO/HTTP；取消时统一silent和空文案，不能在卸载后触发登录恢复。
