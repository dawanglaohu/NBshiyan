# PackJoyU 开发文档

这是一份网站改版与运营能力升级的实施规格。文档、任务契约和知识库已经过结构及语义审查；产品功能、媒体换标、生产部署和数据清理分别由任务验收，文档完成不代表这些动作已执行。

## 阅读入口

双击同目录的[index.html](index.html)即可离线阅读，不需要启动网站或联网下载依赖。左上搜索支持任务、边界、接口和术语；`H`进入任务交接台。09/12节序列和状态图可点击模块/边界编号；ER和数据流仍保留Mermaid源。

在Obsidian选择“打开文件夹作为库”，选择本目录，从[_MOC.md](_MOC.md)开始。`图谱/`是源表派生的模块、任务和边界笔记；任务尚未实施时，代码位置和实施沉淀受保护区块保持空白，不填写虚构证据。

## 不同角色从哪里开始

- 负责人：01目标、02非目标、21风险、22决策；概览可看依赖、覆盖和低置信记录。
- 实施方：交接台复制本任务实施提示，先读对应任务笔记和直接前置代码位置，再按07/08目录、09/10契约及所引边界实施。
- 审查方：同一行审查提示，核最新契约，真实运行测试和界面链路后回填；语义复核不是产品已通过或任务已落地。
- 运维方：14/16/17/18；实际生产删除、发布、扩容和外部承诺另受授权约束。

## 如何开工

文档已合并到本地`main`；不假定远端`origin/main`已包含它。第一项M1-T1从origin/main创建任务工作树后，若该远端基线尚无文档，先从本地main导入本目录及根AGENTS/CLAUDE，随首个实施PR提交；已含文档时沿用该版本。其他任务等待首PR合入远端主干后再创建。换机器须先传送已提交的规格基线，不能从没有文档的分支派出任务。

任务交接台顶部可选择窗口数、复制各窗口的顺序和开工提示；文件冲突会压低实际并行数，批次只是依赖层级。先复制开工提示，再派发当前可用任务。复制“实施”会推进本机状态，未准备派发时不要试点；完成后复制“审查”，审查通过由审查方登记复核、回填知识库、记录落地并按既定PR流程合入。每批全落地后做批次收口；紧邻上一批最新收口为clean/fixed才解锁下一批，open遗留会派生独立返工任务。

本轮只完成S1–S6文档，不自动开始S7。全部实施任务保持未落地；没有自动合并既有恢复PR、部署或执行生产删除。UI任务消费唯一minimalist-flat规格与11节项目适配；后台三尺寸D1–D6、真实GIF与computed style必须逐页验证。

## 目录与修改规则

00概览、01约束、02设计、03质量、04执行、05附录为可编辑源；`_run/presentation.json`与`task-contracts.json`是编排/契约源。`index.html`、`docs-data.js`、`_run/dispatch.json`、`图谱/`和`_MOC.md`是产物，不手改。源修正后运行项目内`maintain_docs.py build`重建；受保护的代码/实施记录随知识库重建保留。

`_run/review-log.md`记录本轮结论，`review.json`为结构证据，`task-reviews.json`为文档契约证据；校准原始状态、响应、model和哈希另存对应calibration目录。配置值、数据库和受保护恢复档案不在本文档公开材料中。
