# 后端架构

沿用现有Next.js/App Router、Auth.js、Prisma/PostgreSQL及SMTP。以下为目标实现约束，不表示目录与能力已实现；六项有限选择已记入决策13–18。共用错误、配置与DTO约定由06节及同源architecture.shared定义。

## 目录与职责

```text
src/
├─ app/api/                 Next route.ts入口与现有协议
├─ auth.ts                  Auth.js配置、sid与期限适配
├─ lib/contracts/           共享Zod请求/响应与错误码
├─ lib/server/              仅服务端组合、服务与repo
│  ├─ admin/                M3账号、设备、单用途授权与受限恢复
│  ├─ chat/                 M4消息、访客范围与通知出箱
│  ├─ analytics/            M5采集、聚合、保留与时区
│  ├─ ops/                  M6只读指标与脱敏来源
│  ├─ jobs/                 固定任务注册与有界消费
│  ├─ http/                 新HTTP错误映射
│  └─ composition.ts        显式依赖组合入口
└─ types/next-auth.d.ts      Auth.js类型增量
prisma/schema.prisma        增量数据模型唯一源
```

## layout

src/app/api/**/route.ts保留路由、src/auth.ts保留Auth.js组合；src/lib/server/admin/{device-session,action-grant,recovery}.ts属M3，chat/属M4，analytics/属M5，ops/属M6，jobs/放固定作业；src/lib/contracts/放新契约，prisma/schema.prisma仍是数据源；禁止另建应用或迁移无关旧模块。

## layers

新路径route→service→repo单向；route收发HTTP和调用守卫，service管业务/事务，repo接显式Prisma依赖执行查询；M6只读M4/M5查询，禁止repo反调service、service返回NextResponse、客户端导入server、统计或聊天反调看板；未改旧路径不强制重分层。

## data

复用db.ts唯一PrismaClient；新查询集中模块repo，锁/聚合用Prisma.sql参数化，禁止service拼SQL及拼接queryRawUnsafe；每实例connection_limit=5、pool_timeout=10s，总连接不超过数据库可用额度；schema只经现有deploy.sh备份/diff/plan-check/db push/零drift，禁止accept-data-loss、删改旧列或把prisma/sql参考计划当已执行迁移。

## middleware

后台新入口按requestId/脱敏计时→requireAdmin(当前User/sv/sid/角色)→写操作精确同源→await限流→限体/Zod strict→service→HTTP错误映射；公开聊天先同源/限流再cookie范围校验，恢复先限流再凭据，cron仅Bearer；既有邮件gate仍最先；禁止仅靠layout鉴权、漏await、日志含验证码/token/正文/email。

## tx

仅service或顶层use-case开事务，嵌套调用复用tx，禁止事务内SMTP/HTTP/文件IO与嵌套事务；一次性凭据核销+动作、恢复核销+sv/设备撤销+受限session、消息+seq+出箱均原子；敏感写最终重查账号/设备/授权；固定User→Device→Grant锁序，聚合整组原子替换并核作业代次，禁止先报成功再补关键写。

## utils

contracts及lib/chat/rules.ts、lib/analytics/rules.ts只放无IO的schema/枚举/纯转换；授权、同意准入、时钟、cookie、加密、存储与通知留server；禁止将带请求/状态的业务判断塞入utils或从纯模块读env。

## errors

新AppError仅含受控code/fieldErrors，service抛领域错误，repo只转已识别唯一冲突；仅server/http/errors.ts映射新HTTP，未知错误脱敏记录；Auth.js CredentialsSignin、旧{error}/邮件状态/rum空体保持协议；禁止全库换信封或外泄Prisma/SMTP原始异常。

## config

server/config.ts首次Node运行组合时集中读env、Zod验证并冻结，沿instrumentation.ts与startup/env-check.ts生产检查；测试显式传配置；环境改动需重启，站点时区从版本化SiteSetting按同一revision读取；禁止业务散读新增env、构建内联秘密或静默热改安全策略。

## di

不加DI库；server/composition.ts组装createService({repo,config,clock,tokenCrypto,mailer})供route使用；仅Prisma、冻结配置与无请求状态服务可为进程级对象；禁止全局当前用户/恢复凭据/消息/计数和以Map代替跨实例事实；依赖测试显式注入。

## jobs

jobs/registry.ts固定注册聊天通知、5min分析聚合、分析/聊天保留、运维采样及既有mail-queue包装，deploy/cron.nbshiyan真实调度；复用service/repo，持久租约+代次、batch≤500、截止55s；ChatNotification与消息同事务，SMTP事务外且稳定Message-ID/至少一次有界重试；禁止setInterval、after承担持久交付、看板GET跑作业或只写接口不接调度。

## 会话与恢复适配

Auth.js仍拥有认证HTTP协议、加密JWT、CSRF与redirect。新增设备sid接现有JWT/sessionVersion链，服务器每次核当前账号、设备、期限；request内可去重，禁止跨请求缓存授权。新适配层按普通2h滑动、记住7d闲置/30d绝对裁定JWT与Set-Cookie期限；初登、刷新、SSR、退出四条真实路径必须逐一证明。只改全局maxAge、只返回callback字段、只调用无参auth()都不能证明浏览器已续期。有效活动刷新入口和失效清cookie规则见09/10。

现有普通Credentials的recoveryCode参数与旧敏感写的恢复码捷径必须被拒绝或迁移到独立受限恢复，不能只隐藏字段。恢复码、permit、ActionGrant均做当前状态原子核销；TOTP核销同时匹配secret/sv/step。不同恢复码并发不得以旧数组覆盖复活已用码。恢复cookie只可重新绑定，不能替代Auth.js后台凭据；忘密码不等于换验证器后已找回，具体OS-owner重设与新绑定流程见09。

## 数据、作业与兼容边界

09是字段/状态/保留与可逆增量的唯一详表，10是端点/错误码/重试唯一详表。新成功响应直接用DTO、新失败保留error字符串；既有认证、询盘、邮件、空体RUM不整体重构。看板仅消费授权脱敏来源，采集、聊天保存与通知不依赖看板成功。schema-first db push继续既有备份/diff/审查/零漂移流程，新表列允许旧应用忽略；本次文档不自动授权生产迁移或不可逆清理。
