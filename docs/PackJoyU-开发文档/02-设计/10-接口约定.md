# 接口约定

## 兼容与新增范围

- NextAuth Credentials、`/api/auth/*` 的 CSRF、redirect、cookie、CredentialsSignin 与 session 形状仍归 Auth.js。扩展 `sid`/有效期元数据，不向客户端返回设备撤销凭据；失败保持 Auth.js 通用登录失败，不能通过不同码透露账号是否存在、是否启用无密码。
- 既有 53 个 handler、询盘/邮件 DTO、`/api/rum` 的空体 204、绑定 `{otpauthUri}` / `{recoveryCodes}` 不整体换信封。只改本轮明确触达的账号验证/绑定安全接缝并保持旧字段兼容；旧日常恢复码字段停止作为登录入口，UI 引导到独立恢复，其旧请求得到通用登录失败。
- 新增账号设置、恢复、人工聊天、分析和看板接口：成功直接返回本节有名 DTO；错误用 `{error,requestId,fieldErrors?}`。认证/授权拒绝仍可使用已有 `{error}`，新客户端要接受无 requestId 的旧守卫错误。
- 不引入线上语义判断、AI 客服、新数据库、新队列服务、通用任务平台。Sanity 产品内容仍在原数据源，PostgreSQL 中只保存必要业务/分析引用。


`Auth.js`是兼容族，绝不承诺自定义成功信封；具体新增DTO后列。所有新JSON接口`Cache-Control: private, no-store`，公开分析也不缓存；时区设置GET仅ADMIN；cron不接受浏览器session替代Bearer。

## 登录字段规范

`LoginMode`仅有`password`和`totp`：前者校验当前密码及验证器码，后者只在账号已启用passwordlessEnabled时校验账号与验证器码。缺mode保持旧password+totp请求的兼容；未知mode、未启用的totp模式及非空recoveryCode均走Auth.js通用登录失败，不公开账号或模式是否存在。日常界面默认显示验证器方式，并提供明确的密码方式入口，不加匿名账号方式查询API。

Auth.js表单字符串中，rememberDevice仅字面`true`映射true；缺值、false或字面`false`映射false，其他值拒绝。不得用JavaScript Boolean或无约束coerce把字符串`false`转成true。LoginMode由account schema单一定义并导出，组件不另写枚举。

## 响应、字段与例子

新增成功体不额外套ok/data。除Auth.js协议外，新错误保持error字符串可兼容旧守卫；requestId只做追踪，不是秘密。以下UUID/ID是示例非真实记录。

```json
{"message":{"id":"cm_example_message","seq":3,"sender":"VISITOR","bodyText":"Can you make this box in blue?","createdAt":"2026-10-19T16:20:00.000Z"},"receivedAt":"2026-10-19T16:20:00.000Z","duplicate":false}
```

```json
{"error":"idempotency_conflict","requestId":"5fcf5ba2-7d35-4d50-8798-e6f65b1268ef","fieldErrors":{"clientMessageId":"This identifier was used for different content."}}
```

## 幂等、重试、限流与版本

幂等按重复相同请求的所请求效果判定；正常访问日志、计数或附带审计不使读取变成业务非幂等，也不能仅因updatedAt变化就认定非幂等。一次性授权、验证码消费和秘密只返一次的动作仍按下表限制重放；语义上的最终状态幂等不等于允许客户端自动重试这些安全动作。采用[RFC 9110 §9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)的口径。

普通安全GET可按既有读取策略重试；`GET /api/admin/cron/mail-queue`是遗留的发信触发接口，明确不属于安全GET。浏览器、预取器、通用API拦截器不得调用或重试它；本轮调度使用POST，GET仅保留受控兼容。代理及调度客户端对两个触发方法均关闭自动HTTP重试。

聊天conversation创建使用clientConversationId，消息使用clientMessageId，绑定真实身份+会话并以payloadHash/唯一约束防重；同key同载荷返回原id/seq，不再加出箱，同key异载荷409。`POST /api/chat/session`是cookie bootstrap，不使用conversation UUID恢复身份：已有有效cookie可复用，无cookie响应丢失可能留下空session，客户端不自动循环创建，只有下一次明确联系才新建，未确认成功前不发送消息。read采用MAX；关闭和设备撤销的最终状态幂等，但已消费授权不可重放。Analytics事件保留原eventId/semanticKey重试，不把原始事件去重与按日重算混为一件事。

### 逐路径副作用、重试与结果未知

下表逐项覆盖端点校准中11条`mutating=yes + idempotent=no`记录；consent和受限enroll经补充分支约束后有条件幂等，原校准结论保留。禁止用表中触发接口本身探测作业是否已运行。除明确列出的有条件重试外，网络超时、408、429、5xx都不触发客户端自动重放；Retry-After只限制下一次允许操作的最早时间，不证明前次未提交。

### 其他写路径的结果核实

- `/api/auth-admin/enroll`与`/api/auth-admin/enroll/confirm`仍按既有一次性token窗口，不自动重放绑定/确认。首次绑定响应不明时不能生成新key覆盖当前pending；已确认但恢复码响应丢失时用下一TOTP及密码正常登录，再经新鲜验证的受限重绑取得新材料，不重复confirm取回旧码。
- `/api/admin/account/password`、`/api/admin/account/2fa/reset`、`/api/admin/account/login-mode`、`/api/admin/account/devices/[id]/revoke`、`/api/admin/account/logout-all`及`PATCH /api/admin/settings/analytics`不自动消费同grant或同TOTP重放。账号/开关读GET /api/admin/account；设备读GET /api/admin/account/devices；时区读GET /api/admin/settings/analytics的version/revision；已退出或改密用当前预期凭据正常登录核实。本人2fa/reset若cookie已收到则回受限页重入enroll；无cookie才明确重新新鲜验证，原绑定在最终确认前保留。撤销/关闭所请求的最终状态可幂等，不能因此恢复已用grant。
- `POST /api/internal/ops-report`按source+measuredAt和规范载荷处理：同时间同载荷重放返回原accepted结果且不改测量/成功时间；同时间不同载荷409；旧measuredAt返回accepted=false并忽略，不倒退lastSucceededAt或覆盖新快照。失败报告保留此前成功值。相同报告网络重试最多一次，身份仍仅CRON_SECRET。
- 聊天消息/读取和analytics事件的同key请求可按前述语义重试。消息网络/408/429/5xx可复用原key退避1s/2s/4s最多3次，429遵Retry-After；401/403/404、幂等冲突、关闭或匿名化不重试。后台聊天包括read始终只允许ADMIN/SALES；“仅改自己的游标”不授权EDITOR。后台会话401去安全站内登录；action_grant_invalid仅要求当前仍有效账号重新本人验证，不能把旧grant重发。通知失败不改变已received消息。

- 初值：公开session/新会话每匿名cookie10次/10min与IP-HMAC20次/10min；聊天写每会话20条/min、每后台用户30条/min；同步每cookie/后台用户60次/min；分析每cookie120事件/min、每IP-HMAC300事件/min；恢复/reauth沿既有账号+IP限流并加每账号5次/10min、每IP20次/10min，5次错码作废待确认新因素和受限凭据，保留原有效绑定；看板每后台用户30次/min；cron按租约拒绝重叠。IP仅当场派生限流键不入分析库，遵现有可信边缘IP解析。
- 新JSON体上限：聊天16KiB、账号/恢复8KiB、分析批次32KiB；先限体再JSON解析。普通API客户端15s超时，服务端普通数据库交互事务≤5s，聚合单批快照/替换事务≤30s且总作业仍≤55s；SMTP由作业独立20s截止，外部验证沿既有10s；cron总55s。429带Retry-After，超时/数据库不可用503，不把失败记录伪作成功。
- URL沿现有`/api`体系，新协议称`operations-v1`并以DTO字段向后追加；不改全站版本前缀。破坏性变更另开兼容窗口/新路径并双读验证，移除旧协议另任务；Auth.js版本始终由锁文件约束，不把自定义API版本套到它。

## 非REST通道与短轮询

本轮无新增WebSocket/SSE。消息同步使用`afterSeq`短轮询：可见且窗口打开3s，收到hasMore立即补页；隐藏/关闭暂停，恢复前台立即补齐；网络失败1/2/4/8/16/30s退避，成功回3s；同请求只允许一个在途，取消旧请求不推进游标。后台收件箱刷新快照，聊天正文按会话seq补齐。所有回调卸载时取消请求/计时器。

不新增SSE、WebSocket或长连接路由。消息同步的seq协议与传输分开，后续变更传输须独立契约与部署验证。

## 既有公开数据源的兼容契约

以下是第07/11节使用的既有数据源，不改请求、成功体、错误协议或缓存策略，不计入上表本轮修改端点。

- `GET /api/models`：`src/app/api/models/route.ts`调用`listPublishedModels`返回`{items}`，仅已上架且检查通过模型，`public,max-age=60,s-maxage=60`。模型字段沿`src/lib/server/published-models.ts`实际导出类型，前端不得造一个新的商品接口。产品页实际SSR调用loadCatalog(listPublishedModels)，不要求浏览器再次GET此端点；独立兼容HTTP校验不等于页面取数请求。
- `GET /api/models/[id]/[variant]`：沿既有授权发布状态、variant白名单和内容哈希检查，返回模型或海报文件；静态`/models/`现有资源链仍保留，实际GLB加载完成才发成功终态。
- `POST /api/inquiries`：沿`src/app/api/inquiries/route.ts`的严格schema、Turnstile/防滥用/上传归属及真实事务；合法新提交返回201 `{ref}`。`source`沿FORM/WIZARD/CART/CUSTOMIZER/SAMPLE，`locale`沿已发布语言；contact、items、message、logoUploadId等字段不借本轮改形状。点击提交的证据必须包含该真实请求、持久业务编号及重载后的记录，不能把已收到邮件当成保存成功。

## chat_start字段与消费

AnalyticsEventDTO的chat_start分支要求eventId、navigationId、occurredAt、locale，path只能是净化的站内白名单路径，productSlug若有须已发布；不接收conversationId、messageId、email、bodyText或cookie/token。M4-T5经M5客户端队列调用POST /api/analytics/events，服务端按09的导航语义键去重，成功落账后才参与chatStarts聚合。业务咨询保存不等待分析成功，拒绝/撤回分析不阻止聊天。
