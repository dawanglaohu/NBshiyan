# 性能与容量假设

本节的数字分为已知输入、既定配置边界与待测容量。配置上限是防止工作无限增长的设计约束，不代表该机器已证明的吞吐能力。测量使用隔离服务、数据库与合成数据；本轮文档没有执行网站性能验收，也不承诺生产SLA。

## 时间、并发与有界工作目标

以下目标沿08–10节，不引入第二套服务常量。实现后的报告须给出设备、网络、浏览器、Node/锁文件版本、数据库配置、样本规模与时间范围，再陈述实测值及是否满足；在取得该报告前都记为未验证。

| 路径 | 既定目标或边界 | 失败/超界行为 |
|---|---|---|
| 访客/运营消息同步 | 可见且窗口打开时正常3秒轮询；每轮最多一个在途；消息页默认50、最大100 | 隐藏暂停；恢复立即从完整seq补齐；连续网络失败1/2/4/8/16/30秒退避，成功回3秒；不并发堆积请求 |
| 普通HTTP与数据库交互 | API客户端15秒超时；普通交互事务不超过5秒；外部验证沿既有10秒截止 | 按10节返回安全失败；一次性安全写不因超时自动重放，聊天与事件仅按原幂等key重试 |
| 数据库连接 | 每实例`connection_limit=5`、`pool_timeout=10s`；总连接不越数据库实际可用额度 | 实例数和其他消费者额度上线前实测；连接不足先限制并发或关闭可选入口，不自动扩容 |
| 聚合 | 每5分钟触发；快照/替换事务单批不超过30秒，总轮次不超过55秒 | 事务中断保留上次完整值；数据源超15分钟按stale说明，不能承诺故障期仍按5分钟更新 |
| 固定作业 | 每批最多500项、总55秒、租约90秒，按需受控续租 | 未完成工作留到下轮；旧代次不得覆盖新结果，超时不由HTTP客户端重复触发 |
| 聊天通知与既有邮件队列 | 每分钟真实cron；SMTP单次20秒截止；聊天通知最多3次，退避1/5/30分钟 | 持久状态恢复；未知投递允许至少一次策略的重复，不承诺精确一次；消息收件独立于邮件结果 |
| 后台列表与统计查询 | 设备最多50项；聊天列表默认25、最多100；统计最多连续400日且受13个月范围限制 | 参数越界400；游标受验证；大范围查询不返回无界明细，不在看板GET运行作业 |
| 滥用隔离 | 各接口沿10节身份/IP-HMAC限流与8/16/32KiB体积上限 | 429给Retry-After、413拒绝超体，不把拒绝写入算成功消息或分析事件 |

首屏加载、LCP/INP/CLS、API p50/p95/p99、并发安全容量、真实3D加载耗时和交互帧率的现状均未评估；并发与API分位容量目标也未评估。第12节明确的p75 LCP≤2.5s、INP≤200ms、CLS≤0.1及本地反馈100ms是设计体验目标，不能声称已测通过。实施验收先留下可复现测量，再在不扩大费用及范围的条件下解决明确退化；不能用没有基线的漂亮百分比宣称提升。3D成功率与平均耗时只覆盖同意后真实尝试，并携带样本数；没有样本返回null，不能称0毫秒或100%成功。

## 媒体与交互资源策略

- 选定v3视频使用其实际帧JPG海报与用户可控制的静音行内播放，不重新指向原参考视频。解码失败、自动播放被阻止或减少动态效果时维持静态回退及主动播放入口，不以持续重试抢占资源。
- GIF在场景模块接近可视区后才下载；不在首页启动时预取整段。用户暂停、离开视区、后台标签或减少动态效果均可转同尺寸静帧，用户的显式暂停优先。复核或确需派生时须保持选定GIF全部361帧的品牌覆盖、制作记录逐帧时序和完整循环，不以丢失标识检查换体积；同尺寸暂停帧依所选原尺寸/预览GIF分别核验发布，不用静态PNG假充。
- 模型只在实际模型操作区接管输入；卡片不做几何hover scale。普通滚轮仍交页面；聚焦后的显式缩放才改变相机。卸载、失焦、取消和Escape必须释放捕获、监听及定时器，防止不可见模型持续占用输入或渲染。
- GLB失败、WebGL不可用或context lost使用对应产品静态回退，不无限重试。相同viewId只报一次终态，分析批次最多20事件；未同意或已撤回时不排队补报访问。
- 媒体、模型和看板分别记录资源及请求成本。不得为了缓存提速把受保护JSON、身份判断或咨询内容放入公共缓存；数据时间与身份撤销一致性优先于跨请求缓存命中。

## 数据库与作业瓶颈

| 已知压力点 | 设计控制 | 必须取得的验证证据 |
|---|---|---|
| 每次受保护请求读取设备和当前账号 | 请求内去重、按09节索引查询；无跨请求授权缓存 | 合成并发下查询计划、连接占用、撤销可见性及响应分位；不得牺牲撤销验证换吞吐 |
| 同一咨询并发追加seq及已读更新 | 会话行锁+唯一约束；已读MAX/CAS；有界分页 | 双运营和重复提交不漏消息、不重复出箱；锁等待与超时可解释 |
| 分析原始写入与自然日distinct | eventId/semanticKey唯一，occurredAt/receivedAt及产品索引；只处理合法有界批次 | 真实PostgreSQL重复/乱序写、跨午夜与迟到样本；聚合计划与工作集内存测量 |
| 聚合重算与时区修改争用 | 一致快照、租约代次、revision复核，整组事务替换 | 并发调度与切时区中旧任务不能覆盖；中断不出现半组数据；不重算原始不完整的历史日 |
| SMTP缓慢或不可用 | 消息先提交，SMTP在事务外；持久出箱、20秒截止和有界领取 | 真实发送结果/受控故障下数据库事务不等待SMTP，重启后消费且不误报已投递 |
| 保留清理与新消息同时发生 | 默认dry-run；按有限批扫描，最终事务重读活动与策略版本 | 隔离库验证清理跳过新咨询；生产关闭状态明确，无未经授权删除 |
| 备份与存储采样 | M6固定采样只报安全摘要；15分钟采样、不读备份内容 | 真实来源可用时的采样成本；来源不可用时其他指标仍可用，不能由看板读取触发备份 |

容量不足时优先关闭可选聊天入口并保留现有联系渠道、暂停新媒体自动播放、限制有界作业并发，继续保留已接收数据和真实来源状态。购买资源、迁移数据库或另起客服平台均超出本轮选型的自动执行范围。
