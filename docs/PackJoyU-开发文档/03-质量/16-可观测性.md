# 可观测性

观测用于解释真实业务与作业结果。看板GET是只读消费者，不能靠刷新页面产生心跳、发信、补聚合或触发备份。所有新增状态必须有已接线生产者和真实时间；没有证据时显示未知、未接入或最近已知结果，不从“没有流量”推断整条链路健康。

## 生产者、落点与覆盖范围

| 来源 | 生产者与接线归属 | 持久证据/可读口径 | 覆盖限制 |
|---|---|---|---|
| 授权访问与产品/3D | M5同意与事件入口；M2真实页面和模型生命周期发事件 | AnalyticsEvent→固定analytics-aggregate→AnalyticsDaily、sourceThrough/aggregatedAt/timezoneRevision | 仅允许分析的匿名浏览器；UV不是真人；海报或程序化演示不算GLB成功 |
| 询盘 | 既有Inquiry成功持久化路径，M6只读原scope | 稳定询盘标识和授权计数 | 失败和重复提交不新增发起；SALES遵既有业务scope，不输出联系人字段 |
| 人工咨询 | M4消息/会话事务及专属ChatNotification | 唯一会话/消息、真实receivedAt、seq与通知状态 | 收件、人工已读、通知接受、实际投递分开；轮询不能表示坐席在线 |
| API可靠性 | M3共享`src/lib/server/http/metrics.ts`在最终响应处接线；M4/M5复用 | ApiDailyCounter按routeId/日/revision的请求数、5xx数与lastObservedAt | 只覆盖本轮明确接线API；无真实requestCount不计算错误率，不称全站监控 |
| 固定作业 | M5交付JobState、registry与实际cron；M4/M6交付自身注册 | lease/generation、lastStartedAt/FinishedAt/SucceededAt、lastStatus、白名单计数 | 路由存在或手动成功一次不证明cron运行；不注册未来模块的空实现 |
| 询盘邮件与聊天通知 | 既有MailMessage、M4出箱worker及验证过的SMTP适配器 | sent/failed/unknown等真实尝试结果、稳定Message-ID的安全关联 | SMTP接受不等于收件箱投递；缺配置为DISABLED，不能算发送成功 |
| 存储 | M6固定ops-sample与受鉴权report脚本 | OpsSourceSnapshot(STORAGE)的bytesUsed/bytesFree、measuredAt/lastSucceededAt | 只传白名单摘要，无服务器路径、文件名或文件内容；无接线为not_connected |
| 备份 | 既有备份流程的真实完成/验证元数据，经M6受控报告接入 | OpsSourceSnapshot(BACKUP)的backupCompletedAt/backupAgeSeconds/verified | 计划时间、文件存在和普通上传不证明备份完成或可恢复；不可读取/传输dump内容 |

`src/lib/server/composition.ts`是实际组合点，`src/lib/server/jobs/registry.ts`是固定作业注册源，`deploy/cron.nbshiyan`负责系统调度。M5先交付基础及分析作业；M4随后追加通知/聊天保留及既有mail-queue调度；M6追加运维采样与报告。M7仅核对完整链路，不承担先前任务运行所需的任何基础。

ApiDailyCounter等观测写失败不得进入或回滚核心消息、账号变更事务；响应仍反映业务真实结果，同时留下脱敏观测失败警告并将该来源覆盖标为部分/失败。记录请求数须在最终响应边界且每次请求最多一次，不能在route和错误处理器两次累加。匿名统计中的业务发起按稳定业务标识去重，不能从HTTP请求总数推导成功咨询量。

## 结构化日志与审计分工

新增服务端日志使用固定事件名和受控字段：`timestamp`、`level`、`requestId`、`module`、`operation`、固定`routeId`、`outcomeCode`、`status`、`durationMs`；作业可附`jobKey/generation/counts`，聚合可附`timezoneRevision/sourceThrough`。错误码沿10节，未知异常只记录脱敏类别，不把底层message、堆栈或连接串直接串入日志。受控requestId可回到新API错误体；它只是关联标识，不是授权依据。

| 级别 | 具体记录点 | 不应记录的内容 |
|---|---|---|
| DEBUG | 仅隔离开发中无PII的状态流转与分页/取消诊断；生产默认关闭 | 请求体、cookie、密码、验证码、恢复材料、正文和邮箱 |
| INFO | 固定作业开始/结束安全摘要、聚合事务成功发布、真实通知结果、ops采样结果 | 将每次成功轮询打印全文；将计数日志当原始访问账本 |
| WARN | 限流、受拒越权/重放、幂等冲突、租约过期、未知投递、观测写失败、来源变旧 | 原始IP/UA、被拒字段值、完整URL、SQL、SMTP服务器响应全文 |
| ERROR | 数据库不可用、聚合作业失败、脱敏内部错误、配置阻止必要功能启动 | 环境变量值、数据库地址、文件路径、密钥及原始异常对象 |

安全审计是另一个有权限的持久渠道。账号/因素/设备、恢复签发完成和时区变更的成功审计与对应数据库动作同事务；actor/target仅进入该受限审计，不复制到公共指标或一般访问日志。不得用审计中出现一条“开始”记录宣称动作已经成功。日志与截图遵14节脱敏，原始附件和恢复备份不进入收集范围。

## 指标定义

| 指标 | 定义与空值处理 | 数据来源 |
|---|---|---|
| 今日授权访客、PV | 站点IANA自然日左闭右开；browserHash当日去重，真实navigation/page事件计PV | 当前revision的完整AnalyticsDaily；拒绝分析访问不补入 |
| 产品访问、3D发起/成功/失败 | 产品slug须发布有效；真实viewId关联start与最多一种terminal | 产品维度聚合；没有打开3D不算发起，失败回退不算成功 |
| 3D加载成功率与平均耗时 | 成功数/真实发起数；耗时取有效终态样本并显示samples | 没有发起或耗时样本时value=null；不可展示无样本0%或0毫秒 |
| 咨询及未读 | 成功持久化会话/消息去重计数；未读按当前运营本人游标 | M4业务表；仅收到消息不推进已读、不伪造在线 |
| API错误率 | 本轮已接线routeId的5xx数/同范围真实requestCount | ApiDailyCounter；分母0时无样本，来源不全显示coverage |
| 通知排队、失败、未知及已接受 | 分别按真实状态/尝试结果统计，不把进入函数或QUEUED计SENT | MailMessage与ChatNotification，保留两种协议差异 |
| 作业时效和积压 | 最近真实开始/结束/成功、租约状态与白名单剩余计数 | JobState及对应队列；没有运行记录为NEVER/未接入，不生成虚拟成功时间 |
| 存储与备份 | 真实字节值、最后完成/验证时间及状态 | 受控OpsSourceSnapshot；没有验证仅陈述已知完成事实，不声称可恢复 |

不新增收入、产能、虚构SLA或全网用户等没有来源的数字。运维来源仅ADMIN，SALES读取授权业务聚合，EDITOR只读公开流量/3D；服务端在查询前应用角色和scope。趋势和导出若沿既有入口复用，适用同一权限及脱敏约束，不能借导出绕过看板限制。

## 数据时间与分源状态

每个来源独立携`state/value/timezone/timezoneRevision/dataThrough/queriedAt/lastSucceededAt/coverage`。`queriedAt`仅代表本次读取时刻；`dataThrough`是被聚合覆盖的来源水位，`lastSucceededAt`是该来源最后真实成功时间。界面不能用新的queriedAt覆盖旧值时间。聚合作业只有整组替换事务提交成功才推进sourceThrough及aggregatedAt，旧代次和旧timezoneRevision不能发布。

| 状态 | 可核实条件 | 界面行为 |
|---|---|---|
| ok | 已接通、查询成功且结果非零，时间在来源新鲜范围内 | 展示值、数据时间、口径与coverage |
| zero | 同一有效来源与查询范围中真实结果为0 | 展示0及成功时间；不判为采集故障 |
| no_data | 来源尚无所选范围覆盖或首次尚未形成可查结果 | 展示尚无数据和来源原因，不填0 |
| not_connected | 配置、生产者或任务来源没有接通 | 展示未接入及具体来源；核心访问与3D不能以此通过本轮验收 |
| query_failed | 本次必要读取失败 | 展示安全错误与重试；有上次快照则保留原值/原时间并标明旧值，无快照不填0 |
| stale | 保留的最后成功值已超过该来源新鲜阈值 | 明显展示旧值、真实时间与状态；不能靠刷新页面重新计时 |

一张卡失败不覆盖其余卡的状态，页面总刷新成功不代替分源成功。切换日期/时区时不能把旧查询响应覆盖较新选择；只能展示匹配当前查询键的快照。原始30天以外的历史重算能力由coverage和recomputableFrom说明，旧revision不与新时区混成统一趋势。

## 异常条件与处理

以下阈值是09节既定时效规则，尚非实测服务承诺。异常首先进入脱敏日志、JobState和有权限的看板状态；本轮不因此新增外部告警服务、付费平台或对他人自动发送消息。

| 触发条件 | 可观测结果与恢复路径 |
|---|---|
| 分析每5分钟聚合，最近成功超过15分钟 | 标stale并保留原watermark，核cron实际注册、租约、数据库与revision；无流量但作业成功可是真实zero，不伪造采集心跳 |
| 邮件/聊天通知每分钟任务，最近成功超过5分钟 | 标旧任务状态并显示积压/失败/未知；核持久租约与SMTP配置，下一计划恢复；不重复HTTP触发来探测结果 |
| 存储15分钟采样，最近成功超过45分钟 | 该来源独立stale/failed，保留原measuredAt；核受控report通道，不在看板请求中采样 |
| 每日备份36小时没有真实成功标记 | 标stale；核原备份流程及其完成记录，不能用计划时间、文件上传或数据库health代替成功 |
| cron接口存在但没有真实运行记录，或配置未接 | 显示NEVER/未接入，交由所属模块修复实际调度并验证重启后运行；不能改时间掩盖 |
| SMTP接收后状态写回失败、旧worker晚提交或租约丢失 | 保留UNKNOWN或对应旧租约拒绝记录；按出箱状态机有界恢复，稳定Message-ID，承认可能重复；已收件消息不回滚 |
| 数据库、统计查询或辅助来源异常 | 当前源query_failed，已有值保留原成功时间；其他来源继续读取；必要身份校验失败则不返回受保护内容 |
| 受拒越权/重放、连续429或计数写失败 | WARN记录固定route/结果码及覆盖受损原因；按14节处理安全边界，按10节退避，不记录尝试的秘密或用失败请求灌成功统计 |
| 保留作业未获生产授权 | 明示dry-run/清理未启用及候选数量；不将其标为已执行删除，不碰既有询盘、恢复文件及备份 |

当前`/api/health`仅验证数据库且按04节不对公网暴露，不能代表模型、聊天通知、统计调度、存储和备份全链路健康。验收证据须从真实页面/接口或业务动作追到对应持久结果及分源DTO；日志截图、手工改库、单次手动cron和演示数字均不能替代该链路。
