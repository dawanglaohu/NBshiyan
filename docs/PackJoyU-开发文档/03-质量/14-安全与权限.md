# 安全与权限

本节约束本轮新增和明确触达的接口，身份、字段及状态以09节为准，HTTP协议与错误码以10节为准。设计目标尚须实施与真实服务验证；文档完成不表示生产恢复、迁移或清理已经获得执行授权。

## 身份与权限矩阵

普通后台登录保留Auth.js。`mode=password`校验密码和验证器码；`mode=totp`仅在账号本人已启用且绑定有效时使用账号与验证器码。账号标识不构成第二个因素，界面须按E-09说明无密码模式的实际安全含义。`recoveryCode`完全移到独立恢复，日常Credentials出现非空值即通用失败；不能仅删除界面字段而保留后端旁路。缺失mode沿既有密码方式，未知枚举和未启用方式均不透露账号是否存在；`rememberDevice`显式解析，字符串`false`不能被转为true。

## 会话、新鲜验证与恢复边界

- 设备行与加密JWT的sid/sv共同决定有效性。普通模式为2小时有效前台活动滑动；记住设备为7天闲置、签发后30天绝对上限。先判有效再touch，以数据库时间和条件更新处理并发；过期、撤销、禁用或sv变化不能因刷新复活。真实活动入口15分钟节流，后台轮询、读取session和无参`auth()`不产生前台活动。
- 初登、活动刷新、SSR和Auth.js普通signOut共用期限及撤销规则。能写响应的路径同时裁JWT与Set-Cookie；SSR不能写cookie时只报告现有有效性。普通退出撤销当前sid；改密、重置因素、禁用与退出全部设备原子递增sv并撤销旧设备。不能以删除浏览器本地状态替代服务端撤销。
- 敏感设置使用当前密码与未使用TOTP换取5分钟、一次性、绑定user/sid/sv/purpose/target的ActionGrant。原始grant仅留标签页内存；最终动作与核销同事务，按User→Device→Grant顺序锁定。TOTP消费匹配当前secret、sv和时间步，同一时间步不能被登录或并发设置重复使用。忘记密码仍能无密码登录不等于有权绕过新鲜验证。
- 一次性恢复码和15分钟permit只能换取10分钟受限恢复session；核销、旧设备撤销、sv推进和受限session创建同事务。恢复码须锁User后重读当前数组再删除匹配项，避免不同码并发用旧数组覆盖而复活已用码。受限cookie只被recovery/enroll和confirm接受，不能进入admin守卫、任意callback或Auth.js完整后台会话。
- 新因素最终验证成功前保留旧有效密码和验证器；受限enroll重入仅复用未过期pending材料和原期限。确认成功原子替换因素、恢复码并撤销旧凭据，恢复码一次展示，不可由查询接口取回。5次错码使待确认流程作废，不关闭原有效绑定。
- ADMIN替他人签发permit须自己的新鲜授权，不能自授权。无第二管理员且恢复材料丢失时，只有服务器OS所有者的受控本地TTY命令可签发同类受限permit，并注明目标、来源与原因。需要忘密重设时，本地隐藏输入的待提交密码hash随permit进入受限session，仅新TOTP最终确认事务可提交。HTTP不得接收或修改`pendingPasswordHash`，不开放匿名邮件万能重置，也不放宽既有首次绑定脚本的守卫。

以上对应E-01–E-15、E-68–E-75、E-95–E-96。首次绑定仍保留既有token字段和窗口；最终CAS必须重新匹配当前tokenhash、期限、sv和secret，不能用请求开头读取的旧状态完成绑定。

## 凭据、传输与存储

| 数据 | 浏览器/传输 | 服务端与输出限制 |
|---|---|---|
| 后台会话 | 沿Auth.js加密JWT与生产Secure/HttpOnly cookie；保持原CSRF协议 | 当前设备行校验不可省略；客户端不能更新sid/sv/role/remembered；不输出可复用设备凭据 |
| 受限恢复cookie | `Secure; HttpOnly; SameSite=Strict; Path=/api/auth-admin/recovery`，不设Domain | 随机256bit，仅存hash；独立于后台cookie；过期、完成或撤销清cookie |
| 聊天必要cookie | 主动联系后签发；`Secure; HttpOnly; SameSite=Lax; Path=/api/chat`，不设Domain；localhost开发例外单列 | DB仅存hash；7天闲置/30天绝对；无URL、HTML和JS持久副本；邮箱不能用来找回旧会话 |
| ActionGrant与恢复permit | HTTPS一次性响应；grant在内存，permit若构成链接只放fragment，读取后立即清URL | DB仅存tokenHash；禁止query、埋点、访问日志及本地持久存储；丢失响应按10节结果未知协议处理 |
| 密码、TOTP及恢复材料 | 密码不回显；绑定URI仅向有效绑定/受限流程返回；恢复码一次展示 | 沿现有Argon参数和AES-GCM密钥封装；恢复码存hash；加密密钥不进入客户端构建或库内文件 |
| 分析身份 | 获同意后服务器签名`pj_analytics` cookie；不信请求体的consent/browserId | 域分离HMAC得browserHash；不收原始IP/UA、指纹、邮箱、聊天内容或完整URL；聚合不含可回连身份 |
| 咨询内容及邮箱 | 纯文本1–4000 code points，可选邮箱≤254；只按本人访客凭据或ADMIN/SALES读取 | 不渲染HTML、不接附件、不进入日志/埋点/通知正文；非本人查询不暴露会话存在性 |

公开分析、后台及聊天新JSON响应均为`private, no-store`。HTTPS与现有代理信任配置按受保护部署配置校验；来源校验使用站点精确Origin，不接任意同域后缀和跨站凭据CORS。SameSite不代替CSRF防护：Auth.js继续自己的CSRF流程，新增cookie认证写接口执行精确同源检查。受限恢复页不加载可读取其临时材料的第三方脚本；回跳只允许当前角色可见的站内路径。

## 最小化、保留与审计

聊天凭据与咨询内容期限独立：必要cookie7天闲置/30天绝对，新增消息和主动邮箱最后成功收发后90天；轮询、已读和通知重试不延长咨询保留。分析原始按接收时间30天、无个人关联聚合13个月；旧询盘730天及已有备份策略保持原约束。所有不可逆保留清理默认dry-run，实施及隔离验证不代替生产保留策略授权；未获明确授权不能开启真实删除，也不能据本文清除恢复文件或备份。清理最终事务重验当前活动、策略版本与截止，避免删除并发恢复沟通的内容。

安全审计至少覆盖绑定/恢复签发与完成、设备撤销、登录方式和密码变更、时区变更及受拒越权。敏感数据库变更与成功审计同事务，记录actor/target、source、结果码、时间和必要原因；失败验证记录脱敏事件，不保留用户提交值。任何审计meta、请求日志、截图及测试产物禁止出现密码、验证码、恢复码、密钥、cookie、完整恢复链接、聊天正文或邮箱。

通知出箱与消息同事务，但SMTP在事务外；通知只含收件事实和受保护后台链接，使用稳定Message-ID及至少一次有界重试。SMTP接受不等于投递或人工已读，未知结果不能改写为成功；通知异常不能撤销已收件消息。具体可观测证据与异常状态见16节。本项目没有线上语义判断层，不向文档校准服务发送生产咨询、用户凭据或访问明细。
