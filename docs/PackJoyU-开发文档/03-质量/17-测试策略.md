# 测试策略

本节定义实施与收口的验收方法，不表示本轮文档编写已运行或通过网站功能测试。测试基线取锁文件、`package.json`、`.github/workflows/ci.yml`、`playwright.config.ts`、`e2e/global-setup.ts`与现有测试文件；新增用例与生产入口同时提交，不能把“测试文件存在”当作功能完成。

## CI与命令基线

使用Node 22、pnpm 10与冻结锁文件。Windows本机pnpm 9不能改写锁文件规避安装差异；可用`npx --yes pnpm@10.34.6`执行同一pnpm命令。完整构建应在Linux CI或隔离Linux环境完成，Windows standalone的symlink EPERM不能写为构建通过。

| 检查 | 实际入口与实施要求 |
|---|---|
| 安装/规则测试/构建 | `pnpm install --frozen-lockfile`、`pnpm test`、`pnpm build`。CI保留`pnpm audit --audit-level high --prod`及模型体积、模型引用、后台guard脚本 |
| 静态检查 | 当前`pnpm lint`定义为`next lint && pnpm run lint:ru-yo`，CI尚未执行；实施先核锁定Next命令是否可用，若入口失效，改为该锁版本支持的ESLint入口并补进CI，不得删除规则或把未运行的lint报绿。类型可用`pnpm exec tsc --noEmit`核验，不声称仓库已有typecheck脚本 |
| 条件DB测试 | `cleanup-lock.db.test.ts`、`last-admin.db.test.ts`只在有效PostgreSQL `DATABASE_URL`时执行；`admin-reset-initial-password.db.test.ts`仅认`ADMIN_RESET_TEST_DATABASE_URL`，不能拿普通开发库替代。隔离CI须显式提供两项测试地址并验证数据库可连接，运行对应文件并核0个环境性skip；缺地址、地址非一次性测试库或不可连均阻断本轮DB验收 |
| standalone | `pnpm build`后确认`.next/standalone/server.js`存在，再设置`STANDALONE_TEST=1`运行`node --import tsx --test tests/standalone-start.test.ts`；缺标志或缺产物造成的skip不能算启动检查通过。测试仅用假密钥，验证缺EDGE_AUTH_SECRET/DATABASE_URL/SMTP_PASS等拒绝启动 |
| 浏览器 | 当前CI先专用PG17 `prisma db push --skip-generate`、安装Chromium、构建，再`pnpm test:e2e`。配置单worker、0重试，默认服务3100、Turnstile测试服务3999；`E2E_PORT`可改测试端口。`global-setup.ts`通过现有创建脚本建合成管理员并传一次性绑定token，不打印token |
| 部署脚本 | 在Linux/Bash运行仓库`deploy/tests/*.test.sh`9项入口；至少覆盖plan-check、smoke、env-check、mem-check、build-offbox和import-scan。只在隔离目录与测试资源运行，不触发生产部署或清理 |
| 性能回归 | 沿用Lighthouse对`/en`、`/en/products`各3次、LCP≤2000ms、CLS≤0.1、performance≥0.9的既有CI门槛；结果是测试环境证据，不扩写为生产SLA |

现有E2E会拦截第三方请求；新主冒烟只能拦外部服务，**不能拦截/替换本应用的账号、聊天、分析、stats API或模型请求**。Turnstile使用官方测试key及隔离验证服务可验证应用提交链，但生产真实key配置与TLS连通性需单独记录；不以测试验证服务证明第三方生产可用。

## 端到端冒烟

实施新增一条由CI `e2e` job执行的主冒烟，运行真实构建后的Next服务和专用PostgreSQL。每个可见控件使用语义role/name或稳定testid定位；禁止通过sessionStorage、localStorage或直接写业务表伪造登录、同意、消息、事件、看板数字。可读取安全业务状态核对结果，但创建业务事实必须经过对应产品入口和HTTP。

1. 新浏览器打开`/en`，等待真实CSS加载；断言11节token在元素computed style生效：白底/黑色文字、主控件2px边框、0圆角、无阴影，以及实际字号/行高。通过导航进入`/en/products`，确认真实目录/模型数据加载与真实接口响应，保存请求method/path、状态码及安全业务id；不能只断言SSR有文字。
2. 用同意控件明确允许分析，观察服务器签名分析cookie；真实完成一次页面导航并发出`page_view`，打开已发布GLB产生同viewId的start及success或可解释failure。拒绝分析的独立浏览器须无标识/事件且模型仍可用；先true在途再false后不得残留采集。
3. 按真实已注册计划触发分析聚合，读取成功JobState与完整watermark，再由通过真实首次绑定和登录的管理员进入`/admin/stats`。核对相同日期/时区的真实PV、授权浏览器和3D指标，重复事件不累加；清晰区分样本数、null和0。至少一次集成验收等待真实五分钟计划并在重启后再次成功，不能以只手调HTTP代替cron注册。
4. 从可见联系按钮打开咨询，拒绝分析状态也可发送；通过真实POST创建会话及首消息，HTTP超时重试复用原UUID。另一管理员浏览器从后台壳进入收件箱、打开该会话并回复，访客下一次seq同步看到回复；通知状态独立，不把received改成已读或已投递。
5. 从后台个人信息切换已验证登录方式，普通登录不出现恢复码必填；记录真实Set-Cookie，在有效期内重新打开同一真实浏览器配置恢复会话，再撤销设备验证其下一受保护请求拒绝。2h/7d/30d等长时间边界由可控clock的服务/数据库测试覆盖，同时至少实测一次HTTP活动续期与旧cookie撤销；不得把仅改前端expires文字当持久化证据。

主冒烟失败阻断相关任务与批次，保留trace、截图、安全请求摘要与真实GIF。运行必须带精确commit、命令、环境类型、时间、通过/失败/跳过数；网络失败或依赖不可用明确列未通过，不降低断言、加重试或改演示值刷绿。

## UI、密度、媒体与输入验收

前台与后台共用11节`minimalist-flat`视觉方向，后台属于product工作界面；primary寄存器为brand不能豁免后台验收。所有本轮后台工作页、表单页、单卡登录/恢复页均在1920×1080、1440×900、390×844测试其真实加载、空、失败及有数据状态，保留截图与操作GIF。

| 范围 | 自动测量与人工可复核断言 |
|---|---|
| 后台D1–D6 | 在已通过真实登录的浏览器上下文执行`_run/density_probe.js`的`densityProbe`，参数density=7、gutter=16、gap=16、pad=16，type取11节work/form/card且指定实际main/rail。不得使用探针示例中的sessionStorage注入。D1断点不增大间距；D2工作面fill≥0.85、表单左对齐且fill≥0.55；D3无空轨；D4块间距≤24px、卡片padding≤20px；D5空/加载状态原位左上且不过量留白；D6最大横向空带≤可用宽15%，单卡按工具规则不适用。手机保留工具真实n/a并单独验44px触控和无横向溢出，不伪填D1–D6全pass |
| 首页媒体 | 生产视频静音、playsinline、可暂停；失败用正确视频海报。品牌城市JPG/GIF位于独立段，GIF近可见才设动态src，隐藏/减少动态/手动暂停切静帧；用户暂停不能被滚动恢复覆盖。网络记录证明首屏不同时下载全部媒体，媒体不覆盖导航与3D操作区 |
| 素材发布副本 | 原件哈希不变；GIF 361帧的顺序、每帧呈现时刻、总时长30.08秒与循环属性保留；飞艇/墙面每次出现及透视/遮挡后再现均完整换为现用自有字标，无新增错位/漏标。逐帧差异清单、代表帧和真实制作记录齐全；任一失败文件保持未完成且不纳入发布映射 |

## 失败处理与完成判定

每个缺陷先保存可重复失败场景，再做根因修复与同一场景通过证据；测试断言指向最终用户行为，不复制实现细节。任务验收逐项引用13节编号和10节接口；仅本任务范围内有因果价值的测试进入改动，不借测试大范围重构。

任务相关检查全过、适用DB/standalone测试无环境性skip、真实页面与接线冒烟通过且证据对应同一head才可交审。批次收口复跑全量现有测试、跨模块主冒烟和后台密度；未通过项目按交接流程保持open并生成返工任务，不以文档完成或单元绿灯宣称功能落地。

## 恢复来源补充边界

E-105按最高影响且非rare优先：复用前只读核候选PR当前head/base/check和必需批准，与本机来源记录逐项匹配；缺批准或HEAD变化应保持未满足，不能把草稿已推送等同于可合并。扫描发布清单确保受保护恢复备份和秘密未混入。此处不授权合并或部署。
